# Вывод вертикали (org-resolve.ts)

> Чистые функции «кто чей руководитель» над снимком организации: сильнее всего — точечное переопределение, дальше дерево отделов, дальше объект; кто ОТВЕЧАЕТ за должность сегодня — лестница замещений. Модель, права, API и каскады — [org_structure.md](org_structure.md).

Код: `apps/api/src/modules/staff/org-resolve.ts` (чистые функции; Prisma здесь нет намеренно), снимок и кэш — `apps/api/src/modules/staff/org-graph.service.ts`.

## Снимок и функции

Снимок `OrgGraphService.load(workspaceId)` — четыре запроса + живая команда; кэш: процессный `Map` 15 с + Redis `org:graph:v1:<ws>` TTL 600 с; сброс — `afterStructureChanged` после КАЖДОЙ мутации (там же resync прав) и `invalidateOrgGraph` при ЛЮБОМ изменении состава (принятие приглашения даже без должности) и любой правке справочника. Правило шире «структурной правки»: снимок несёт роли, НАЗВАНИЯ и `sortOrder` — без сброса схема живёт старым именем до TTL, а новичок «не в организации». Строки замещений в снимке сырые; **дата — всегда параметр** (иначе кэш небезопасен); «сегодня» — календарная дата в `APP_TIMEZONE` (`orgToday()`). Проверка циклов на записи читает `loadFresh` мимо кэша.

- **`superiorPositionOf(g, posId, branchId)`** — по убыванию силы: 1) `reportsToPositionId`; 2) голова отдела должности, если ≠ она сама, иначе вверх по предкам до первого отдела с головой ≠ она; 3) дерево не ответило → голова ОБЪЕКТА назначения (если ≠ она); в **типовой схеме** (`branchId = null` — общий канвас, корни) объектом считается ОСНОВНОЙ; 4) `null` — корень.
- **`holdersForPosition(g, posId, branchId, at)`** — лестница объекта: 1) ДАТИРОВАННОЕ замещение, действующее в `at` (объектное затеняет общее); 2) держатели В ЭТОМ объекте; 3) держатели в любом объекте — только если объект у должности ровно один (управляющий чужой точки не подставляется); 4) БЕССРОЧНЫЙ зам (когда некому); 5) пусто. Разворот «зам — должность» рекурсивен (`visited`, ≤ `ORG_LIMITS.maxDeputyDepth`); живость людей (команда trainee+) — здесь же.
- **`managerOf(g, userId, {branchId?, assignmentId?, at?})`** — назначение (явное → совпадение объекта → основное → раннее) → вверх, пока не найдутся держатели (вакантная должность вертикаль не рвёт); человек не бывает своим руководителем ВНУТРИ цепочки должностей; стоп-кран `ORG_LIMITS.maxChainDepth`; **пусто на вершине → владелец организации** (`reason: 'owner_fallback'` — снимок согласования не пуст, инвариант движка цел). У САМОГО владельца фолбэк отдаёт его же — осознанно («решает владелец»; иначе его шаг «Согласование руководителя» падал бы `empty_assignees`), витрины рисуют заглушку «Вершина структуры» (`isTopOfStructure` — один хелпер на десктоп и мобильное дерево). Возвращает `{positionId, userIds[], viaDeputy, deputyUntil, branchId, reason, chain}`.
- **`managerChainOf`** — цепочка по должностям (не по людям). **`subordinateIdsOf`** — ТОЧНАЯ инверсия `managerOf` по КАЖДОМУ назначению каждого члена команды (`я ∈ subordinates(рук) ⇔ рук ∈ managerOf(я, назначение)`): одно правило, два направления, ноль расхождения между «мой руководитель» и «моя команда». Обход — по ЖИВОЙ КОМАНДЕ (`memberRole`), не по назначениям: человек вне структуры тоже подчинённый (его вертикаль упирается в корень → владелец), обход по назначениям терял таких в `subordinates_of`. Владелец — руководитель всех, чья вертикаль упирается в корень.
- **`findPositionCycle(g)`** — ПОЛНАЯ разрешённая цепочка для каждой должности × каждого объекта (цикл бывает смешанным: `reportsTo` + дерево + голова объекта); на записи (`reportsTo`, отдел должности, голова отдела/объекта, родитель отдела) → 400 `org_cycle` с именами петли. Повреждённый через БД цикл чтение не вешает (`seen`-гарды).

Вертикаль — по ФАКТУ (`StaffAssignment`), не по договору (`Employment.legalPositionId`) — [staff.md](staff.md).
