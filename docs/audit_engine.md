# Журнал аудита безопасности (`core/audit`)

> Код: `apps/api/src/core/audit`, реестр событий — `packages/shared/src/audit`, миграции — `20260923120000_core_audit` (+ `…_core_audit_review`, `…_audit_leaf_order_v3`), роли БД — `apps/api/scripts/db-roles.sql`, веб — `apps/web/src/components/security/`.

26-й платформенный движок: **единый поток событий безопасности** «кто / когда / откуда / что / с чем / исход» с тремя зрителями — сам человек, админ его организации, безопасность платформы. Одно событие пишется один раз, а каждый зритель видит свою проекцию. В этот журнал переехали пять прежних журналов (ключей, команд Кабинета, доступа сотрудников, чтений ПДн, учёта действий с ПДн). Их API и экраны остались проекциями.

## Несущие правила

1. **Событие пишется В ТРАНЗАКЦИИ факта** — `audit.record(tx, …)`. Если факт откатился, записи нет. Если запись не удалась, факт откатывается (fail-closed). `tx = null` допустим только там, где факта в БД нет вовсе: неудачный вход, просмотр в Кабинете, агрегат чтений. Сбой записи всё равно поднимается, и вызывающий сам решает, что делать: fail-closed (неудачный вход → 503) или `recordBestEffort` (только `platform.access.*`, батч `pii.read` и свёртка отказов `authz.denied` — с метрикой отказов).
2. **Событие — декларация реестра**, а не строка в коде. Для ключа в реестре заданы категория, серьёзность, три флага зрителей, `disputable`, `notify`, строгая Zod-схема деталей, OCSF и имя OWASP Vocabulary. Незнакомый ключ или детали вне схемы → `Error` (это ошибка разработчика).
3. **В деталях только коды, id, счётчики и признаки.** Свободный текст разрешён одному полю — `detailNote()`, обоснованию админа; его нормализует `audit.redact.ts`. Список запрещённых слов в ИМЕНАХ полей (`AUDIT_DENY_DETAIL_WORDS`: phone, iin, email, name, ip, token, password…) проверяет `check:audit`.
4. **Слова — при чтении** (render-at-read): в БД лежат ключ и коды, заголовок и строка ленты — ключи `audit.events.<key>.title|body` на языке зрителя. Если ключ неизвестен (строка из прошлой версии реестра), показывается сам ключ, а не пустота.
5. **Полный IP человеку и организации не показывается никогда.** Им видны страна, класс устройства и клиент. Полный IP получает только платформа — командой раскрытия с записью факта — и сам человек в «Моих данных».
6. **Действия сотрудников платформы** (`platform.*`) людям и организациям не показываются: у этих событий видимость `platform`.
7. **Права движок не проверяет** (как все `system*`): кого и о ком записать, решает вызывающий. Проверку прав на чтение делают проекции зрителей.

## Контракт продюсера

```ts
await audit.record(tx, {
  key: 'org.member.role_changed',          // ключ реестра (литерал; компилятор проверяет)
  subjectUserId, workspaceId,              // о ком и в каком контексте
  actor?,                                  // по умолчанию — из контекста запроса
  target?: { type, id, label? },           // label — снимок подписи (нормализуется)
  op?, outcome?, reasonCode?,              // outcome: success | failure | denied | unknown
  details,                                 // строго по схеме реестра
  evidence?, ref?, ctx?,
});
```

| Вариант | Когда |
|---|---|
| `record(tx, …)` | Основной: в транзакции факта |
| `recordOnce(tx, dedupeKey, …)` | Кроны и повторяемые джобы: пишет первый вызов за TTL. Если Redis недоступен, пишет всё равно (лишняя строка лучше потерянной) |
| `recordCollapsed(key, windowSec, build)` | Шумные отказы (ключи API, перебор): строки на счётчиках 1, 10, 100, 1000… с полем `attempts` |
| `recordBatch(null, rows)` | Высокочастотные агрегаты (`pii.read`): буфер процесса, сброс раз в секунду или по 500 строк |
| `recordBestEffort(…)` | Только для `platform.access.*` (и под `recordCollapsed`): сбой — метрика и лог |
| `signal(…)` | Попытка без строки журнала (вход во время блокировки): только наблюдатели `after` — детекции видят перебор «сверх блокировки» |
| `observe(name, {inTx, after})` | Наблюдатель записи: `inTx` — внутри транзакции факта (стрим в SIEM), `after` — вне её (счётчики детекций). Регистрирует себя сам — это исключает DI-цикл |

`recordOnce` снимает отметку дедупликации, если запись не удалась: иначе повтор крона считал бы событие записанным. Счётчик окна в Redis — только `incrWindow` (INCRBY + EXPIRE NX одним MULTI): раздельные INCR и EXPIRE при сбое между ними оставляли ключ без срока — вечный лимит.

**Актор** выводится из аутентификации, а не из тела запроса. `user` — сессия; `bot` — ключ бота; `platform_staff` — сессия Кабинета: интерцептор ставит его с ролями, поэтому события внутри команд Кабинета не записываются «анонимом»; `system` — крон/джоб/скрипт; `guest`, `anonymous` — до входа; `device` — этап 4. Цепочка делегирования: `actor_id → on_behalf_of_id → actor_key_id`.

**Система по поручению человека** — `actor: { kind: 'system', onBehalfOfId }`: эффект применила система, но начал его человек продукта (увольнение КЭДО с галочкой «снять и членство» применяет джоб или чужой запрос, дошедший маршрутом до применения — актор из контекста запроса там был бы случайным). Проекция отдаёт `{ kind: 'system', onBehalfOf: person }`, веб рисует «Система · инициатор <карточка>». Делегирование сотрудника платформы пишется актором `platform_staff`, не системой, — поэтому через `onBehalfOf` системы личность сотрудника наружу не уходит.

**Контекст запроса** middleware кладёт в ALS (`shared/context/request-context.ts`): `requestId` (он же в конверте ошибки), IP (только `req.ip`), UA, `X-Device-Id` (стабильный id клиента, не зависит от opt-out аналитики), страна, клиент (`web | mobile_web | mobile | api_key | console | socket | job | script`), маршрут.

**Страна — только из доверенного заголовка края сети** (`trustedCountry`, env `GEO_COUNTRY_HEADER`, за Cloudflare — `cf-ipcountry`): его ставит CDN и затирает у клиента. Список «любой известный CDN-заголовок» (`countryFromHeaders`) годится лишь для догадки о языке: угонщик из другой страны прислал бы `X-Country-Code: KZ` и погасил уведомление «вход из новой страны». Не задан — страны нет. Та же дверь — у «откуда» ключа API.

## Модель данных

`security_events` — партиции по МЕСЯЦАМ (`occurred_at`), PK `(id, occurred_at)`, `id` из sequence (identity на партиционированной таблице невозможна).

- **Время**: `occurred_at` = `clock_timestamp()`, `tx_at` = `now()`, `xact xid8` = `pg_current_xact_id()` — курсор дайджестов и экспорта.
- **Коды smallint**: `category`, `severity` (OCSF 1..5 → 0..4), `outcome`, `actor_kind`, `client`. Коды ↔ словари shared — `audit.codes.ts`.
- **Зрители**: `vis_subject`, `vis_workspace`, `vis_platform` (CHECK: всегда true).
- **Сеть**: `ip_enc` (envelope платформенного KEK), `ip_hmac` (псевдоним `sa6m:` для поиска по равенству), `ip_net` (/24, /48), `country`; `city`/`asn`/`is_anonymizer` — поля под GeoIP (сейчас пустые).
- **Устройство**: `ua_family`, `ua_raw_enc` (сырой UA — только шифротекстом), `device_id`.
- **Корреляция**: `request_id`, `route`, `idempotency_key_hash`, `ref_type/ref_id`, `related`.
- Детали и `evidence` — JSONB со сжатием lz4. Индексы: `(occurred_at DESC, id DESC)` — лента Кабинета без фильтров идёт по нему, а не сортировкой всей таблицы (BRIN порядка не даёт); keyset-ленты `(subject|workspace, occurred_at DESC, id DESC)`, актор, ключ, `xact`; ЧАСТИЧНЫЕ `WHERE col IS NOT NULL` у разреженных `op`, `ip_hmac`, `request_id`, цели (руками в миграции, Prisma их не видит); уникум `(event_id, occurred_at)`.
- **Новая колонка журнала — только с NULL по умолчанию.** Лист Меркла v2 (`jsonb_strip_nulls`) пустую колонку не видит; непустое умолчание изменило бы лист каждой прошлой строки — проверка всех дайджестов и сброс архивов упали бы.

**Append-only на уровне БД** (NIST AU-9, ЕТ № 832 п. 38):
- триггер `security_events_guard` роняет `DELETE` и любой `UPDATE`, кроме перешивки `ip_enc`/`ua_raw_enc` при ротации KEK (строка сравнивается целиком без двух этих колонок — новая колонка защищена сразу);
- `TRUNCATE` запрещён отдельным триггером на родителе И на каждой партиции;
- все триггеры `ENABLE ALWAYS` — их не глушит `session_replication_role = replica`;
- второй слой — права (`db-roles.sql`, правило деплоя после `migrate deploy`): владелец журнала `sa6_audit_owner` (NOLOGIN) ≠ роль приложения; у роли приложения `DELETE`/`TRUNCATE` отозваны, `UPDATE` — column-level только на две enc-колонки.

**Партиции** создаёт и сбрасывает SECURITY DEFINER-функция владельца (`AuditPartitions`), а не роль приложения; от `PUBLIC` функции закрыты. `audit_ensure_partition(month)` заводит месяц со своими триггерами (на буте и кроном — на три месяца вперёд); чужая таблица с именем партиции — громкий отказ. `audit_drop_partition(name)` сбрасывает месяц только при наличии строки архива и при возрасте ≥ 3 лет — этот пол зашит в функцию БД. **Границы месяца функция берёт из ИМЕНИ партиции**, а строка архива обязана описывать ровно этот месяц: строку пишет роль приложения, и подложный `to_at` в прошлом иначе открыл бы сброс текущего месяца.

Соседние таблицы:
- `security_digests` — неизменяемы, кроме отметок выгрузки и проверки; `leaf_version` — версия корня (1 — `to_jsonb`, 2 — `jsonb_strip_nulls`, 3 — формула v2 и числовой порядок листьев), подписана в строке дайджеста; уникумы по `xact_from` и `xact_to` (последний дайджест и звено цепочки — по индексу);
- `security_partition_archives` — изменить можно только отметку сброса, один раз; `leaf_version` — формула корня манифеста (формат `sa6-audit-archive:v<версия>`). Умолчание колонки у обеих таблиц — 1 (писатель, не знающий версий, считает по v1); код пишет версию явно;
- `security_alerts` — тревоги (рабочая очередь, не журнал: закрытые старше года удаляет ночной крон, факт остаётся событием `detect.*`). Один партиальный уникум `(kind, dedupe_key) WHERE status IN ('open','ack')`;
- `platform_command_receipts` — квитанции идемпотентности команд Кабинета, append-only;
- `user_devices` — устройство человека по `X-Device-Id`;
- `sessions`: `last_seen_at`, семейство, `family_created_at`, `confirmed_at`, мягкий отзыв с причиной из CHECK;
- `users`: `login_locked_until`, заморозка (`security_frozen_at/reason ∈ self|platform`), `session_max_idle_days ∈ {7,30,90,180}`.

**IP-колонки** зарегистрированы в `KeysFieldRegistry` (scope `platform`, `idNumeric: true`), поэтому ротация KEK перешивает их числовым курсором. Лист дайджеста в хеш эти колонки не включает, так что перешивка хеш не меняет.

## Таксономия

Категория — первый сегмент ключа. Исключение — семейство `auth.session.*`, у него категория `session`.

| Категория | Что | Зрители (типично) |
|---|---|---|
| `auth` | вход, неудачи, блокировка, OTP, step-up | человек |
| `session` | новая сессия/устройство/страна, завершение, cooling | человек |
| `account` | пароль, номер, заморозка, «Это не я», удаление | человек |
| `org` | членство, роли, первый вход в организацию, политика, стрим | организация (+ человек) |
| `keys` | ключи API, боты, ротации, криптодействия | организация / платформа |
| `platform` | команды и доступ сотрудников Кабинета | только платформа |
| `pii` | агрегат чтений ПДн | организация / платформа |
| `pd` | учёт действий с ПДн (передачи, уведомления) | человек, без окна |
| `consents` | приёмка и отзыв согласий | человек, без окна |
| `data` | выгрузки (`data.export{source}`) | по источнику |
| `detect` | детекции | только платформа |
| `audit` | мета-аудит: дайджесты, архив, просмотры, настройки журнала | только платформа |
| `sharing` | доступы к данным организации, публичные ссылки | организация (+ автор ссылки при атаке) |
| `files` | угрозы в загруженном (вирус) | загрузивший + организация |
| `authz` | отказы доступа (403), свёртка | только платформа |

Реестр — 133 ключа (`packages/shared/src/audit/<область>.ts`). Статус `planned` — ключ объявлен заранее, отправителя пока нет: `detect.impossible_travel`, `detect.session_context_changed` (нужна база GeoIP). Как только такой ключ начинают писать, страж требует перевести его в `live`.

## Три зрителя

| Зритель | Проекция | Окно |
|---|---|---|
| Человек (`/users/me/security/*`) | `vis_subject` и свой `subject_user_id` | 365 дней; `pd`/`consents` — без окна (`windowExempt`: законный учёт) |
| Организация (`/workspaces/:id/security/*`, owner/admin) | `vis_workspace` и `workspace_id = :id`; фильтр обойти проекцию не может | тариф `audit.retentionDays`: free 90 / basic 180 / standard 365 / pro 1095 |
| Платформа (`/platform/security/*`, `security.read`) | всё | весь срок хранения |

Организация видит только автоподпись устройства; имя, которое дал человек, ей не показывается. Бот в ленте — `BotChip` с именем теневого пользователя. Сотрудник платформы в ленте организации выглядит как `{kind: 'platform', id: null}` — так же и в журнале ключей организации (`KeysAuditService`: ни id, ни имени). Детали «только платформе» (`AUDIT_PLATFORM_ONLY_DETAILS` в `audit.codes.ts`) срезает каждая проекция не-платформы: ленты, журнал ключей, стрим.

**Где и чем — данные актора.** В ленте человека событие, которое совершил над ним другой (админ сменил роль, сотрудник платформы заморозил аккаунт), не раскрывает страну и устройство этого другого: `location` и `device` пустые.

**Мета-аудит (NIST AU-9)**: просмотры журнала в Кабинете копятся счётчиками Redis по ключу (сотрудник, час). Раз в час крон пишет одно событие `audit.viewed{queries, rows, reveals}`. Если Redis недоступен, дельта пишется сразу. Каждое раскрытие IP дополнительно пишет свой `platform.access.reveal`.

## Вход, сессии, устройства

- **Блокировка по аккаунту** (`audit.login-guard.ts`): 5 неудач за 10 минут → блок на 15 минут. Каждый следующий блок подряд — вдвое дольше, максимум сутки. Правда о блоке — `users.login_locked_until`, счётчик — в Redis (фолбэк — подсчёт событий за окно). **Блок — один на залп**: параллельные неудачи пересекают порог разом, и ставит блок тот, кто сменил «открыт» на «закрыт» (status-guarded строка / `SET NX` неизвестного номера); остальные получают уже стоящий блок — ступень не растёт, уведомление одно. Во время блока попытки построчно не пишутся, но детекции их видят (`signal`); итог `audit.lockout_summary` пишется при входе, снятии блока и следующем блоке (при непрерывной атаке человек может не войти вовсе). **Неизвестный номер** блокируется так же, по HMAC номера: иначе ответ 429 против 401 выдавал бы, существует ли аккаунт. Время ответа выровнено: bcrypt считается и для неизвестного номера.
- **Пароль вне входа — под той же защитой.** Публичная `POST /auth/unfreeze/start` проверяет пароль — это вход по сути: та же блокировка по аккаунту и события `auth.login.failed` (без неё — перебор пароля любого аккаунта мимо блокировки: «не заморожен» против «неверный пароль» выдаёт угаданный пароль). Step-up живой сессии (`/verify/step-up`) — свой потолок: 5 неверных паролей за 15 минут → 429 даже для верного; блокировку входа он не трогает (её наводит любой, кто знает номер, и она не должна запирать смену пароля у сессии владельца).
- **Сессия для человека = семейство refresh-цепочки** (строка ротируется на каждом refresh). Поля семейство наследует. `first_seen` считается по устройству, а не по `sid`. Если клиент не прислал `X-Device-Id`, новизна определяется по паре `(ua_family, country)` на 30 дней. Новое устройство или страна → `auth.session.new_device|new_country` с уведомлением; повтор — без уведомления.
- **Мягкий отзыв**: завершённые сессии остаются в списке «вышедшие» (до 50) с причиной. Access-токен отозванного семейства гаснет сразу: отметка в Redis плюс проверка в БД. **Живой сокет отозванного семейства рвётся сразу**: сокет входит в комнату `fam:<семейство>`, `markFamiliesRevoked` (после коммита любого отзыва) шлёт `auth.families.revoked` — авторизация сокета только на рукопожатии, и без этого завершённая на украденном устройстве сессия продолжала бы получать сообщения.
- **Cooling 24 ч** (`assertConfirmed`): неподтверждённая сессия младше суток не может завершать чужие сессии, выходить везде, менять пароль или номер, забывать и переименовывать устройства, запускать «Это не я». Иначе угонщик с паролем первым же действием выгнал бы владельца. Ответ — `403 auth.cooling_period{confirmAt, canConfirmNow}`. Подтверждение — SMS-кодом (`POST /users/me/sessions/confirm`) или само по истечении срока.
- **Автозавершение неактивных** — настройка человека `session_max_idle_days` (7/30/90/180, по умолчанию 90). Крон пишет одно агрегатное событие на человека. Устройства без активности год → забыты; забытые старше года удаляются (событие остаётся, строка устройства — нет).
- **«Видели» сессию/устройство** отмечается не чаще раза в 5 минут.

## Аккаунт под угрозой

- **Экстренная заморозка без входа** (`/freeze`, `POST /auth/freeze/start|confirm`): номер + SMS. Закрываются вход, все сессии (и в Кабинете), личные ключи API. Повторная заморозка идемпотентна. **Сброс пароля по SMS заморозку не снимает** — иначе она бессмысленна против угона SIM. **Разморозка** — старый пароль + SMS (`/auth/unfreeze/*`) либо командой Кабинета после проверки личности по регламенту. Лимит: 3 старта в час с одного IP. SMS о заморозке — без ссылок, максимум одна в час.
- **Мастер «Это не я»** (события с `disputable`): шаг 1 (`POST /users/me/security/not-me`) завершает все ДРУГИЕ сессии, забывает чужие устройства, отзывает личные ключи API (без бампа эпохи — текущая сессия остаётся) и отключает Google. Шаги 3–4 — смена пароля и номера своими ручками. Финал — `not-me/complete{passwordChanged, phoneConfirmed}`: журнал — улика, а не пересказ клиента, поэтому `credentialsRotated` берётся из события смены пароля ПОСЛЕ старта мастера, финал без старта по этому событию (сутки) — `400 audit.not_disputable`, повтор финала второго события не пишет. Лимит: 3 запуска в час на человека.
- **«Мои данные»** (`GET /users/me/security/export`, кнопка на `/profile/my-data`): весь журнал человека за срок хранения (≤ 10 000 новейших). Полный IP — только там, где адрес его: действовал он сам или аноним на его аккаунт (неудачный вход, заморозка). IP админа или сотрудника платформы, действовавших над ним, — чужие ПДн, не отдаются. Cooling-гард: свежая неподтверждённая сессия выгрузку не получает (история с полными IP — самое ценное чтение для угонщика). Тип провода — `SecurityMyDataExportDto`.
- **Уведомления**: in-app + push — всегда; SMS (`audit.sms_alert`, джоб в транзакции события) — только если у человека нет живого push-устройства, не чаще одной в час, текст — заголовок уведомления без ссылок. Отправка SMS — событие учёта `pd.transfer` (номер ушёл оператору связи).
- **Step-up**: общий веб-диалог `StepUpDialog` «пароль → SMS» (цели `keys_manage`, `security_confirm`).

## Организация

Страница `/workspaces/[id]/security` (пункт навигации `ws-security` — только owner/admin). Фильтры: `AUDIT_ORG_FILTERS`, человек, период, исход. `?e=<id>` открывает событие (ссылка из уведомления). Объект события (папка Диска, заметка, папка заметок, шаблон) — кнопка «Открыть» по тем же адресам, что у уведомлений владельца; удалённый объект ссылки не получает.

- **Экспорт** (`POST /workspaces/:id/security/export`, `@Idempotent({required})`, ответ 202): тариф `audit.export`, период не шире окна тарифа (`400 audit.export_range`), не больше 5 выгрузок в сутки (429), потолок 100 000 строк. Выгрузку выполняет джоб `audit.export`. Джоб повторно проверяет права и окно, пишет CSV (BOM, защита от формул OWASP) или NDJSON на языке заказчика, без имён людей. Файл профиля `audit_export` ложится на Диск организации в закрытую системную папку «Безопасность» (`security_exports`, грант — роль admin). В одной транзакции — привязка файла, `data.export{source: audit_org, rows, format}` и уведомление `security.org.exportReady`.
- **Стрим в SIEM** (`audit.stream.ts`) — обычные вебхуки организации: `security.<категория>.recorded` для категорий `org | keys | data | consents | detect | sharing | files`. Входов людей в стриме нет: организация их не видит. Событие с `vis_workspace` ставится в outbox вебхуков В ТРАНЗАКЦИИ ФАКТА. Payload — OCSF без IP, UA и имён (у системного действия — `actor.onBehalfOfId`, инициатор; делегирование сотрудника платформы наружу не уходит), поэтому стрим не считается трансграничной передачей ПДн. Подписка проверяет тариф `audit.stream` на всех путях (хук `WebhooksRegistry.registerSubscriptionHook` в транзакции create/update/delete, 402). Смена подписки — факт `org.audit.stream_changed{enabled, categories}`. После понижения тарифа доставки тихо пропускаются.

## Доступы, ссылки, файлы, отказы

**Доступ к данным организации** (`sharing.access.granted|revoked`) пишут владельцы объектов в транзакции гранта: Диск (`DriveShareService`), Заметки (`NotesShareService` — заметка, папка, «выдать упомянутым»), шаблоны документов (`DocumentsService.addGrant/removeGrant`). Только когда объект принадлежит организации: личный шеринг — история объекта (хроника), не журнал. `previousAccess` — прежний уровень (`none` — доступа не было); тот же уровень повторно и снятие несуществующего гранта событий не пишут. Субъект — получатель-человек (`principalType = user`), зрители — организация. Каскады (разрыв окружения, снятие членства) `sharing.*` не пишут: причина уже в журнале.

**Публичные ссылки** (`core/share-links`) — дверь наружу, пишутся ВСЕ пути: `sharing.link.created` (рядом с учётом `pd.publication`, в той же транзакции) — чем закрыта (пароль, подтверждение номера, срок, потолок открытий); `sharing.link.updated{fields}` — коды реально изменённых настроек, смена адреса — `address`; `sharing.link.revoked{reason}` — `manual`, `mine_bulk`, `workspace_bulk`, `object_deleted` (актор — система), строка на ссылку. Подбор пароля: блок ставит тот, кто застал счёт на пороге (переход по условию), — одна `sharing.link.password_locked` на залп с уведомлением автору `security.link.passwordLocked`. Новый подтверждённый гость ЭТОЙ ссылки — `sharing.link.guest_verified` (актор — гость). Каждое открытие — только журнал визитов `ShareLinkVisit`. Субъект — автор ссылки; личная ссылка видна только платформе (человек видит её учёт `pd.publication` и «Мои ссылки»). Очистка ссылок при окончательном удалении организации (`forgetWorkspace`) событий не пишет — факт уже `org.workspace.purged`.

**Выгрузка** — только массовый вынос (`AUDIT_EXPORT_SOURCES`): кадровый ZIP, журнал, «Мои данные», гостевой ZIP папки Диска (`drive_guest_zip`, до первого байта, fail-closed; актор — гость или аноним, субъект — автор ссылки). Скачивание ОДНОГО документа, в т.ч. ZIP пакета подписи, — доступ к содержимому, граница журнала.

**Вирус в загрузке** — вердикт сканера и `files.malware_detected{engine, signature}` одной транзакцией (переход статуса по условию — повтор джоба не пишет второй раз); уведомление загрузившему `files.scan.infected` — паспортом события; имя файла — снимок подписи цели. Серия — детекция `malware_burst`.

**Отказы доступа** — глобальный фильтр ошибок подаёт сигнал на каждый 403/404 (`shared/filters/access-denied.signal.ts`; общий слой движков не импортирует — слушатель `AuditAuthz` регистрирует себя сам). 403 → свёртка `authz.denied{reason, attempts}` на (актор, шаблон маршрута) за час, только платформе: человеку и организации это шум, а показ отказа чужой организации подсказал бы, что объект существует. 403 и 404 на маршруте с id объекта → счётчик разных объектов детекции `idor_probing` (404 у нас — тоже «чужое»). Не считаются: отказ до входа, адрес без маршрута, отказы-состояния `AUDIT_AUTHZ_IGNORED_CODES` (свежая сессия, шлюз согласий, заморозка, step-up). Фильтр работает вне ALS интерцептора — контекст запроса передаётся явно.

**Интеграции** — `account.integration.connected|disconnected{provider, reason}` на всех путях: подключение (колбэк OAuth, актор — человек из подписанного `state`), кнопка «Отключить» (`self`), отзыв согласия `integration_google` хуком владельца данных (`self`), мастер «Это не я» (`not_me`), удаление аккаунта (`account_deleted`). Мастер отзывает согласие НЕ служебным отзывом с причиной `not_me`: у служебного хуки не бегут, и подключение с токенами Google осталось бы живым.

**Настройки журнала** (`audit.settings.ts`) — на старте процесса под advisory-замком каждая настройка (`AUDIT_SETTINGS`: интервал дайджестов, срок хранения, архив, доверенный гео-заголовок) сравнивается с `to` последнего `audit.settings.changed` этой настройки; расхождение → событие, первый запуск → исходное значение (`reason_code: baseline`). Правда о прошлом значении — сам журнал. Два процесса разной конфигурации на одной базе пишут событие на каждый старт — это и есть сигнал.

**Доступ к ПДн и видимость полей** ([visibility_engine.md](visibility_engine.md)): `pii.reveal` (раскрытие строгого поля одной записи — видят субъект, организация и платформа; фильтр «Раскрытия» в лентах человека и организации), `pii.reveal_denied` (отказ: нет окна, пауза детекции, план не даёт), `pii.read` (агрегат чтений ПДн батчем); организация — `org.visibility.policy_published`, `org.visibility.settings_changed`, `org.visibility.explain_viewed`. Детекция массового раскрытия (30 за 10 минут одним человеком) ставит раскрытия ему на паузу до решения админа; детекция скрейпинга (`detect.pii_scrape`, 20 000 чужих записей с контактами/личными полями целиком за час) — тревога без блокировки. В деталях — только коды полей реестра видимости, не значения.

## Целостность и хранение

- **Дайджесты** (`audit.digests.ts`) каждые `AUDIT_DIGEST_INTERVAL_MIN` (по умолчанию 5) минут. Окно событий ограничено курсором `pg_snapshot_xmin`: незакоммиченная транзакция не проскочит мимо дайджеста (долгая транзакция держит окно — метрика `audit_digest_lag_seconds`). Лист = sha256 от `jsonb_strip_nulls(to_jsonb(e) - 'ip_enc' - 'ua_raw_enc')::text`, считается в БД (`auditLeafSql(version)`; v1 — без `jsonb_strip_nulls`). Порядок листьев — ЧИСЛОВОЙ `(e.xact, e.id)` (v3): в v1–v2 запрос выбирал `xact::text AS xact, id::text AS id` и сортировал `ORDER BY xact, id` — по выходным колонкам, то есть ТЕКСТОМ, а курсор страницы сравнивал числа; окно больше страницы теряло и дублировало строки (на всём dev-журнале — 10 648 «строк» при 10 046). Дайджесты и архивы v1–v2 проверяются своим прежним запросом (их подписанный корень посчитан по нему), новые пишутся v3; перед сбросом партиции число её строк сверяется НЕЗАВИСИМЫМ `count(*)` с архивом. Корень дерева Меркла — по RFC 6962 (лист `0x00‖d`, узел `0x01‖l‖r`), **потоково** (`MerkleBuilder`: стек поддеревьев, память O(log n)) — месяц журнала не держится в памяти ни строками, ни хешами. Сьют сверяет корень с независимой рекурсивной реализацией. Цепочка — хеш предыдущего дайджеста. Подпись — Ed25519 аудитории `audit` (`KeysSigningService`). Копия — в объектное хранилище `audit/digests/yyyy/mm/<id>.json`. События: `audit.digest.created`; при проверке — `audit.digest.verified|failed`. Расхождение → тревога `digest_mismatch` (critical).
- **Архив** (`audit.archive.ts`, ежедневно, если не `AUDIT_ARCHIVE_ENABLED=false`): закрытый месяц выгружается сразу после закрытия в `audit/archive/<партиция>.ndjson.gz` с подписанным манифестом (`sa6-audit-archive:v1`, корень Меркла) и строкой `security_partition_archives`. Архивация идемпотентна. **Сброс** месяца старше `AUDIT_RETENTION_YEARS` (≥ 3) происходит только после пересчёта корня и проверки подписи манифеста. При расхождении сброс отменяется и поднимается тревога `audit_degraded`. Хранилище — драйвер `core/files` (`STORAGE_DRIVER`).
- Hash-chain по строкам сознательно не делается: он сериализует запись. Вместо неё — подписанные дайджесты вне БД.

## Детекции

Счётчики Redis на каждой подходящей записи (наблюдатель `after`, вне транзакции факта) и на каждом `signal` (попытка во время блокировки). Если Redis сбоит, детекция пропускается. Тяжёлые правила считаются раз в минуту. Пороги — константы движка (`AUDIT_DETECT`), а не тариф: это защита платформы. Сбои записи журнала считаются в общем счётчике минуты в Redis (`audit:det:write_fail:<минута>`) — деградацию видит крон любого инстанса, а не только тот, где случился сбой. Метрики: `audit_detections_total{rule}`, `audit_alerts_open{severity}` (крон детекций).

| Вид | Правило | Серьёзность |
|---|---|---|
| `bruteforce_account` | 15 неудач на аккаунт за 10 мин | high |
| `bruteforce_ip` | 30 неудач с сети за 10 мин | high + оповещение |
| `password_spray` | 20 аккаунтов с одной сети за час | critical + оповещение |
| `credential_stuffing` | ≥ 100 попыток за минуту и > 40 % неудач | critical + оповещение |
| `otp_fatigue` | 5 SMS-кодов человеку за 5 мин | high |
| `mass_export` | 1000 строк выгрузок/чтений ПДн одним актором за 10 мин | high + оповещение; внутри организации — уведомление `security.org.massExport` её владельцу и админам (ссылка на событие-причину журнала организации, актору о себе — нет) |
| `pii_scrape` | 20 000 чужих записей с контактами или личными полями, прочитанных целиком одним человеком или ботом за час (считает `core/visibility` на каждом `shape()`) | high; видит организация «шляпы»; без блокировки — решение за организацией |
| `dormant_login` | вход после 180 дней тишины | medium |
| `digest_mismatch` | проверка дайджеста не сошлась | critical |
| `audit_degraded` | ≥ 20 сбоев записи в минуту / сбой архива | critical + оповещение |
| `idor_probing` | 30 разных чужих объектов (403/404 на маршруте с id) одним актором за 10 мин | high + оповещение |
| `malware_burst` | 3 заражённых загрузки одного человека за час | high + оповещение |

`raise()` — атомарный upsert по партиальному уникуму (`RETURNING xmax = 0`). Событие `detect.<kind>` (ключ — из явной карты `DETECT_EVENT_KEY`) и оповещение владельцам платформы (`PlatformNotifier.securityAlert`) рождает только СВЕЖАЯ тревога. Повтор на открытой тревоге увеличивает `hits` и добавляет улики (не больше 50).

## Регистрации в движках

- `notifications`: типы `security.*` (в т.ч. `security.org.exportReady`, `security.org.massExport` — контекст организации), `security.link.passwordLocked` (автору ссылки), `files.scan.infected` (паспорт `files.malware_detected`), `platform.security.alert` (+ 8 видов тревог). Ссылки `security_event` (модалка в профиле) и `security_org_event` (журнал организации). Адресат обязан видеть событие в своей проекции.
- `realtime`: `audit.recorded` → `security:changed` в личную комнату (веб перечитывает сессии и ленту).
- `entitlements`: `audit.retentionDays` (config), `audit.export`, `audit.stream` (сервис `audit`).
- `analytics`: `audit.feed.viewed` (клиент), `audit.not_me.completed`, `audit.export.requested`, `audit.device.forgotten`, `auth.account.frozen{by}`.
- `webhooks`: `SECURITY_WEBHOOK_EVENTS` (сервис `security`, в т.ч. `security.sharing.recorded`, `security.files.recorded`) + хук подписки.
- `consents`: причина отзыва `not_me` (мастер «Это не я»); хук `integration_google` пишет `account.integration.disconnected`.
- `files`/`drive`: профиль `audit_export`, `FilesRefRegistry` `audit_export` (менеджер организации) и `audit_platform_export` (автор), размещение `DriveCoreRoutesProvider` → папка `security_exports`.
- `keys`: `KeysFieldRegistry` (`ip_enc`, `ua_raw_enc`), подпись аудитории `audit`, HMAC-псевдонимы.
- `platform`: команды, панели, возможности `security.read|write|approve`, группа команд `security`.
- Циклы: `core/keys` и `core/platform` берут `AuditService` лениво (`DI_TOKENS.AuditService`).

## Настройки

`AUDIT_DIGEST_INTERVAL_MIN` (1–60, по умолчанию 5), `AUDIT_RETENTION_YEARS` (3–25, по умолчанию 3), `AUDIT_ARCHIVE_ENABLED` (`false` — аварийный стоп архива; месяц без архива не сбрасывается никогда), `GEO_COUNTRY_HEADER` (доверенный гео-заголовок края сети; пусто — страны нет) — [environment_variables.md](environment_variables.md). Локальной базы GeoIP нет: город, ASN и признак анонимайзера пусты, а детекции, которым они нужны, помечены `planned`.

## Ловушки

- **Сортировка и курсор в сыром SQL — по КОЛОНКАМ таблицы с алиасом** (`ORDER BY e.xact, e.id`). Голое имя в `ORDER BY` Postgres берёт из ВЫХОДНЫХ колонок: `xact::text AS xact` превращает сортировку в текстовую (999 999 после 1 000 000), и корень Меркла расходится с независимой проверкой. Регрессия — сьют: корень движка по всему журналу = числовой эталон.
- Уникум и identity на партиционированном родителе невозможны: `id` берётся из sequence, уникум включает `occurred_at`, квитанции команд лежат отдельной таблицей.
- Партицию не создавать в чужой транзакции — только `ensureAhead` функцией владельца.
- Кэш ключей стрима нельзя заполнять внутри транзакции создания эндпоинта (незакоммиченное состояние). Внутри tx — без кэша, и учитывается `pending_verification`.
- Детали — `.strict()`: новое поле без правки схемы реестра роняет запись (по замыслу).
- Бандл веба `@superapp/i18n/messages/*` читается из `dist`: после правки каталогов нужно пересобрать i18n, иначе будет `MISSING_MESSAGE`.
- Счётчики детекций живут в Redis между прогонами: посев дев-полигона использует синтетический субъект.
- Ответ блокировки неизвестного номера обязан совпадать с ответом известного — и по статусу, и по времени.
- Текст события НЕ обращается к человеку («нажмите „Это не я“»): одно событие видят три зрителя, подсказку несёт кнопка модалки.
- Умолчание `leaf_version` — 1, а не текущая версия: процесс старой сборки на той же базе (второй инстанс при выкатке) пишет дайджест без версии и считает по v1 — умолчание «текущая» записало бы v1-корень с меткой v2, и строку уже не исправить (append-only).
- Ключ в `AUDIT_PLATFORM_ONLY_DETAILS` и коды — в `audit.codes.ts` (чистый модуль): `core/keys` импортирует их без цикла файлов keys → audit.query → keys.envelope.
- Шина событий — одна группа потребителей на все инстансы: событие получает ОДИН инстанс. Два процесса разной сборки на одной dev-базе делят события (и кроны) — проверка realtime плавает; сьют гонять против одного API актуальной сборки.

## Правовая сверка

Карта норм — [legal_kz.md](legal_kz.md). До production юрист подтверждает:
1. срок хранения ≥ 3 лет и запрет админам изменять журнал (ЕТ № 832 п. 38) применимы к платформе в её статусе (п. 2 — интеграция с государственными ИС);
2. стрим в SIEM организации без IP/UA/имён не требует отдельного согласия `cross_border`;
3. полный IP в «Моих данных» исполняет ст. 24 ЗоПД (доступ субъекта к своим данным), а бессрочный архив журнала сочетается со ст. 12 (срок = достижение цели).
