# Сотрудники (StaffModule, B2B)

> Справочники организации (Должность / Отдел / Объект) + назначения должностей. Три оси проецируются в core/access. Вертикаль власти на этих справочниках (головы, подчинение, заместители, области, канвас) — [org_structure.md](org_structure.md).

Код: `apps/api/src/modules/staff/`.

## Модель

- **`StaffDepartment`** — Отдел; ДЕРЕВО через `parentId` (цикл → 400); `headPositionId` — руководящая должность ([org_structure.md](org_structure.md)).
- **`StaffPosition`** — Должность; опционально принадлежит отделу. **Членство в отделе — ПРОИЗВОДНОЕ от должности** (модель штатного расписания 1С) — прямого назначения «человек→отдел» нет. `reportsToPositionId` — переопределение подчинения, `glyph` — значок-данные.
- **`StaffBranch`** — Объект. С появлением сервиса «Объекты» это ДЕРЕВО площадок (`parentId`, `ancestorIds`, `kind`, юрлицо, часовой пояс, правила смен) — см. [objects.md](objects.md); здесь остаются справочные свойства (имя, адрес, `headPositionId`). **У организации ВСЕГДА ≥1 объект**: основной (`isDefault`) заводится вместе с организацией с её именем (старые организации бэкфиллены; `ensureDefaultBranch` самолечит). Основной удалить нельзя (409 `org_default_branch`); перенос флага — `isDefault: true` на другом объекте.
- **`StaffAssignment`** — человек × должность × **объект (обязателен; пусто → основной)**; ДАТИРОВАНО (`startsOn`/`endsOn`/`rateShare`/`staffingPositionId` — [objects.md](objects.md)); закрытое назначение остаётся в истории, а «кто работает сейчас» = фильтр `activeAssignmentWhere()` у КАЖДОГО потребителя; несколько на человека; **`isPrimary`** — основное место (первое назначение основное само; переключение снимает старое в той же tx; удаление основного повышает следующее по `createdAt`); статус `training→certified` (фундамент Додзё; переключает manager+).
- Дубль имени → 409 (unique на воркспейс); удаление должности с назначениями или руководящей отделом/объектом → 409; удаление объекта с людьми → 409. Удаление ОТДЕЛА не каскадит: должности отцепляются (FK SetNull), а подотделы переезжают к РОДИТЕЛЮ удалённого (не в корень: корневой уровень правят только полновластные роли, и «уезд в корень» позволял голове ветки завести корневой отдел в обход `requireAll`; удалить КОРНЕВОЙ отдел, у которого есть подотделы, может только полновластный). Назначение должности Подрядчику → 400.

## Проекция в core/access

`position#holder@user` · `branch#member@user` · `department#member@user` **с closure предков** (грант на отдел достаёт подотделы) · `department#head@user` (голова отдела — на отдел и всех ПОТОМКОВ + member предков) · `branch#head@user` (держатели головы объекта В ЭТОМ объекте); `resyncWorkspaceStaff` на каждую мутацию + `reconcileStaff` в AccessReconcileCron; диф проекции сужен по отношению (чужие рёбра переживают resync); `EPOCH_FANOUT` для трёх осей. Роли воркспейса → `member` маппингом; contractor НЕ проецируется. Замещения не проецируются никогда.

## Гейты

Кнопки правки в вебе стоят по ОБЛАСТИ (`GET /org/my-scope`), а не по роли: голова отдела/объекта видит «Управлять» в ростере и форму заместителя на своей должности ровно потому, что сервер это разрешает. Чтение справочников/ростера — команда (trainee+; Подрядчик → 403). Запись — область (`OrgRightsService.scopeOf`): Менеджер+ полновластен (`STAFF_FULL_SCOPE_ROLES`); голова отдела правит свою ветку (подотделы, должности, назначения; перемещение — права на оба отдела); голова объекта — назначения в своём объекте; корневой отдел, объекты, мастер — только полновластным; ранг субъекта уважается (выше своей роли — нельзя). Роли/увольнение — admin+ (админа — только владелец). Увольнение/выход — каскад: назначения + замещения + tuples снимаются. `system*`-методы (`assignPositionSystem`/`removeAssignmentSystem`) прав не проверяют — для джоба КЭДО `hr.apply`.

## Факт vs юридический план

StaffAssignment — ФАКТ («как работает»); юридический план («как договорились» — договор, оклад, должность ПО ДОГОВОРУ) — `Employment` в КЭДО ([hr_kedo.md](hr_kedo.md)); расхождение = плашка-подсказка, не ошибка. **Официальный** оклад остаётся в `Employment` (меняется приказом `salary_change`); **управленческая** ставка и график живут в Штатном расписании объекта ([objects.md](objects.md)). Увольнение в КЭДО ЗАКРЫВАЕТ назначения датой приказа (`closeAssignmentsSystem`), а не стирает их.

## API (кратко)

`GET /workspaces/:id/staff` (справочники одним ответом, аддитивно: `headPositionId/Name`, `isDefault`, `reportsToPositionId`, `glyph`) · departments/positions/branches CRUD (PATCH несут `headPositionId`, `reportsToPositionId`, `isDefault:true`) · `POST /members/:userId/assignments` (`branchId` необязателен → основной; `isPrimary`) · `PATCH /assignments/:id` (перевод в объект / аттестация / `isPrimary:true`) · `DELETE /assignments/:id`. Граф/области/заместители — `workspaces/:id/org` ([org_structure.md](org_structure.md)).

## Веб

`/workspaces/[id]/members` — сервис с **вторым уровнем сайдбара** (единственное исключение среди сервисов организации — [web_conventions.md](web_conventions.md)): **Люди** (ростер — `StaffPersonCard` гридом как «Моё окружение»; бейдж карты = должности (основное первым); модалка управления: роль по лестнице + назначения с объектом и «Сделать основным» + реквизиты (приезжают ОТДЕЛЬНЫМ запросом `GET /members/:userId`, когда карточку открыли) + блок «Уход из организации» («Исключить из организации» матовой, рядом ссылка «Оформить увольнение по ТК» — это два РАЗНЫХ действия); «Сохранить» доводит правки; «В структуре» → канвас с фокусом) · **Орг. структура** (канвас) · **Объекты** (список: основной, руководитель объекта, адрес; карточка объекта) · **Приглашения** (форма — клон «Добавить в окружение»: номер → чипы Должность (одна) + Объекты (несколько; без выбора — основной) → «всегда Стажёр») · **Сроки** (КЭДО). Общее — `members-lib.tsx` (`useMembersBase`, `MembersHeader`, `MemberRequisitesBlock`, редирект легаси `?tab=`). Профиль `/members/[userId]` — вкладками ([org_structure.md](org_structure.md), [hr_kedo.md](hr_kedo.md)). EntitySelector-типы department/position/branch зарегистрированы с workspace-скоупными лоадерами.
