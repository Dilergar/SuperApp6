# Конвенции веба (apps/web)

> Правила для любого UI-кода. Перед созданием/редактированием ЛЮБОГО компонента обязательно читать `/DESIGN.md` (действующая система — Organic Bento warm matte). Здесь — механика и несущие запреты.

## Каркас и навигация

- **`AppShell`** (`apps/web/src/components/shell/`) — ЕДИНЫЙ каркас приложения: глобальный сайдбар 264px с деревом (2 уровня) + топбар с переключателем «Личное / Организация». Новый сервис = +1 строка в реестре `apps/web/src/lib/app-nav.ts`; рейл 60px/шторка/Ctrl+B — из коробки. У сервисов ОРГАНИЗАЦИИ второй уровень сайдбара не заводится (один маршрут с вкладками) — единственное исключение «Сотрудники» (пять разделов, один из них полноэкранный канвас; страница-вкладки в 1359 строк уже не жила) — объяснено комментарием в `app-nav.ts`. Состояние сайдбара — cookie `SIDEBAR_COOKIE = 'sa6_sidebar'` (там же, значения `collapsed|expanded`); серверные layout'ы читают его и передают `defaultCollapsed`. Своих навбаров страницы НЕ рисуют. **Рабочий стол** (полотно важнее меню — Заметки) объявляется там же в `prefersRail(pathname)`: каркас входит в него со свёрнутым сайдбаром как переопределением НА ВИЗИТ (ручной разворот cookie не пишет, уход возвращает меню как было), а страница занимает всё правее сайдбара через `.canvas-layer` (globals.css) — без `PageHeader` и ограничения `--content-max`.
- Каркас выводит контекст «Личное / Организация» ИЗ ПУТИ (`/workspaces/[id]/...`) → **адрес обязан нести организацию** (рабочая заявка/документ живут внутри `/workspaces/[id]/…`; личный маршрут сам переадресует рабочую сущность внутрь организации).
- Верхние иконки топбара (стопка решений, колокольчик, упоминания) — СКВОЗНЫЕ (без скоупа); витрины ВНУТРИ контекста скоуплены. У выборки «что ждёт меня» ТРИ состояния скоупа: `workspaceId` · `scope=personal` · без параметров (сквозной).

- **Глобальные горячие клавиши** — только на `window` из всегда смонтированного компонента (`Providers`: `CallsWatcher`, `NotesStickyLayer`), сравнение по физическому коду И символу (`e.code === 'KeyN' || e.key.toLowerCase() === 'n'`: русская раскладка даёт кириллицу в `key`, синтетические события — пустой `code`), выход на `e.defaultPrevented`. Занято: `Ctrl+B` (сайдбар), `Alt+N` / `Alt+Shift+N` (стикеры Заметок). Браузер не отдаёт `Ctrl+N`, `Ctrl+Shift+N`, `Ctrl+T`. Редактор текста гасит всплытие СВОИХ сочетаний (`Ctrl+B/I/U/E/K/Z/Y`), иначе они дёргают каркас.
- **Полноэкранный слой канваса — общий класс `.canvas-layer`** (globals.css, рядом с переменными каркаса): `top: var(--svc-topbar-h)`, `left: var(--svc-w, 0px)`, `z-index: 30`. **`inset: 0` в таком слое запрещён** — он раскрывается в `left: 0` и накрывает сайдбар: навигация исчезает, полотно перехватывает жесты в его полосе, а фокус продолжает уезжать на накрытые ссылки (`visibility: visible`). Прецедент — схема оргструктуры, скопировавшая инлайновый слой у редактора процесса (у того сайдбара нет вовсе). Шкала слоёв — в `/DESIGN.md`.
- **Календарная дата (`YYYY-MM-DD`) в интерфейсе — только через `apps/web/src/lib/dates.ts`** (`dmy`/`dmyOrDash`/`dm`): идиома `iso.split('-').reverse().join('.')` успела разъехаться по семи файлам с разным поведением на пустом значении.

## Примитивы

- **Только кит `apps/web/src/components/ui/`** — реестр имён = его `index.ts` (единственный источник), витрина всех состояний — `/dev/ui` (dev-only), каталог смысла — `/DESIGN.md`. Свои примитивы страницам запрещены; не хватает — расширяется кит.
- **Нативные `confirm()`/`alert()` ЗАПРЕЩЕНЫ** (и линтером): браузерная галочка «блокировать диалоги» заставляет их молча возвращать false — кнопка удаления перестаёт работать без признаков. Вместо них `useConfirm()` (`components/ui/useConfirm.tsx`) и `toastError()` (`apps/web/src/lib/toast.tsx`). `useConfirm()` возвращает кортеж `[confirm, node]` — `node` ОБЯЗАН быть отрендерен в дереве, иначе диалог не появится и `confirm` молчит.
- Ошибка API: текст — `apiErrorMessage(err)`, ветвление — `apiErrorDetails(err)?.code` (машинный `details.code` конверта, не русский текст); оба — реэкспорт `@superapp/api-client` через `apps/web/src/lib/api.ts`. Свой разбор `error.response.data…` на странице не писать.
- **Выгрузка файла с JWT-ручки — только БАЙТАМИ** (`apiGetRaw` → blob): голая `<a href>` на защищённую ручку = всегда 401 (прецеденты: протокол подписания, экспортный ZIP, кадровые выгрузки).
- Поля — только из кита с `label`/`aria-label` (кит сам связывает `htmlFor`+`id`); голый `<input className="ui-input">` с несвязанным `<label>` оставляет поле без имени.
- Закрытие оверлеев — единый `CloseChip` (самодельный × запрещён). Модалка кита: `role="dialog"` + Esc + ловушка фокуса + возврат фокуса.
- **Строка для человека — только ключ каталога** (`useTranslations('<ns>')`), никогда не литерал: литерал — это один язык навсегда. Запрещено линтером `i18n/no-cyrillic-literal`. Свои неймспейсы страница получает серверным layout'ом: `<ServiceMessages ns="tasks">` (`apps/web/src/i18n/ServiceMessages.tsx`); `common` и `shell` есть везде. Подробно — [i18n.md](i18n.md).
- **Форматирование — только через `@superapp/i18n`.** `toLocaleDateString('ru-RU')` запрещён: это язык и регион сразу, зашитые навсегда. Числовые даты и деньги языка не требуют (чистые `apps/web/src/lib/dates.ts`, `apps/web/src/lib/wallet-format.ts`); где есть слова — хуки `apps/web/src/lib/format.ts` (`useFormatters`, `useDayLabel`, `useByteUnits`). **Размер файла — только `useBytes()`**: своя `humanSize` в `components/files` была второй копией с русскими «КБ/МБ» и точкой-дробью и удалена. **Сортировка имён — только `useFormatters().compare`**: `localeCompare` без языка берёт умолчание браузера, и у казахоязычного человека на русской Windows ростер выстраивается русским алфавитом вопреки его выбору; чистой функции сравнение приходит ПАРАМЕТРОМ (`sortGroups`, `layoutOrg`).
- Реестры UI несут КЛЮЧИ, а не подписи: `apps/web/src/lib/app-nav.ts` — `labelKey`, шаги мастеров — `labelKey`. Тот же приём, что `icon: 'tasks'`.

## Человек и выбор сущностей

- **Человек в UI = ТОЛЬКО `PersonChip`/`PersonAvatar`**, не голый текст — несущее продуктовое правило (видимость платных скинов карточек). В ките `components/ui/` их НЕТ: `PersonChip` — `apps/web/src/app/circles/PersonCard.tsx` (рядом `PersonCard`, `StaffPersonCard`), `size: CardSize` = `'XL'|'L'|'M'|'S'|'XS'` (`apps/web/src/app/circles/card-skin.ts`); `PersonAvatar` — `apps/web/src/app/messenger/messenger-ui.tsx` (`size: 'sm'|'md'|'lg'`, скин подтягивает сам). Пикеры — карта M; инлайн-упоминание — S; грид Окружения — L→XL.
- **Бот — `BotChip`/`BotAvatar`** (`components/keys/`, размеры `xs|sm|md`), никогда PersonChip: акторы хроники и уведомлений несут `kind: 'person'|'bot'` — ветвиться по нему. **Секрет показывается один раз** — только `KeyRevealOnce` (копирование, чекбокс «сохранил», без закрытия по фону); повторного показа нет нигде, только ротация. Права ключа — `ScopeMatrix` (строки — `GET /keys/scope-matrix`, ботам закрытые сервисы недоступны, потолок уровня применяется). Действия с ключами — под `useKeysStepUp().withStepUp(action)` (диалог пароль → код открывается сам; 403 `keys.step_up_required` повторяет действие). Реестр ключей организации — `/workspaces/[id]/integrations` (пункт `ws-integrations` только owner/admin; бейдж «ждут решения» — `useKeysPending`, сокет `keys:changed`); личные ключи — `/profile/keys` — [keys_api_access.md](keys_api_access.md).
- **Выбор человека/группы/отдела/должности/филиала — единый `EntitySelector`** (`apps/web/src/components/EntitySelector.tsx` + реестр `apps/web/src/lib/entities.ts`). Тип `user` — контекстный: с `context={{workspaceId}}` лоадер отдаёт РОСТЕР организации (вся команда, ВКЛЮЧАЯ самого себя; Подрядчик исключён), без — личное окружение. Правило: **пикер не предлагает того, что сервер отвергнет**. Заголовок группы типов и СИНТЕЗИРОВАННЫЙ вариант («вся организация») хранятся в реестре КЛЮЧАМИ (`ENTITY_TYPE_LABEL_KEYS`, `EntityOption.titleKey`) — разворачивает их владелец пикера, поэтому кэш реестра остаётся языконезависимым.
- Значок, выбранный человеком, — данные: рисует `<Glyph/>`/`<EmojiIcon/>`, выбирает `<GlyphField/>` (три каталога). Значок из API — ключ реестра иконок (`icon: 'robot'`); незнакомый ключ рисуется запасной иконкой. Свои поля «Значок» и разборы «имя иконки или эмодзи?» запрещены.
- Иконки — Phosphor Light через `<Icon/>` (`apps/web/src/components/ui/Icon.tsx`, статический спрайт `/icons/sprite.svg`). Прямой импорт `@phosphor-icons/react` в `src` запрещён (конвенция; линтером НЕ покрыто — в рантайм-бандле пакета нет вовсе). Новая иконка = строка в `icons.manifest.json` + `pnpm --filter ./apps/web gen:icons` (незнакомое имя валит сборку).

## Защищённые поля

- Поле с формой провода `Guarded<T>` рисует **только** `<GuardedValue>` (кит): значение, маска с подписью или «Скрыто» решает сервер ([visibility_engine.md](visibility_engine.md)). Своя проверка `$v`, свой маркер и своя маска номера запрещены линтером веба; чтение — `isVisible` / `isMasked` / `isHidden` / `visibleOr` / `guardedDisplay` из shared.
- **Раскрытие — только в карточке одной записи** (`<RevealButton>`), никогда в списке и таблице: раскрытие — событие журнала на одну запись.
- **Заголовки таблиц — по плану зрителя** (`VisibilityPlanProvider` + `GET /visibility/plan`): колонку, которой зритель не видит ни у одной записи, не показываем вовсе; значение в строке — всё равно `<GuardedValue>`.
- Форма правки не отправляет поле, которое пришло маской или скрытым: сервер ответит `400 visibility.masked_value_rejected` / `403 visibility.field_forbidden`.

## React Query

- **Ключ запроса — в `apps/web/src/lib/queries.ts`, не литералом на странице** (литерал в одном месте + общий ключ в другом = молчаливый рассинхрон кэшей).
- **Один ключ = ОДНА форма кэша**: `useQuery` и `useInfiniteQuery` на общем ключе несовместимы (плоская страница чужого useQuery роняет ленту на «reading 'length'» при клиентском переходе). Общая лента объявляется один раз через `infiniteQueryOptions` рядом с ключом; потребитель первой страницы читает `pages[0]`.
- Глобально (`apps/web/src/app/providers.tsx`): `refetchOnWindowFocus: false`; retry ≤2 раз и только при `status === undefined || status >= 500` — сетевые ошибки без ответа ретраятся, 4xx (403 отозванный доступ, 404) — нет. Мутации инвалидируют общий префикс ключа.

## Auth и сессия

- `useAuthStore` (`apps/web/src/lib/stores/auth.ts`) — единственный источник правды, токены в localStorage только через store; защищённые страницы — `useRequireAuth`.
- `hydrate()` сносит токены ТОЛЬКО на 401/403 (500/таймаут/оффлайн не выкидывают на логин).
- Выход/вход — `apps/web/src/lib/session-reset.ts` (`resetSessionCaches`): чистит кэш React Query и модульные кэши (скины, пикеры) — иначе следующий вошедший видит кэш предыдущего. Ловушка: `registerQueryClient(queryClient)` вызывается один раз в `Providers`; без регистрации сброс React Query — no-op (модульные кэши чистятся, RQ — нет).
- ОДИН socket.io-коннект на вкладку (синглтон с подписчиками); heartbeat паузится на скрытой вкладке.

## Маршруты и границы

- **Новый сервис = +1 файл `<сервис>/loading.tsx`** (реэкспорт `components/shell/RouteLoading`). В корне `app/` держать НЕЛЬЗЯ — корневой loading.tsx вешает 404 на вечный спиннер (проверено). Намеренно БЕЗ `loading.tsx`: гостевые `check/`, `s/` (клиент `public-api`), auth-страницы `login/`, `register/`, `reset-password/`, и `dev/`. `not-found.tsx` и `error.tsx` — в корне, на русском, внутри каркаса.
- ⚠️ **Suspense-граница + >~12.8 КБ серверной разметки под ней = вечный спиннер в невидимой вкладке** (содержимое едет отдельным чанком с инструкцией `$RC` через rAF, а в скрытой вкладке кадров нет; сервер отдал 200, консоль чистая). Авторизация клиентская — серверу рисовать нечего: ранний выход по `mounted` до гидратации (после ВСЕХ хуков). Скрининг: `curl -s <url> | grep -c '$RC('` → 0 = хорошо.
- ⚠️ **Вторая причина того же `$RC` — асинхронный серверный компонент между границей и шлюзом авторизации**, при любом размере разметки. `loading.tsx` сегмента оборачивает дочерние сегменты ВМЕСТЕ с их layout'ами, и `ServiceMessages` (он `await getMessages()`) в таком layout'е приостанавливает границу: оболочка уходит без содержимого. Всё, что ниже шлюза каркаса (`isReady`), сервер не рисует вовсе — там асинхронность безвредна. Поэтому в области организации словарь каркаса лежит в `apps/web/src/app/workspaces/layout.tsx` (выше границы `workspaces/loading.tsx`, часть оболочки), `[id]/layout.tsx` синхронный, а словари разделов — в `[id]/<раздел>/layout.tsx` ниже шлюза; главная организации — группа маршрутов `[id]/(home)/` со своим layout'ом.
- Тяжёлые страницы (канвас Процессов, канвас оргструктуры, комната звонка, WOPI-редактор, оверлей звонка) — `next/dynamic ssr:false`. Общее для канвасов React Flow — `apps/web/src/components/canvas/` (`canvas.css` красит `.react-flow__*` и подключается ПОСЛЕ стилей библиотеки; `FlowCanvas.tsx` — обёртка с `nodeTypes`/`isValidConnection`); раскладки у каждого канваса свои.

## Длинные ленты

- Виртуализация — **react-virtuoso** (модель Telegram: в DOM только видимые строки). Правила из ленты мессенджера (переиспользовать, не изобретать): `firstItemIndex` для догрузки вверх без прыжка (индекс и данные — одним коммитом); `startReached` на монтировании ЛОЖНЫЙ (до первых замеров «верх достигнут» сразу — нужен засов); индексы асимметричны (`itemContent`/`startReached` — абсолютный, `scrollToIndex`/`initialTopMostItemIndex` — индекс в массиве); отступы — на строке, не на контейнере (движок меряет offsetHeight); `getElementById` для перехода не годится (половина истории не смонтирована).

## Производительность и dev

- dev идёт на **Turbopack** (`next dev --turbopack`); запасной путь — `pnpm --filter ./apps/web dev:webpack`.
- ⚠️ CSS-импорты пакетов из чистого `.ts`-модуля Turbopack в сборку НЕ кладёт — переносить в `.tsx` компонента.
- ⚠️ **Mantine запинен на ^8.3.11** (прямая зависимость apps/web) — НЕ поднимать до 9, пока Next не на react 19.2+ (Mantine 9 зовёт `useEffectEvent`, которого нет в вендоренном react App Router).
- Lottie — через `next/dynamic` + IntersectionObserver-гейт.
- Мобильный веб обязан работать: 375px без горизонтального скролла; сетки модалок — `auto-fit`, не жёсткие столбцы. Запас ширины считать по kk/en: они длиннее русского до +30 %.
- Клиентский код НЕ импортирует `@superapp/i18n` целиком — только подпути `/format` и `/locale`: пакет CommonJS, tree-shaking на него не действует, и полный импорт утащит в бандл словарь всех трёх языков.

## Графики и аналитика

- **Графики — только кит `apps/web/src/components/ui/charts/`** (`LineChart`, `BarChart`, `StackedBars`, `FunnelChart`, `CohortGrid`, `ScatterLabeled`, `Sparkline`; `StatTile` с `delta`/`sparkline`): SVG/HTML без зависимостей, цвета — токены `--series-1…6`, у каждой серии форма маркера, у каждого графика таблица-дублёр (`ChartFrame`), числа и даты форматирует вызывающий через `useFormatters`. Слот цвета закреплён за сущностью. Правила палитры — `/DESIGN.md` «Серии графиков».
- **Аналитика клиента** — `apps/web/src/lib/analytics.ts` (экземпляр `@superapp/analytics`); автоматический вид — только переходы (`apps/web/src/components/analytics/AnalyticsRouteTracker.tsx`, внутри `<Suspense>`); прочее — `analytics.track('<ключ>', props)` там, где человек «увидел/попытался» (замок тарифа, шаги регистрации). Серверный факт из клиента не шлётся (страж `pnpm check:analytics`). Отказ SDK никогда не всплывает в интерфейс — [analytics_reports.md](analytics_reports.md).

## Линтер веба

`apps/web/eslint.config.mjs` (flat, только стражи границы; всё — `error`): кириллица в литералах/шаблонах/тексте JSX (`i18n/no-cyrillic-literal` — ратчет `apps/web/i18n.legacy.json`, постоянное исключение `src/app/dev/**`); голый `api.get|post|patch|put|delete` — ВЕЗДЕ, включая `apps/web/src/lib/api.ts` (адаптер лишь реэкспортирует хелперы `@superapp/api-client`, override'а у него нет); распаковка конверта `res.data.data` И `data.data` после деструктуризации (два селектора); нативные `confirm`/`alert`. Единственное ослабление — `apps/web/src/lib/public-api.ts` (гостевой клиент, свой axios без перехватчиков): там разрешена распаковка `data.data` в типизированных `guestGet/guestPost`, запрет голого `api.*` действует и там. `pnpm lint` веба = `eslint src`, шаг в CI. Правила Next/react-hooks здесь не живут (их дом `next lint`).

## Защитные диалоги и ленивые словари

- **Step-up — один диалог** `components/verify/StepUpDialog` («пароль → SMS-код», цели `keys_manage` и `security_confirm`); своё окно подтверждения не заводить. Ключи — обёртка `KeysStepUp`.
- **Большой словарь раздела — чанком**: `<LazyNamespace ns="audit" fallback={<LoadingBlock/>}>` грузит неймспейс только там, где он нужен (раздел «Безопасность» профиля), а не на все страницы. Словарь читается из `dist` пакета i18n — после правки каталогов пересобрать `@superapp/i18n`, иначе `MISSING_MESSAGE`.
- **Меню разделов на телефоне** (профиль): боковая колонка на узком экране превращается в горизонтальную строку над содержимым — колонка 200 px на 375 px сжимала секции в столбик.
- Публичные маршруты вне каркаса и шлюза согласий (`/freeze`) перечисляются в `AppChrome` и `ConsentGate` явно: защитное действие не упирается в экран документов.

## Отказы API и повторы

- **Единая дверь отказов — `toastApiError(err)`** (`apps/web/src/lib/api-errors.ts`). Прежняя пара «взять текст отказа → красный тост» запрещена ESLint-стражем: у отказа больше не один смысл. `already_completed` — это УСПЕХ (тон успеха + перечитать данные), `in_flight` — спокойное сообщение, `key_reused` — отказ + сброс ключа намерения. Исключение у первого: `details.completedStatus ≥ 400` значит «эффект случился, и первая попытка ВСЁ РАВНО упала» — тон отказа, но данные перечитать (`apiErrorCompletedStatus`).
- **`outcome_unknown` тостом не показывают вовсе.** Тост говорит «не вышло» и исчезает, а правда другая: операция МОГЛА пройти. Плашка `OutcomeUnknownAlert` остаётся на экране и ведёт в историю (`historyHref` — другая страница, `onOpenHistory` — вкладка этой); когда история на ЭТОМ же экране (маршрут заявки, список приказов), действия у плашки нет, а форма просто перечитывает данные. Новых цветов нет — предупреждающий вариант `Alert` кита. Развилка «плашка или общая дверь» одна на платформу: `useOutcomeUnknown()` → `if (!outcome.capture(e)) toastApiError(e)`.
- **Ключ намерения формы — `useIdempotencyKey(deps)`** на необратимых формах (деньги, отправка, подпись): двойной клик даёт ОДИН эффект. Сбрасывается на успех, на изменение полей и по событию «ключ занят». Передаётся хелперу: `apiPost(url, body, { idempotencyKey })`.
- **Ключ намерения СПИСКА — `useIdempotencyIntent()`**: у списка кнопка на каждой строке, и хук на строку не завести. `keyFor('buy', listingId)` = «эта попытка × эта строка»; `reset()` на успех. Общий ключ на весь список склеил бы разные строки в одно намерение (`422 key_reused` на второй покупке).
- **Ключа намерения НЕ ставят там, где повтор несёт ДРУГОЕ тело** (контейнер CMS у ЭЦП — каждая подпись новые байты) и там, где ответ ручки `store:'none'` (второй заход получил бы `409` вместо кода). Двойной клик в таких местах закрывает `disabled`/`loading`.
- **Долгий авто-повтор** (транспорт повторяет сам): кнопка `loading` и заблокирована, рядом — `SlowRequestNote` («Проверяем соединение…») через несколько секунд. Иначе зависшая кнопка выглядит сломанной, и человек ищет, как нажать ещё раз.
- Оптимистичный пузырь отправки **не исчезает при отказе**: он остаётся «Не отправлено · Повторить», и повтор уходит с ТЕМ ЖЕ ключом (id пузыря = ключ повтора). Подмена на сохранённое идёт по ключу, а не по содержимому.
