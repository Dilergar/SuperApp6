# core/search — движок поиска

> Единый кросс-сервисный поиск: индекс-витрина + реестр провайдеров. Новый сервис добавляет провайдер — глобальный поиск «загорается» сам.

## Модель

- **`SearchDocument`** — индекс-витрина = проекция доменных таблиц (хуки send/edit/delete + крон-сверка + бэкфилл `scripts/backfill-search.cjs`).
- Postgres FTS `tsvector('russian')` (словоформы) + `pg_trgm` GIN (опечатки/имена/подстроки; БЕЗ `unaccent` — он ломал бы казахские буквы). Типо-порог `word_similarity` 0.4 через `SET LOCAL`.
- ⚠️ generated tsvector/GIN зеркалить в schema.prisma комментами — иначе `migrate dev` дропнет.
- Реестр провайдеров: **индексные** (пишут SearchDocument) и **живые** (запрос на лету).

## Обрезка по правам — в SQL

Выдача режется правами НА УРОВНЕ SQL (не фильтром после): пример message — активный ChatMember + `seq >= visibleFromSeq` прямо в условии. Индексация — вне критического пути send.

## Подключённые провайдеры

`message` (индекс) · `chat` + `person` (живые, по членству/окружению) · Диск · Документы · Контрагенты. Будущие (Задачи/Календарь/Вишлист) — регистрацией.

## Режимы

Глобальный (`GET /search?q=`) — сгруппированный, relevance + лимит на тип · поиск-в-чате (`&chatId=`) и страница типа (`&type=&cursor=`) — recency keyset. Сниппет центрируется на совпадении. Дип-линк `/messenger?chat=&msg=`.

## Проверка

`verify-search.cjs` (индексация, словоформы, обрезка по правам, опечатки trigram, пагинация).
