## Семантика метрик

День — календарный в `APP_TIMEZONE`. Активность — квалифицирующее событие. DAU — различные люди с активностью за день; WAU / MAU — скользящие 7 / 28 дней; stickiness = DAU ÷ MAU. Активная организация — ≥ 1 участник с активностью в её контексте. «Новый» — первый активный день в хранимой истории. Удержание: когорта — первое квалифицирующее (или указанное) событие; `n_day` — активен ровно в день N, `unbounded` — в день N или позже, `bracket` — в корзине дней (1 · 2–7 · 8–14 · 15–30 · 31–60 · 61–90). Воронка: `ordered` (по умолчанию) — шаги по порядку в окне от первого шага, `strict` — между шагами нет других событий этой воронки (только для людей), `any` — шаги 2..n в любом порядке; первое вхождение первого шага, один субъект — одна конверсия; окно ≤ 90 дней. Шаг «любое из» (`orEventKeys`) засчитывается первым вхождением ЛЮБОГО своего события. Adoption — активные в сервисе ÷ активные всего + медиана дней использования. Lifecycle: новые · текущие · вернувшиеся · уснувшие (минусом). Тарифы — по СНИМКУ `plan_key` события (без подписки — `none`); «на активную организацию» — нормировка. Анонимные события склеиваются с аккаунтом по неоспоренной связи.

## Язык запросов

`analyticsQuerySchema` (union): общие поля `range {from, to}` (≤ 400 дней), `compare` (тот же отрезок назад, вторым запросом), `filters` (`services`, `eventKeys`, `platforms`, `sources`, `planKeys` с `none`, `context` all/personal/workspace, `workspaceId`), `excludeInternal` (по умолчанию `true`). Виды:

| Вид | Уточнения | Источник |
|---|---|---|
| `trend` | `metric` (dau, wau, mau, stickiness, active_workspaces, new_users, events, event_users, sessions, session_p50), `eventKey`, `interval`, `breakdown` (service/plan/platform/workspace; у `sessions`/`session_p50` — только platform/workspace: роллап сессий сквозной, service/plan для него равны отсутствию разбиения, а людей для k-анонимности организаций исполнитель берёт из роллапа субъектов) | роллапы; `event_users` — сырьё |
| `funnel` | `steps[]` (2–8; шаг — событие или «любое из»: `orEventKeys` до 4 альтернатив; `where` — только enum/boolean-свойство реестра и только у шага из одного события), `windowDays`, `mode`, `unit`, `breakdown` (platform/plan) | сырьё; > 90 дней — фоновый джоб |
| `retention` | `mode`, `days`, `startEvent`, `returnEvent`, `unit` | роллап; с указанными событиями — сырьё |
| `breakdown` | `by` (service, event, plan, platform, workspace, denied_key), `metric`, `eventKey`, `perActiveWorkspace`, `limit` | роллапы; по событию и `denied_key` — сырьё |
| `lifecycle` | `interval`, `unit` | роллап |
| `adoption` | `unit`, `byPlan` | роллап |
| `journeys` | `limit` (переходы между сервисами внутри сессии по `navigation.page.viewed`) | сырьё, ≤ 90 дней |

Исполнитель САМ дописывает фильтры, исключение внутренних, k-анонимность и таймаут (`ANALYTICS_QUERY_TIMEOUT_MS`, транзакция `READ ONLY` через `AnalyticsReadDb`; `ANALYTICS_READ_DATABASE_URL` — реплика). Кэш Redis `analytics:q:<hash>` — 60 с, если диапазон включает сегодня, иначе 24 ч. Воронка длиннее 90 дней → `{ status: 'pending', jobId }`, джоб `analytics.report.run` кладёт результат в тот же ключ кэша (час, если диапазон включает сегодня: минутный кэш заставлял бы плитку ставить тот же джоб заново на каждом поллинге), повтор запроса отдаёт `ready`. Ответ несёт `meta` (пояс, время роллапа, первое событие, `kAnon`).

**k-анонимность:** ячейка разбиения по организации или тарифу, серия тренда такого разбиения, строка воронки, когорта, пара переходов и кривая удержания с людьми < K → `masked: true`, значение `null`. Исключение — ключ `personal` у разбиения ПО ОРГАНИЗАЦИИ (это все личные пространства разом, а не одна организация).

## Кабинет: маршруты, права, команды, панели

Способности: `analytics.read` (раздел, запросы, отчёты), `analytics.person.read` (панель «Активность» карточки 360), `analytics.manage` (рубильник, забвение, пересчёт, правка чужих отчётов). Маршруты `/platform/analytics/*` (`@PlatformRoute` + `@PlatformCapability` на каждом): `POST query` (свой потолок 240 запросов/мин на сотрудника), `GET events` (реестр + объём 14 дней + последний день + рубильник), `GET quality` (карантин, длина и отставание stream'а, outbox, счётчики приёма за сутки, первое событие), CRUD `reports` и `dashboards` (`GET dashboards/:id` принимает id или системный ключ). Команды: `analytics.event.setStatus` (medium, причина обязательна), `analytics.user.forget` (high, не на себя), `analytics.rollup.rebuild` (medium, предпросмотр). Панели: `user.analytics`, `workspace.analytics`.

## Отчёты и дашборды

Общие по умолчанию (видят все с `analytics.read`), `private` — черновик автора; правит автор или `analytics.manage`; системные (`systemKey`) не правит никто — «Изменить» создаёт копию. Дашборд — УПОРЯДОЧЕННЫЕ плитки `{reportId, span 4|6|12, viz?}` без координат. Общий дашборд показывает только общие отчёты (`400 analytics.private_tile`); отчёт, ставший личным, уходит с общих дашбордов; удалённый — со всех. Рабочие материалы кабинета — маршруты с capability, без журнала команд (журнал — у команд, меняющих продукт и людей). Системные «Обзор», «Сервисы», «Воронки», «Удержание», «Тарифы» засеваются из `analytics.system-dashboards.ts` на бутстрапе (идемпотентно: правка кода обновляет запросы и плитки; системный отчёт или дашборд, убранный из кода, удаляется из базы — отчёт с плиток всех дашбордов). Воронка «Первая ценность» — регистрация → задача, событие календаря или чат (шаг «любое из»).

## Веб

- Вход = ответ: `/platform/analytics` сразу открывает «Обзор». Вкладки Дашборды · Отчёты · События; `/platform/analytics/d/[id]`, `/reports`, `/reports/new`, `/reports/[id]`, `/events` (`?tab=quarantine`). Пункт «Аналитика» в `PlatformShell` — только у `analytics.read`.
- **Одна панель управления** (липкая): период пресетами и свой, сравнение, контекст (всё · личное · организации · одна организация через поиск кабинета), платформа, внутренние аккаунты. **Всё состояние — в адресе** (`useAnalyticsParams`: `range`, `from/to`, `compare`, `ctx`, `ws`, `platform`, `internal`), переходы между страницами раздела его сохраняют. Сравнение, объявленное самим отчётом, тумблер не выключает.
- Плитки независимы: свой запрос, скелет, ошибка с «повторить»; повторная загрузка приглушает прошлую картинку; удержание переключается «кривая ↔ когортная сетка» прямо в плитке (один ответ запроса, кривая по умолчанию); «считаем…» у фоновой воронки; честные пустые состояния («событий нет», «сбор начался {дата}», «за период событий нет»); скрытое — «—» с подсказкой о приватности. Ни одной поимённой таблицы людей.
- Конструктор — от вопроса («Сколько людей…?» · «Где отваливаются…?» · «Возвращаются ли…?» · «Какие сервисы…?») → события (выбор с поиском по сервисам, названием, описанием, объёмом за 7 дней; у шага воронки — «или другое событие») → уточнение → «Сохранить» / «Сохранить и добавить на дашборд»; живой предпросмотр тем же `ReportViz`, что у плитки (задержка 400 мс); уход с несохранённым — подтверждение; чужой и системный отчёт сохраняется копией.
- Каталог событий: группы по сервису, класс и статус чипами (`planned` — «запланировано»: объявлено, отправителя ещё нет), объём 14 дней спарклайном, рубильник — `CommandRunner`; карантин с подсказкой разработчику.
- Панель «Активность» (`ActivityPanel`): последняя активность, штриховой прогресс активных дней из 28, сервисы и платформы по дням, упоры в тариф с кнопкой, раскрывающей панель тарифов той же карточки (нет у сотрудника этой панели — нет и кнопки); у организации — активные участники и доля по сервисам.
- Тумблер человека — «Профиль → Мои данные» (`apps/web/src/app/profile/my-data/page.tsx`): отказ от аналитики — согласие вида `analytics` движка согласий ([consents_engine.md](consents_engine.md)); текст «что собираем, чего не собираем, что остаётся при отключении» — документ `analytics`.
- Графики — кит `components/ui/charts` (правила — `/DESIGN.md`, раздел «Серии графиков»): у каждого таблица-дублёр, форма маркера у каждой серии, числа — `useFormatters`.

## SDK клиента

`@superapp/analytics` (`packages/analytics/`, ≤ 5 КБ gz, без runtime-зависимостей: лимиты и признаки событий внедряются из shared). `createAnalytics({ baseURL, getToken, getWorkspaceId, getLocale, getRoute, storage, app, limits, traits })` → `track`, `identify`, `reset`, `setOptOut`, `flush`, `context`. `device_id` навсегда, `anonymous_id` ротируется на `reset()`, сессия — 30 минут бездействия или 24 часа; очередь 20 событий / 5 с / `visibilitychange:hidden` / `pagehide`; батч ≤ 60 КБ; офлайн-кольцо 200 событий / 128 КБ / 24 ч с бэкоффом; `fetch(keepalive)` на выгрузке для обоих путей (API на другом origin: `sendBeacon` не несёт ни JWT, ни JSON без preflight). `context()` только читает сессию — фоновые запросы её не продлевают. Веб: `apps/web/src/lib/analytics.ts`, трекер маршрутов в `<Suspense>` (`/platform` и `/dev` не считаются), `identify()` после входа/регистрации/сброса пароля, очередь сбрасывается ДО выхода и `reset()` после, заголовки `X-Analytics-*` — `getAnalyticsContext` api-client. Mobile — адаптер хранилища (контракт `AnalyticsStorageAdapter`) на этапе 2.

## Ловушки

- `useSearchParams` на страницах раздела — только внутри `<Suspense>`.
- Слот цвета закреплён за сущностью (порядок областей реестра, фиксированный порядок платформ), а не за местом в рейтинге.
- У счётных метрик деления оси — целые (`integer`), у долей и медиан — нет.
- Заливка под линией — только у одной серии без пропусков (иначе SVG-путь без `M`).
- Карточка 360 грузит сразу только первые три панели по `order` (`eager`); «Активность» (`order: 40`) за ними раскрывается кнопкой «Показать» — проверяя панель в браузере, её нужно раскрыть.

## Проверка

`node apps/api/scripts/verify-analytics.cjs` (роллап дня, все виды запросов, k-анонимность, фоновая воронка, отчёты и дашборды).
