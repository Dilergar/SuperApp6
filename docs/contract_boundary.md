# Контракт API ↔ клиенты (несущие правила границы)

> HTTP-граница между API и клиентами (веб, mobile, будущий Терминал) — единственный стык, который сам по себе не проверяет компилятор: внутри API типы держит TypeScript, в БД — Prisma, а через провод может улететь `any`. Прошлое mobile-приложение умерло именно от контрактного дрейфа. Класс проблем закрыт **тремя эшелонами**: компилятор → линтер → правила ниже.

## Эшелон 1 — компилятор

- **Одна форма провода = ОДИН тип в `@superapp/shared`, и он стоит на ОБЕИХ сторонах.** На API — тип возврата читающего метода сервиса (`Promise<Dto>`); на вебе — тот же Dto на фетчере. Типа нет в shared → СНАЧАЛА завести в shared, потом использовать.
- **Тип, который не импортирован с обеих сторон, — врёт.** Мёртвых «типов-документации» в shared не заводить.
- **Входные типы = `z.infer` из `validation/*.ts`.** Рукописные `XxxRequest`-интерфейсы запрещены (второе описание Zod-схемы молча отстаёт от первой).
- **Страница едет в `data` цельной** (`CursorPage<T>` / `OffsetPage<T>`) — см. [api_conventions.md](api_conventions.md).
- **WS-события — тот же закон**: payload-типы в shared (`WsMessageNew`, `WsReceipt`, `WsCallState`, карты `MessengerServerToClientEvents`/`MessengerClientToServerEvents`); ими типизированы И gateway (`Server<C2S, S2C>` + `RELAY_MAP … satisfies`), И клиентский хук (`Socket<S2C, C2S>`). Форма enforced на **emit-сайтах** — единственной точке, где компилятор ловит дрейф. Ради этого `EventBusService.emit` принимает `object` (под `Record<string, unknown>` именованные интерфейсы не подходят).

## Эшелон 2 — линтер

- **Клиенты ходят в API только хелперами** `apiGet<T>/apiPost<T>/apiPatch/apiPut/apiDelete` (+`apiGetRaw`/`apiPostRaw` для нестандартных конвертов) из `@superapp/api-client` через свой адаптер (`apps/web/src/lib/api.ts`, ~30 строк). Единственный `as` границы живёт внутри пакета.
- Голый `api.get(...)` и `res.data.data` **запрещены линтером** (`apps/web/eslint.config.mjs`, все правила `error`; локально `pnpm lint` веба, в CI отдельный шаг), включая маскировку деструктуризацией (`const { data } = …; data.data`).
- Нативные `confirm()`/`alert()` запрещены тем же конфигом (см. [web_conventions.md](web_conventions.md)).
- Гостевой клиент `apps/web/src/lib/public-api.ts` — осознанно отдельный axios БЕЗ перехватчиков (второй ремень против 401-ловушки: перехватчик уводит на /login); конверт распаковывают два типизированных хелпера `guestGet/guestPost` с `ApiOk<T>` — только для них точечный override линтера.

## Эшелон 3 — правила

- **Локальный `interface`/`type` для серверного ответа на клиенте ЗАПРЕЩЁН** (правило, линтером не выразимо — ловится ревью): его не проверяет никто, и он молча разъезжается с сервером. Нужен узкий срез — `Pick<>`/`Omit<>` от shared-типа.
- `packages/api-client` — только ТРАНСПОРТ (axios-инстанс, подстановка токена, single-flight ротация refresh под Web Locks, обработка 401, `X-Workspace-Id`; точки инъекции: baseURL, storage, onAuthFailure, getWorkspaceId). Доменные фетчеры и ключи React Query СЮДА НЕ переезжают — уедут доменно, когда попросит второй клиент.
- Ручки, отвечающие голым `{success:true}` без `data`, объявлять `Promise<void>` — не выдумывать тип.
- Осознанные исключения (решение, не дрейф): payload-типы уведомлений с пометкой `ЗАГОТОВКА` (подключатся с центром уведомлений и push); `CalendarLayerItemBase.id` опционален (встроенные kind несут идентичность в своём поле, НОВЫЙ слой обязан отдавать `id`).

## Ловушки (выучены на крови)

- **Веб `tsc --noEmit` проходит ЧИСТО сразу после ломающей смены формы провода**, если клиент читает через `as` — типы без линтера не защищают ничего. Отсюда обязательность эшелона 2.
- **Массовый codemod с «умной» подстановкой типа из объявленного возврата сочиняет ЛГУЩИЕ аннотации** (`apiPost<number>` на ручке, отдающей `{moved: N}`), которые tsc принимает. Автозамене — только однозначные формы; остальное руками.
- Verify-сьют — единственное место, где форма провода проверяется ПО ФАКТУ: скрипты читают строго `json.data.items` / `json.data.nextCursor`; ослаблять до `json.data?.items ?? json.data` нельзя — «терпимость» пропустит ровно тот дрейф, ради которого сьют написан.

## Транспорт: что уже устроено

- single-flight refresh (Web Locks + re-read storage для мульти-таб) — параллельные 401 не ротируют refresh наперегонки;
- `sid` строки сессии чеканится в `generateTokens` и едет в payload access-токена → сервер сам считает `isCurrent` у сессий;
- socket — `auth` как функция (свежий токен на каждом reconnect);
- транспорт покрыт своим сьютом `verify-api-client.cjs` (против живого API).
