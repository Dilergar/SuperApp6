# core/share-links — движок гостевых ссылок «наружу»

> «Поделиться с человеком БЕЗ аккаунта»: токен → гостевая СТРАНИЦА `/s/<токен>` (не сырые байты), срок, отзыв, пароль, лимит открытий, журнал визитов, личность гостя по SMS. core/access НЕ участвует: гость не принципал — **строка ссылки И ЕСТЬ грант**.

## Модель

- **`ShareLink`** — token base64url плейнтекстом на @unique; полиморфные refType/refId БЕЗ FK; ownerType/ownerId/workspaceId из резолвера; passwordHash (bcrypt, мин. 6 символов, счётчики подбора `pwdFailedAttempts`/`pwdLockedUntil` — 5 подряд → 15 мин, верный пароль обнуляет); maxOpens/openCount; снимок `refTitle`/`refIcon`; `settings` (пер-refType опции: allowDownload — оговорка: это НЕ защита от копирования, байты превью и так у гостя, у PDF-просмотрщика своя кнопка — так же осторожно формулируют Google Drive/Dropbox; requireIdentity; notifyOnOpen — по умолчанию ВКЛЮЧЁН, суточный предохранитель `notifyPerDay`); `sessionEpoch` — рубильник выданных пропусков. **Статус (`active|revoked|expired|exhausted`) — ВЫЧИСЛЯЕМЫЙ** (`shareLinkStatus` в shared), в БД не хранится.
- **`ShareLinkVisit`** — журнал (когда/IP/UA/guestId; ретеншн 365 дней кроном; ⚠️ журнал — НЕ доказательство: вечные доказательства живут в core/sign).
- **`ShareLinkGuest`** — личность гостя (unique (ownerType, ownerId, phone) — запись на ВЛАДЕЛЬЦА: организация А не видит знакомств организации Б; мостик к будущему user_id).

## Контракт потребителя

```ts
ShareLinksRegistry.register(refType, { authorizeManage, resolveGuestView, describeRef?, constraints?, actions? })
```
- **У `authorizeManage` ДВА разных отказа**: `null` → 404 (ответ ПОСТОРОННЕМУ — существование не подтверждаем); брошенный `ForbiddenException` → 403 с причиной (тому, кто объект ВИДИТ, но не управляет).
- `resolveGuestView` зовётся на КАЖДЫЙ показ; объект умер/в корзине → `null` (движок переведёт в 410 `share_ref_gone`); не бросать.
- `constraints`: `forbidMaxOpens` (подписные ссылки — лимит открытий ЗАПРЕЩЁН: запер бы подписанта), `requireIdentity` (принудительная личность).
- `actions` — слот действий гостя (потребитель — гостевое подписание core/sign).
- Объект удалён насовсем → потребитель зовёт `revokeAllForRefs(tx|null, refType, ids)` из своего пути удаления (корзину НЕ отзывать — оттуда объект возвращается).
- Байты гостю — системные методы движка файлов (`buildAttachmentViews`, `buildSystemDownloadUrl`); свой @Public-контроллер начинает с `ShareLinksGuestService.authorizeGuest(пропуск)` → `{link, guest}` и САМ проверяет, что запрошенное лежит в скоупе ссылки (вне поддерева → **404, не 403**).

## Гостевой поток (ДВА шага)

`peek` (жива ли, нужен ли пароль — резолвер НЕ зовётся, счётчик НЕ двигается) → `session` (пароль ДО клейма; **атомарный клейм открытия** сырым SQL; личность при requireIdentity: имя + КЗ-номер → SMS цель `share_link_guest` — старт ТОЛЬКО через гостевой контроллер с гейтом по ссылке; verifyToken гасится ОДНОЙ tx с клеймом) → **подписанный пропуск гостя** (HMAC, TTL 60 мин; в sessionStorage веба — F5 не накручивает счётчик). Строка ссылки перечитывается на каждом запросе → отзыв гасит живую сессию немедленно; включение requireIdentity на живой ссылке бампает sessionEpoch.

**Гостевые ручки НИКОГДА не отвечают 401** — только 403/404/410 с машинным `details.code` (`SHARE_LINK_ERROR_CODES`): 401 уводит веб на /login, и «ссылка истекла» превратилась бы в «вас разлогинило». Инвариант закреплён в сьюте на каждом гостевом вызове.

## Управление

`POST /share-links` (лимиты: 20 активных на объект под advisory-локом / 500 на человека) · `GET /share-links?refType&refId` · `PATCH /share-links/:id` (**null очищает, отсутствие ключа сохраняет**; отозванная неизменяема) · `POST /:id/revoke` (идемпотентно) · `POST /:id/rotate` (новый токен, журнал/настройки сохраняются; **ОБЯЗАТЕЛЕН бамп sessionEpoch** — пропуск подписан по linkId) · `GET /:id/visits`.

Витрины: «Ссылки наружу» профиля (`/share-links/mine…` — право = АВТОРСТВО, не текущие права на объект: потерявший доступ обязан уметь закрыть розданное; отзыв только сужает) · «Ссылки организации» (`/workspaces/:id/share-links…`, Менеджер+, отзыв ЧУЖИХ; контроллер живёт в workspaces — движок ролей не знает). Общий обозреватель `components/share-links/ShareLinksBrowser.tsx`; секция на объекте — `<ShareLinkSection refType refId/>`.

⚠️ Статические пути (`/mine`, `/mine/stats`) объявлены ДО `:id`.

## Уведомления об открытии

`share.link.opened` — счётчик уведомлений В САМОМ атомарном клейме (`UPDATE … RETURNING notify_count`); ключ дедупа — атомарный номер открытия за сутки (не прочитанный openCount+1 — параллельные заходы схлопывали уведомления); сутки в APP_TIMEZONE; после `notifyPerDay` — прощальное `…muted` до завтра.

## ZIP папки (потребитель Диск)

`GET /drive/guest/download-zip` — архив ПОТОКОМ (yazl, без временных файлов), по одному файлу за раз, потолки zipMaxBytes/zipMaxFiles с честным отказом, сжатое кладётся без компрессии, уважает allowDownload; обработка ОБРЫВА скачивания (иначе pipeline виснет в бэкпрешере и держит поток к хранилищу); свой троттлинг 5/мин. Единственное место, где пропуск едет ПАРАМЕТРОМ (у навигации браузера нет заголовков; пропуск строго слабее адреса /s/<токен>).

## Осознанно НЕ в v1 (дизайн зафиксирован — не переизобретать)

**Гостевая ЗАГРУЗКА в папку** (модель Dropbox File Request): три режима ссылки; файлы идут на квоту ВЛАДЕЛЬЦА; свой лимит на ссылку; антивирус ПРИНУДИТЕЛЬНО независимо от типа файла; `uploaderId` = создатель ссылки (колонка NOT NULL — у гостя своего id нет). Также отложены: «помнить устройство гостя 30 дней», иностранные номера (гео-щит = только КЗ).

## Ловушки

- Отозванные ссылки НЕ удаляются никогда — поэтому `GET /share-links` обрезан потолком и отдаёт `total` (это и первопричина ловушки `nulls:'first'` ниже).
- Резолвер — ДО клейма открытия (объект в корзине не должен сжигать maxOpens=1).
- Заражённый файл → честное `state:'unavailable'` (не голый 403 движка файлов, подтверждающий заражение постороннему).
- `ORDER BY revoked_at ASC` кладёт NULL в конец — явный nulls:'first'.
- Веб `/s/[token]` — вне каркаса (`AppChrome.isBare`), `robots: noindex`; клиент — отдельный `lib/public-api.ts` БЕЗ перехватчиков.
- Опрос готовности PDF-отпечатка — конечный график (~2 мин, дальше кнопка), не вечный поллинг.
- Право на журнал ссылок даёт САМ объект → окончательное удаление объекта закрывает и журнал его ссылок.
