## Сроки хранения организации

Организация выбирает срок для классов, помеченных в реестре `tenantConfigurable` (`LIFECYCLE_TENANT_CLASSES`):

| Класс | Что это для человека | Политики | Коридор |
|---|---|---|---|
| `user_content_shared` | Общение — сообщения чатов организации | `Message` | [1 день; вечно] |
| `tenant_record` | Документы и хроника — история записей | `ChatterEntry` | [1 день; вечно] |
| `operational` | Интеграции — журнал доставок вебхуков | `WebhookDelivery` | [7; 30] (потолок — общий срок партиций: лист уходит целиком) |

Классы «по закону» (кадры, финансы, юридические записи) показываются карточками без выбора — с нормой (`citations`). Журнал обращений ключей API организации не настраивается: она его не видит, выбор ничего бы не значил.

**Коридор** — `[наибольший пол закона политик класса; min(потолки политик, потолок тарифа)]`. **Потолок тарифа** — ключ `lifecycle.retention.<класс>.ceilingDays` (`limit`, MAX грантов; `null` = без потолка = «вечно», у всех планов по умолчанию `null`). Он ограничивает ВЫБОР: сохранение выше — `402 entitlement.limit_reached` с `unlock` (`EntitlementsService.assertAtMost`, текст `entitlement.aboveCeiling`). Ретроактивно не режет: смена тарифа не удаляет данные молча (Slack 2024) — карточка показывает «выше тарифа» и разблокировку, срок действует, пока организация сама не сменит.

| Ручка (владелец и админ, ключ API не пускается) | Что делает |
|---|---|
| `GET /workspaces/:id/lifecycle/settings` | Карточки классов: коридор, пресеты (замок выше тарифа), текущий срок, отложенное сокращение, кто и когда менял; классы «по закону» |
| `GET /workspaces/:id/lifecycle/summary` | Плитки страницы: место, записи по классам, ближайшее автоудаление, действующие заморозки |
| `POST /workspaces/:id/lifecycle/settings/preview` | Последствия ДО сохранения: строк старше нового срока по политикам класса (`statement_timeout 5 с`), дата начала удаления |
| `PUT /workspaces/:id/lifecycle/settings` | Сохранить: удлинение — сразу; сокращение — отложенно на `LIFECYCLE_SHORTENING_DELAY_DAYS` (30); тот же срок — no-op |
| `DELETE /workspaces/:id/lifecycle/settings/:class/pending` | Отменить отложенное сокращение до вступления (`404 lifecycle.noPendingChange` — нечего) |

Рядовому члену организации страница — `404` (не оракул). **Каждое изменение — одной транзакцией:** строка `lifecycle_settings`, событие журнала безопасности `lifecycle.settings.changed`, хроника раздела (`refType: lifecycle_settings`, `lifecycle_settings.retention_changed|retention_cancelled` — видят владелец и админ), уведомление `lifecycle.retention.changed|cancelled` всем членам организации (кроме автора), факт аналитики `lifecycle.retention.changed`.

**Одна правда — `LifecycleSettings`:** выбор на момент (`lifecycleChoiceAt`: вступившее отложенное сокращение уже действует — отдельной «сверки» принуждение не ждёт), кэш выбора 60 с на процесс (сброс у процесса, сменившего срок), `tenantRetentions(policy)` для раннера, `readCutoff(policy, ws)` для чтения, `tenantChoice(ws, class)` для мессенджера. Срок проходит тот же разрешитель, что UI (`resolveLifecycleRetention`): пол закона и потолок политики срезают выбор.

## Принуждение при чтении

Сокращённый срок действует **сразу**: строки старше не показываются, раннер лишь освобождает место ночью.

- **Хроника** — лента записи и журнал организации режут `createdAt ≥ readCutoff('ChatterEntry', ws)`.
- **Доставки вебхуков** — список доставок режет по сроку `operational`.
- **Сообщения** — «пол» `seq` чата (`MessengerRetentionService.floorOf`): первое сообщение не старше min(таймер чата, срок организации) с полом закона `Message`. Режут лента, непрочитанные, превью в списке чатов, цитата ответа, поиск, доступ к вложению (`canView`/`canEditContent`), правка/удаление/ответ по id (`404 chat.messageNotFound`). Пол — в памяти процесса 5 минут, у процесса, сменившего таймер, — сразу.

## Таймер автоудаления сообщений

`PUT /messenger/chats/:id/timer { days: 1 | 7 | 30 | null }` (`LIFECYCLE_CHAT_TIMER_PRESETS`): личный чат — любой участник, группа — владелец и админ, контекстные чаты (задача, заказ, встреча) — нет (`400 lifecycle.timerNotSupported`). В чате организации таймер не длиннее её срока сообщений (`400 lifecycle.timerAboveWorkspace`), «выкл» = действует срок организации. Смена — status-guarded переход (двойной клик не даёт двух плашек), системная плашка `chat.timer_set|timer_off`, факт `lifecycle.timer.set`, сброс пола. Деталь чата несёт `retention { timerDays, workspaceDays, effectiveDays, allowedPresets, canChange }`; веб — чип в шапке «Исчезают через N» и меню пресетов (длиннее срока организации — не предлагаются). Раннер — шаг `messenger.retention` (организации по сроку и чаты с таймером, пачки по seq).

## Заморозка на карточке записи

`GET /workspaces/:id/lifecycle/holds/status?type=user|<политика>&id=<uuid>` → `{ held }` — чип «Заморожено до снятия» (`components/lifecycle/HeldChip.tsx`, слова `common.heldChip.*`) на карточке сотрудника и документа (`OrgDocument`). Считаются только заморозки ЭТОЙ организации (платформенные организация не видит). Не участник — `404`; участник ниже руководителя — `false` без отказа (тихая заморозка, отказ был бы оракулом); хранитель не узнаёт о своей заморозке ни по своей карточке, ни по записи, которую держит только она. Запись проверяется на принадлежность организации (`404 lifecycle.holdTargetInvalid`); покрытие — тот же SQL, что у сохранения оригинала (`holdsCoveringRowSql`).

## Уведомления

Реестр `packages/shared/src/notifications/lifecycle.ts`: `lifecycle.retention.changed|cancelled` (всем членам организации, ссылка — страница организации; без схлопывания — `collapse: 'none'`: сокращение одного класса не перекрывает уведомление о другом), `lifecycle.hold.created|released` (владелец и админ, кроме хранителя — тихая заморозка), `lifecycle.erasure.completed` (владельцу стёртой организации — `notifyUserId` заявки, ссылка — `/legal/erasure`). Адресаты — `core/audiences`, ссылки — `NotificationRefRegistry` (`lifecycle_retention`, `lifecycle_hold`).

## Дашборд «Данные» Кабинета (`/platform/data`)

Право `data.read`; шесть вкладок в адресе (`?tab=`), обновление 30 с, бюджет — общая дверь Кабинета (`platform:rate:*`, 60 запросов в минуту). Данные — агрегаты без ПДн. Тяжёлые вкладки считаются не чаще раза в 30 с на процесс.

| Вкладка | Ручка | Что внутри |
|---|---|---|
| Обзор | `GET /platform/data/overview` | Шесть светофоров (база: возраст XID к 1 млрд, реплики, соединения · бэкапы: окно PITR, последний успех, учение · партиции: запас вперёд, зависшие DETACH · сроки: отстающие политики · стирания: в работе, застряли, под заморозкой, среднее до «стёрто» · канарейка), рост хранилища по классам за 90 дней, удалено строк в сутки, «Нужно внимание» (код + серьёзность + одно действие) |
| Хранилище | `/storage` | Топ-30 таблиц (размер, рост за 7 дней по снимкам, строки, доля мёртвых, автовакуум, невалидные индексы) с поиском и сортировкой; соединения; блокировки; команда «Неиспользуемые индексы» |
| Сроки | `/retention` | Реестр политик: класс, принуждение, срок (пол/умолчание), строки и отставание по ночному снимку, последний прогон; признаки `runnable` (раннер ведёт — пробный прогон и пауза) и `overridable` (построчное удаление без своего шага — срок командой) |
| Стирания | `/erasure` | Очередь (псевдоним, этапы tick-прогрессом, возраст; упавшие и застрявшие — первыми и сразу «застряло»), заморозки платформы (цель — ссылкой на карточку 360, имён нет), число заморозок организаций |
| Бэкапы | `/backups` | Полоса покрытия окна (35 суток), прогоны и учения (длительность, размер; проверки восстановления и RTO), репликация хранилища; «Восстановление организаций» — архивы и импорты, команды `lifecycle.restore.extract` и `lifecycle.restore.import` ([lifecycle_export.md](lifecycle_export.md)) |
| Канарейка | `/canary` | 30 прогонов: хранилищ, находки (хранилище · вид), длительность; переход в журнал безопасности (`lifecycle.canary.failed`) |

`GET /platform/data/summary` — худший из шести светофоров, плитка на главной Кабинета. **Сигналы БД** — `lifecycle_db_overview()` (SECURITY DEFINER под `sa6_monitor`): приложение получает числа, а не тексты запросов чужих сессий. **Рост** — ночной снимок `lifecycle_storage_daily` (06:40 по Алматы, по таблице: размер, строки, старейшая строка).

**Команды** (`lifecycle.platform.provider.ts`): `lifecycle.retention.dryRun` (medium), `lifecycle.retention.pause` (high, step-up, причина), `lifecycle.retention.override` (critical, «четыре глаза», не ниже пола, только построчное удаление без шага модуля), `lifecycle.erasure.retry` (high: упавшее — снова в работу, `completedAt` падения снимается), `lifecycle.indexes.report` (low, результат в журнал не пишется). Переопределения — `lifecycle_policy_overrides`; раннер читает их в `modeOf`/`rulesOf`. Панели карточки 360 — `user.lifecycle` (удаление аккаунта, заявки на стирание, заморозки хранителя) и `workspace.lifecycle` (архив и окончательное удаление, сроки организации с отложенными, заморозки, стирание).

### Отчёты бэкапов и учений

`POST /lifecycle/ops/backups/report` — вне сессии Кабинета (под `/platform` всё — сессия сотрудника): `Authorization: Bearer LIFECYCLE_OPS_TOKEN` + `X-Lifecycle-Signature: t=<unix>,v1=<hex HMAC-SHA256(токен, "<t>.<сырое тело>")>`, окно 300 с; токен не задан — в production `404` (fail-closed), в разработке открыто. Тело — `lifecycleBackupReportSchema` (вид, репозиторий, статус, метка прогона, время, байты, детали кодами: проверки восстановления, RTO, лаг репликации, WAL). Идемпотентно по (вид, репозиторий, метка): повтор перехваченного отчёта строку не заводит. Отчётов ещё не было — светофор бэкапов в разработке «нет данных», в production «критично»; успешного бэкапа дольше 26 часов или упавшее учение — «критично» (GitLab 2017: алерт на отсутствие, а не только на ошибку).

- **Организация** — `/workspaces/[id]/profile/data/(retention|holds|history)`: плитки, карточки классов (пресеты «Вечно · 1 год · 90 · 30 · 7 · 1 день», «Другое…», замок выше тарифа, предпросмотр и подтверждение вводом названия организации — `useConfirm({ requireText })`, отложенное изменение с «Отменить»), заморозки (область · причина · кто · с какого дня; постановка и снятие), хроника раздела.
- **Человек** — «Мои данные»: поле кода квитанции → публичная `/legal/erasure/<код>`.
- **Кабинет** — `/platform/data`, пункт меню «Данные», плитка на главной, панели 360. Словарь дашборда — неймспейс `platformData`, едет только на `/platform/data` (вложенный layout); общее для главной и карточки 360 — `platform.data.*`; `lifecycle` грузят только страницы, где он нужен (`app/platform/namespaces.ts` — общий список неймспейсов Кабинета: вложенный провайдер ЗАМЕНЯЕТ словарь).

## Ловушки

- **Потолок тарифа — ограничение выбора, не срок.** Применённый ретроактивно, он удалил бы данные организации молча при смене тарифа.
- **Сокращение без задержки — скандал.** Только через 30 дней, с уведомлением всем и отменой до вступления.
- **Чтение обязано резать само.** Раннер ночной и может отставать; без пола чтения «удалённое по сроку» показывалось бы сутками.
- **Статус заморозки не должен быть оракулом:** ниже руководителя — «нет» без отказа, хранителю — «нет», чужому — `404`.
- **Упавшее стирание само не продолжится** — в очереди оно первым и сразу «застряло»; метрика `lifecycle_erasure_failed`.
- **Отчёт бэкапа под `/platform` невозможен** — там всё требует сессии сотрудника; отдельный путь с токеном и подписью тела.

## Проверка

`node apps/api/scripts/verify-lifecycle.cjs`, раздел 7 — коридор (пол, потолок политики, число строкой), потолок тарифа условием Кабинета (`402` с разблокировкой), предпросмотр, отложенное сокращение (журнал безопасности, уведомление члену, хроника только владельцу), отмена, чтение режет сразу, раннер удаляет только строки организации, заморозка (уведомление админу, хранителю — нет), статус заморозки (видит руководитель, хранитель-админ о себе не узнаёт, чужая организация и чужая запись — `404`), сводка, таймер (права, пресеты, лента режет, раннер удаляет, плашки). Раздел 8 — приём отчётов (подпись, идемпотентность, кривой — `400`), вкладки и признаки строк сроков, продуктовый токен в Кабинет не пускает, команды (пауза со step-up, срок не ниже пола, секционированный журнал — нельзя, пробный прогон, отчёт индексов), упавшее стирание в очереди и его повтор. Регресс — `verify-entitlements`, `verify-platform-console`, `verify-messenger*`, `verify-chatter`, `verify-webhooks`.
