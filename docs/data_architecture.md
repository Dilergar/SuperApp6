# Архитектура данных

> Где живут данные, как к ним подключаться, сколько они живут, как их вернуть и как понять, что слою плохо. Реестр сроков и стирания — [lifecycle_engine.md](lifecycle_engine.md); рунбук бэкапов — [operations_backup_dr.md](operations_backup_dr.md); dev-среда — [dev_environment.md](dev_environment.md).

## Карта

| Хранилище | Роль | Где |
|---|---|---|
| PostgreSQL 18 (primary + синхронный standby) | всё, что должно пережить сбой | город 1 |
| асинхронная реплика PostgreSQL | DR и отчёты (`ANALYTICS_READ_DATABASE_URL`) | город 2 |
| PgBouncer 1.26 (режим транзакций) | пул приложения (`DATABASE_URL`) | рядом с API |
| Redis «состояние» (`REDIS_URL`) | шина, локи, лимиты, эпохи, надгробия, окна детекций, сокет-адаптер | город 1, noeviction + AOF |
| Redis «кэш» (`REDIS_CACHE_URL`) | пересобираемое из базы: профили, роли, права, тарифы, видимость, присутствие | город 1, allkeys-lfu, без персистентности |
| S3-совместимое хранилище | байты файлов, архивы журналов и выгрузок, бэкапы | два города, версии + Object Lock |

Всё — только в Казахстане (ЗоПД ст. 12). Второй город не стоит на пути запроса. Каждое хранилище, таблица и семейство ключей Redis объявлены в реестре `core/lifecycle` (владелец, класс данных, срок, поведение при стирании); незарегистрированное роняет CI и бут.

## Идентификаторы

- Первичные ключи — нативный `uuid` (16 байт), значение генерирует БАЗА: `@default(dbgenerated("uuidv7()"))` — сырые INSERT получают те же v7 и одни часы.
- v7 раскрывает момент создания: публичные id записей, чувствительных ко времени (инциденты ПДн, тревоги безопасности, заявки на стирание, заморозки), — v4.
- Капабилити (ссылки-приглашения, share-ссылки, токены) — 256 бит случайности, никогда не UUID (RFC 9562 §8).
- Id непрозрачны: ни битов шарда, ни смысла — переезд арендатора в другую ячейку не меняет id.

## Владелец данных и готовность к ячейкам

Ключ владельца объявляется в реестре per-модель (`user` · `workspace` · `conversation` · `ledger` · `global`) — розетка будущих ячеек без физического шардирования сейчас. Правила, которые держит страж `check:lifecycle` (отчёт-ратчет): индекс ведёт ключ владельца; внешний ключ не пересекает владельцев, кроме глобальных справочников; нет `int4` ключей; `findMany` без `take` на таблицах владельца учитывается.

## Таблицы: что партиционировано

- **Партиции** (RANGE по времени, листья заводят и сбрасывают только SECURITY DEFINER-функции владельца `sa6_data_owner`): журнал безопасности, события аналитики, журнал доступа ключей API, доставки уведомлений и вебхуков, `idem.*`. Ключ партиции неизменяем.
- **Без партиций — навсегда или до триггера**: сообщения (путь чтения — `(chatId, seq)` без границы времени; пересмотр при > 100 ГБ — hash по `chatId`), очередь джобов (prune + `REINDEX CONCURRENTLY` раз в неделю), хроника (живёт с сущностью), леджер (append-only триггером; при > 100 ГБ — RANGE по самому UUIDv7).
- Время: старые колонки — `timestamp(3)` (UTC-литерал без смещения), новые таблицы движков — `timestamptz(3)`. В сыром SQL — только `utcTs()`/`ts(d)`.

## Подключения к PostgreSQL

| Адрес | Кто ходит | Почему |
|---|---|---|
| `DATABASE_URL` → PgBouncer `:6432` | приложение (Prisma), сьюты | режим транзакций: соединение базы отдаётся на транзакцию — тысячи клиентов на сотню соединений |
| `DIRECT_URL` → база `:5432` | `prisma migrate` (`directUrl` схемы), онлайн-DDL, `DatabaseMaintenance`, сьюты с сессионным `SET` | всё, чему нужна сессия |

- **Размер пула процесса — явно** (`connection_limit` в `shared/database/database-url.ts`: `DATABASE_POOL_SIZE` или 2 × ядра, 5…50). Сумма по инстансам — бюджет `max_db_connections` пулера, а не `max_connections` базы.
- **Совместимость с режимом транзакций**: advisory-локи — только `pg_advisory_xact_lock`; настройки — только `SET LOCAL` / `set_config(…, true)`; `LISTEN/NOTIFY` не используется; Prisma без `pgbouncer=true` (подготовленные выражения держит пулер, `max_prepared_statements = 200`).
- **Потолки роли приложения** (`db-roles.sql`, часть 3): `statement_timeout 30s`, `idle_in_transaction_session_timeout 60s`, `transaction_timeout 5min`. Законно долгое внутри транзакции поднимает свой `SET LOCAL statement_timeout` (запросы Кабинета, раннер сроков). Обслуживание (REINDEX очереди, суточный роллап аналитики) — `DatabaseMaintenance`: прямой адрес, 2 соединения, потолки сняты параметром `options` (параметры запуска старше `ALTER ROLE … SET`; пулер `options` не пропускает). Клиент обслуживания голый — только сырой SQL служебных таблиц, никогда чтение данных людей.
- **Асинхронный коммит пачек логов**: вставки событий аналитики и журнала использования ключей API идут транзакцией с `set_config('synchronous_commit', 'off', true)` — пачка не ждёт сброса WAL и синхронной реплики; сбой сервера теряет не больше ~0,6 с строк, и только целыми транзакциями. Деньги, журнал безопасности и всё с обязательством перед человеком — только синхронно.
- Роли: `sa6_app` (приложение), `sa6_migrate`, `sa6_data_owner` / `sa6_audit_owner` (владельцы журналов и денег, NOLOGIN), `sa6_readonly` (5 с, только чтение), `sa6_backup`, `sa6_monitor` (статистика кластера — функциями-сводками, приложению только EXECUTE), `sa6_pgbouncer_auth` (вход пулера через `auth_query`, паролей в пулере нет).
- Настройки кластера — `infra/postgres/superapp6.conf` (UTC, `max_locks_per_transaction 256`, lz4/zstd, `max_slot_wal_keep_size 50GB`, `pg_stat_statements` + `auto_explain`, логи без значений параметров, autovacuum под append-only).

## Redis: две роли

- **Роль ключа объявляет реестр** (`redis:<семейство>`, `packages/shared/src/lifecycle/stores.ts`: шаблоны, роль, потолок TTL, шаблон субъекта для стирания). Страж `verify-lifecycle.cjs`: каждый ключ обоих инстансов принадлежит семейству, лежит в инстансе своей роли, срок не выше потолка и не вечный.
- **Кэш — только через `RedisService.cache`**: читатель обязан пережить промах И сбой (→ база); запись — всегда со сроком; не версионированный кэш сбрасывается `cache.forget` (DEL сейчас и через 2 с — гонка «заполнение/сброс», Meta 2022). Лучше — ключ под эпохой из состояния (`acl:chk:<эпоха>…`, `ent:snap:<эпохи>…`, `vis:facts:<эпоха>…`): запись после сброса ложится под старую эпоху и не читается.
- **Состояние — `getClient()` и методы `RedisService`**: то, чья потеря — ошибка корректности или безопасности (локи, лимиты, окна и паузы детекций, надгробия ключей API, одноразовые отметки, эпохи). Не смешивать роли в одной MULTI/MGET: два инстанса — два запроса.
- **Путь запроса не ждёт Redis**: офлайн-очередь ioredis выключается после первого `ready` — команда при разрыве падает сразу. Блокирующее чтение (XREADGROUP шины и аналитики) — отдельное соединение `duplicateForBlocking`.
- **Версия — Redis 8.10** (пин в `docker-compose.yml`; тег единственный — CI берёт его оттуда; `verify-health.cjs` сверяет `redis_version` живого сервера с пином). **Модули образа не грузятся**: entrypoint образа Redis 8 подключает всё из `/usr/local/lib/redis/modules` (Search, JSON, TimeSeries, Bloom) независимо от конфига — поверх каталога пустой tmpfs; встроенный `vectorset` остаётся и закрыт ACL. Лог сервера без ключей и значений (`hide-user-data-from-log yes`).
- **ACL**: приложение — `sa6_app`, права **только перечнем команд** (`-@all` + `+команда`, каналы — `&socket.io#*`). Категории (`+@read`, `+@all -@dangerous`) запрещены: в Redis 8 они включают команды модулей и каждую новую команду версии — права росли бы с обновлением сервера. KEYS / CONFIG / DEBUG / RESTORE / MIGRATE / MODULE / FLUSH* / SORT / BACKUP в перечень не входят (обход ключей — только SCAN). `default` в проде выключен, пароли только хешем (`infra/redis/users.acl.template`). **Новая команда в коде** → строка в перечне ОБОИХ файлов (`users.dev.acl`, `users.acl.template`; страж `check:lifecycle` сверяет их, запрещает категории и закрытые команды); dev ответит `NOPERM` сразу, а отказ в пути с `.catch()` поймает шаг CI `redis-acl-denials.cjs` (ACL LOG обоих инстансов после сьюта).
- **ПДн в Redis** — только со сроком ≤ суток или шифротекстом (профиль в кэше — конверт под KEK человека); стирание человека = DEL его ключей по шаблонам реестра в инстансе роли + ежесуточный `BGREWRITEAOF` состояния.
- **Сокеты**: socket.io — sharded adapter (SPUBLISH, канал на комнату): событие `user:<id>` получает только инстанс с сокетом человека. Pub/Sub ничего не хранит — пропущенное за разрыв клиент добирает через API (`onReconnect`).

## Бэкапы и восстановление

pgBackRest в два репозитория (два города), шифрование, 35 дней PITR, блочные инкременты каждые 6 часов, WAL непрерывно (RPO ≤ 1 мин); ночное учение восстановления со сверками (строки, Σ=0 леджера, дайджесты журнала безопасности, журнал стираний) и отчётом с RTO; восстановление одной организации без отката базы; журнал стираний реплеится после любого восстановления. Всё — [operations_backup_dr.md](operations_backup_dr.md), [lifecycle_export.md](lifecycle_export.md).

## Наблюдаемость

- `GET /health/live` — процесс жив (без зависимостей); `GET /health/ready` — база и Redis-состояние критичны (503), Redis-кэш, партиции вперёд и свежесть бэкапов — деградация (200 `degraded`): общая беда не снимает все инстансы с балансировщика. Проверки движков — реестр `HealthRegistry` (`shared/health`). Разбивка — держателю `METRICS_TOKEN`.
- `GET /metrics`: сторожевые сигналы БД раз в 5 минут с каждого инстанса (`lifecycle_db_*` — возраст XID и multixact, лаг реплик, удержание WAL слотами, LockManager, невалидные индексы, доля кэша, чекпойнты, временные файлы, соединения, самая долгая транзакция, архиватор WAL), свежесть бэкапов и учений, отставание сроков, HTTP-гистограмма по шаблону маршрута, статус проверок готовности.
- Лаг потоков Redis Streams (шина событий, приём аналитики): `sa6_stream_lag` / `_pending` / `_length` / `_maxlen` раз в 5 минут. XADD с `MAXLEN ~` обрезает и непрочитанное — тревога на `lag > MAXLEN / 2`, пока хвост цел.
- Тревоги — `infra/prometheus/alerts.yml` (порог → действие). Главные — на ОТСУТСТВИЕ: тишина сторожевого опроса (Stripe 2019) и отсутствие отчёта бэкапа 26 часов (GitLab 2017).

## Миграции без простоя

Страж `pnpm check:migrations` (заголовок `SET lock_timeout`/`statement_timeout`, `CREATE INDEX CONCURRENTLY` — единственный оператор файла, запреты на больших таблицах) и онлайн-раннер `apps/api/scripts/db-online-ddl.cjs` — [lifecycle_engine.md](lifecycle_engine.md#миграции-без-простоя). Бюджет обычной миграции ≤ 3 минут, иначе — фоновая батчами.

## Триггеры масштабирования

| Сигнал | Действие |
|---|---|
| таблица > 100 ГБ | партиции / ревью шарда этой таблицы |
| БД > 2 ТБ или WAL/CPU > 60 % | планирование ячеек; первым уезжает мессенджер (своя БД, hash по `chatId`) |
| аналитика > 3000 событий/с | дневные партиции, затем ClickHouse |
| claim p99 джобов > 50 мс или > 1000 джобов/с | джобы в отдельную базу |
| первая организация > 10 % строк | инструмент переезда арендатора (копия → логическая репликация по владельцу → сверка → переключение) |
| CPU primary > 60 % на чтениях | чтения на реплику с токеном read-your-writes |
| Redis Cluster | многоключевой Lua — под хэш-тегом (лимитер: `throttle:{…}`); MULTI/MGET эпох прав и тарифов через разные слоты — переписать на конвейер при переходе |

## Ловушки

- **Сессионный `SET` через пул** уходит одному соединению, следующий запрос — другому: только `SET LOCAL` в транзакции или прямой адрес с `connection_limit=1`.
- **`ALTER ROLE … SET` младше параметров запуска**: обслуживающее подключение снимает потолки роли `options`, пулер `options` не пропускает — поэтому оно прямое.
- **PgBouncer: повторный `[pgbouncer]` после `%include` сбрасывает прочитанное** — общие ключи в файле без заголовка секции (`infra/pgbouncer/pgbouncer.common.ini`).
- **Redis: рестарт с `appendonly yes` на томе с одним RDB поднимает ПУСТОЙ набор** — сначала `CONFIG SET appendonly yes` на живом.
- **ACL-файл Redis не допускает комментариев**; защищённый режим рвёт подключения не с localhost, когда у `default` нет пароля. ACL лежит в своём каталоге (`/usr/local/etc/redis-acl/`): entrypoint образа правит права каталога конфига только когда в нём один файл, иначе пишет notice на каждом старте.
- **Отказ ACL проверяется ПОСЛЕ арности**: команда с неверным числом аргументов отвечает `ERR wrong number of arguments`, а не `NOPERM` — канарейка ACL обязана звать команду с правильным синтаксисом.
- **Redis 8 читает данные 7.x как есть, 7.x данные 8.x — нет**: откат версии — только из копии тома, снятой до обновления.
- **`duplicate()` ioredis копирует опции** — после `ready` в них `enableOfflineQueue: false`; блокирующему соединению очередь включается явно.
- **Кэш-ключ одноразовой отметки — не кэш**: вытеснение повторит однократное событие (тревогу, уведомление) — такие ключи в роли «состояние».
