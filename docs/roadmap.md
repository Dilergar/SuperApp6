# Дорожная карта и технический долг

> Статусный документ (единственный в docs/, где даты уместны). Детальный gap-анализ с чек-боксами — [gap_analysis_v2.md](gap_analysis_v2.md). Продуктовое видение — `/PRODUCT.md`.

## Этапы

1. **Сейчас: новые сервисы** на готовом веб-фундаменте (каждый — через грилл дизайна перед стройкой).
2. **Mobile** — подготовка (push-пайплайн, design-tokens, upload, OTP-экран) + переписать приложение целиком. `packages/api-client` уже построен. **Жёсткий блокер**: текущее mobile шлёт `register` без `verifyToken` — в production вернёт 400; OTP-экран строится в НОВОМ приложении.
3. **AI** — сервисные ассистенты + SuperAIAgent6 с голосом (архитектура готовится уже сейчас: тонкие контроллеры = будущие AI-инструменты).
4. **Терминал + Умный дом/IoT** — железо после AI-софта.

Фоном, не блокируя этапы: хвост прод-минимума и web-гигиена (ниже).

## Технический долг

**Границы движков (аудит 2026-09-02)**: правило «движки `core/*` не импортируют фичи» нарушено в коде в одном месте: `core/users` зовёт `modules/contacts` и `modules/workspaces` (активация приглашений по номеру) — решение НЕ выбрано, вопрос открыт (варианты — в gap-анализе, «Архитектура (долги)»). Долги «семь движков → `modules/notifications`» и «`core/rich-cards` → `modules/messenger`» закрыты движками **`core/notifications`** (17-й) и **`core/realtime`** (18-й): чат — канал доставки уведомлений, драйвер регистрирует мессенджер ([notifications_engine.md](notifications_engine.md), [realtime_engine.md](realtime_engine.md)). Остаток записан исключением в [module_graph.md](module_graph.md), §4, и в `KNOWN_CORE_TO_MODULES` стража `scripts/check-docs.cjs`.

**Уведомления — остаток после движка**: канал `email` — контракт без доставки (нет SMTP и верификации почты; в UI не показывается) · живые драйверы push `expo`/`fcm` — на mobile-этапе (модель `NotificationDevice` и контракт `PushDriver` готовы) · `follow`-подписка на объект есть в модели, UI — с первым потребителем · сводки/дайджесты по расписанию (Novu digest) — по запросу.

**Оргструктура (2026-09)**: кампании ознакомления молча обрезают аудиторию на `campaignMaxTargets` (движок адресатов сохранил семантику вызывающего; честный отказ — только при создании); `STAFF_FULL_SCOPE_ROLES` = `['owner','admin','manager']` — Менеджер пока полновластен над структурой, сужение до owner/admin одной константой вместе с ролью «Кадры»; матричное подчинение, проектные команды, онбординг-шаблоны структур — по запросу; переброс уже созданных заявок на заместителя не делается намеренно (снимки адресатов неприкосновенны).

**Мелочи аудита 2026-09-02**: `class-validator` в зависимостях API не используется (глобальный `ValidationPipe` инертен при Zod-входе) — снять или оставить как страховку; `API_URL` (Процессы) и `API_PUBLIC_URL` — две переменные одного смысла, слить в одну; запрет прямого импорта `@phosphor-icons/react` вне `Icon.tsx` не покрыт ESLint; у `PersonAvatar` своя шкала размеров (`sm|md|lg`), у `PersonChip` — `CardSize` XS–XL — при желании единой шкалы это правка кода.

**Журнал безопасности — деньги и секреты (отложено 2026-09-23)**: не пишутся в `core/audit` смена платёжных реквизитов и секретов — карта для выплат человека (`payment-cards.service.ts`: добавить/изменить/удалить; сейчас без события, уведомления и step-up — подмена карты = кража выплат при угоне), банковские счета организации (`legal-entities.service.ts`, `workspaces.service.ts` `add|update|removeBankAccount`), реквизиты контрагентов (`counterparties.service.ts` — схема «поставщик сменил счёт»), секреты интеграций Процессов (`processes.service.ts` `create|deleteCredential`). Предложенные умолчания (Workday/банки): карта — событие человеку + уведомление без ссылок + step-up и запрет в cooling-сессии; счета организации и контрагентов — событие организации + уведомление владельцу/админам; секреты — событие организации, как у ключей API ([audit_engine.md](audit_engine.md)).

**Прод-минимум (частично сделан)**: сделаны /api/v1, AllExceptionsFilter, helmet, fail-closed env, enableShutdownHooks. Остаётся: `/health`, Dockerfile API, verification-токен Google-вебхука, прод-наблюдаемость dead-letter джобов (`job.discarded` без подписчиков, /jobs/stats только dev), TURN/TLS 443 + wss для звонков, RNNoise-WASM, **`CLAMAV_HOST` (+ `CLAMAV_PORT`) у API прода** — без него загрузки не проверяются антивирусом (`scanStatus='none'`, выдача заражённого файла не блокируется) и журнал безопасности не видит вирусов (`files.malware_detected`, детекция `malware_burst`); после запуска — проверить EICAR-файлом ([files_engine.md](files_engine.md)).

**Mobile-подготовка (блок 8)**: push-пайплайн — модель `NotificationDevice` (platform ios/android, provider expo/fcm), ручки регистрации и контракт `PushDriver` ГОТОВЫ в `core/notifications`; остаётся живой Expo/FCM-драйвер и `expo-notifications` в приложении · пакет `design-tokens` (будущий, в `packages/`; палитра сейчас живёт только в CSS веба) + платформо-нейтральные поля CardSkinTokens · upload-модуль mobile · мобильные роуты зеркалят веб-пути (actionUrl = deep link). После подготовки mobile ≈ 50–55% новой работы.

**Кабинет платформы — решения ревью (2026-09-12, применены)**: состав штата (`platform.staff.*`) и сам тумблер four-eyes (`platform.policy.set`) идут через второго сотрудника (`dualControl` + `dualControlSoft` — пока владелец один, исполняются напрямую, иначе кабинет запирается насмерть) · `platform.pii.reveal` требует SMS-подтверждения (`stepUp`) · мёртвое право `processes.system.manage` снято (`tier: 'system'` не объявлен ни у одной ноды; когда появятся системные ноды, их откроет команда кабинета) · способности кабинета читаются только внутри `core/platform`, продуктовый путь их не спрашивает (страж `no-restricted-imports`, исключение — снятие со штата при анонимизации в `core/users`). Остаётся решить по ходу: узкие роли (`support`, `billing`, `security`) — сейчас живая роль одна, `platform_owner`.

**Кабинет платформы и тарифы — отложено осознанно (2026-09-12)**: токен кабинета живёт в `localStorage` — переезд на отдельный домен `admin.<домен>` с httpOnly-cookie, CSP и IP-allowlist · WebAuthn/passkeys вторым фактором вместо SMS · `view_as` (смотреть глазами человека) · кастомные роли поверх `PLATFORM_ROLES` · палитра ⌘K поверх реестра команд (когда команд станет 20+), сохранённые фильтры и очереди · оплата (`source: 'payment'`) и семейный план в `core/entitlements` · перенос прочих `isSystemAdmin`-операций в команды кабинета — [platform_console.md](platform_console.md), [entitlements_engine.md](entitlements_engine.md).

**Web-гигиена (остатки)**: `shop/page.tsx` на старом useState-стиле (70 useState — переводить при следующей работе над магазином) · распил >800-строчных файлов по ходу · правило кита для голых `<input>` линтером не покрыто.

**Правила видимости полей ПОСТРОЕНЫ** (2026-09-24): `core/visibility` (27-й) — реестр семи типов записей (`user.card`, `workspace.card`, `staff.member`, `hr.employment`, `objects.staffing`, `objects.shift`, `counterparty`), личная политика человека и матрица организации «поле × адресат» с черновиком, диффом, версиями, пресетами и «четырьмя глазами» через `core/approvals`; провод `Guarded<T>`, маски только на сервере, потолки класса поля и бота/ключа (флаг «Доступ к контактным данным»), раскрытие одной записи под SMS с `pii.reveal`, детекция массового раскрытия, находимость по номеру, маскирование хроники при чтении; стражи — страж ответа, ESLint, `check:visibility`, канареечный и property-based сьюты — [visibility_engine.md](visibility_engine.md). **v2 осознанно**: record-level «кого я вижу» в адресной книге (модель WeCom/DingTalk через `core/access` `card#viewer`) · псевдонимные id людей для ботов (`open_id`/`union_id`) · второй ремень БД (расшифровка `sensitive` только в области `shape`) · DLP-детекторы ИИН / номера карты / телефона в свободном тексте · условно видимые поля в фильтрах через CASE (opt-in) · CSV/XLSX-экспорт отчётов по видимым полям · «здоровье» как отдельный класс с кадровой ролью · правовая сверка ([legal_kz.md](legal_kz.md)).

**Журнал аудита безопасности ПОСТРОЕН** (2026-09-23): `core/audit` (26-й) — единый поток `security_events` с тремя зрителями, в него переехали пять журналов (ключей, команд и доступа Кабинета, чтений ПДн, учёта действий с ПДн); защита входа по аккаунту, сессии-семейства, cooling 24 ч, экстренная заморозка без входа, мастер «Это не я»; журнал организации по тарифу + экспорт на Диск + SIEM-стрим; консоль «Безопасность» в Кабинете; дайджесты Меркла, архив месяцев, 9 детекций — [audit_engine.md](audit_engine.md). **Остаток осознанно**: GeoIP-база (город, ASN, анонимайзеры) и детекции на ней (`detect.impossible_travel`, `detect.session_context_changed` — `planned`) · дайджесты по срезу организации и готовые коннекторы Splunk/Sentinel (v2) · видимость `counterparty` («сотрудник магазина смотрел ваш заказ») · внешнее закрепление корней дайджестов (публичный журнал прозрачности) · правовая сверка ([legal_kz.md](legal_kz.md)).

**Движок ключей + вебхуки ПОСТРОЕНЫ** (2026-09-17): `core/keys` (22-й) — корень в файле/HSM-интерфейс, envelope с AAD, слепые индексы, Ed25519-подпись с JWKS и ротацией без разлогина, reuse-detection refresh, шифрование ПДн (dual-write, `KEYS_PII_READ_MODE`), ключи API и боты, реестр/журнал/политика/каскады, раздел «Интеграции и ключи»; `core/webhooks` (23-й) — Standard Webhooks, доставка с ретраями, аудит битой подписью — [keys_engine.md](keys_engine.md), [webhooks_engine.md](webhooks_engine.md). **Остаток**: дроп открытых ПДн-колонок после прода в `encrypted` ([keys_pii.md](keys_pii.md)); удалить `JWT_SECRET` после `KEYS_LEGACY_HS256_UNTIL`; провайдер `pkcs11` (сертифицированная СКЗИ/ГОСТ — по заключению юриста); учение восстановления корня раз в квартал; уведомление регулятора об инциденте (1 рабочий день) и ГСКД — прод-минимум с юристом; gitleaks с регуляркой `sa6_…` при включении SAST; регистрация префикса в GitHub secret scanning после публичного запуска; OAuth2-провайдер и витрина приложений, AI-агенты (`actor_token`), устройства/POS (X.509), passkeys/ЭЦП как step-up, секреты сайдкаров из `.env`, шифрование имён — вне v1.

**Пагинация списков, растущих с организацией или Окружением (ревью видимости 2026-09-24)**: ростер `GET /workspaces/:id/members` (`listMembers`) отдаёт ВСЕХ сотрудников одним ответом — без курсора, `take` и страницы (правило «страница едет в `data` цельной `CursorPage`» здесь нарушено): на организации в тысячи человек это мегабайты JSON и `shape()` всех карточек за раз, а детекция скрейпинга (`detect.pii_scrape`, порог 20 000 чужих строк/час — оставлен как есть решением 2026-09-24) получает ложную тревогу от легитимного админа. Задача: (1) инвентаризация списков без страницы — кандидаты по сигнатуре `Promise<Dto[]>`: чаты (`listChats`), объявления и заказы магазина (`listListings`, `listMyOrders`), заметки (`listItems`), определения Процессов (`listDefinitions`), недавние и избранные Диска (`listRecent`, `listStarred`), долги и люди Финансов (`listDebts`, `listPeople`), кадровые действия «мои» (`listMine`), записи Диктофона; у части есть внутренний `take` — считать честной страницей только `CursorPage`/`OffsetPage` с `limit` в контракте; (2) ростер — курсорная страница по 50–100 (API + `@superapp/shared` + веб: ключ RQ меняет форму — `useInfiniteQuery`, поиск по имени — серверный); (3) остальные — по мере роста данных, справочники фиксированного размера (пресеты, шаблоны смен, версии) не трогать.

**Архитектура данных ПОСТРОЕНА** (2026-09-25): `core/lifecycle` (28-й) — реестр жизненного цикла всех хранилищ со стражем, смоуком бута и ратчетом готовности к ячейкам; нативный uuid v7; партиции журналов под функциями владельца; раннер сроков, каскад организации, loose FK; заморозки на всех путях удаления; стирание человека и организации (квитанция, сертификат, канарейка); сроки организаций, таймеры чатов, дашборд «Данные»; выгрузки целиком и восстановление одной организации; PgBouncer, потолки ролей, две роли Redis с ACL, pgBackRest с учениями, пробы `/health`, сторожевые метрики и тревоги — [data_architecture.md](data_architecture.md), [lifecycle_engine.md](lifecycle_engine.md). **Остаток осознанно**: хостинг PG18 (managed или Patroni) и S3-провайдер (смоук `s3-conformance.cjs`) · юридическая сверка полов сроков ([legal_kz.md](legal_kz.md)) · экспортёры redis/pgbouncer и развёртывание правил `infra/prometheus/alerts.yml` · байты `pg_multixact/members` — метрикой файловой системы хоста (SQL-функции нет) · чтения на отчётную реплику с токеном read-your-writes — по триггеру CPU · ячейки, Redis Cluster (MULTI/MGET эпох через слоты → конвейер), журнал восстановлений (DELF), каталог размещения арендаторов, крипто-шреддинг текста чатов, лента изменений — v2 по триггерам.

**Жизненный цикл данных — остаток Э5 (2026-09-25)**: каталог `platform` ≈ 41 КБ (порог стража 40 КБ) — основной вес `platform.commands` всех движков; кандидат делить: подписи команд — в неймспейс движка-владельца, консоль «Безопасность» — свой неймспейс, как `platformData` у дашборда · клиентское событие `lifecycle.dashboard.viewed` не заведено: у Кабинета своя сессия, продуктовый SDK аналитики туда не ходит; вкладки дашборда — агрегаты без ПДн, в журнал просмотров не пишутся · системные плашки чатов, записанные до пар «имя ↔ id», id не несут — стирание их не находит (на 2026-09-25 только dev-база, прода нет) — [lifecycle_settings.md](lifecycle_settings.md), [lifecycle_erasure.md](lifecycle_erasure.md).

**Известные ограничения (осознанные)**: юнит-тестов 0 (страж — e2e-сьют) · Google Calendar live OAuth не тестирован (нужны креды) · пер-экземплярные исключения повторов синкаются на уровне master+EXDATE.
