# Штатное расписание (сервис «Объекты», часть 4)

> План ставок и людей вокруг объекта: штатная ЕДИНИЦА (должность × объект) существует и вакантной, назначение датировано, ставка версионируется. Объект, дерево и права — [objects.md](objects.md).

Код: `apps/api/src/modules/objects/staffing.service.ts` + `staffing.controller.ts`; веб — `apps/web/src/app/workspaces/[id]/objects/[objectId]/staffing/`.

## Модель

- **`StaffingPosition`** — штатная ЕДИНИЦА: должность × объект, `headcount` («по штату N»), `shiftTemplateId`, архив. Существует и ВАКАНТНОЙ — на этом держится план затрат. Рукописный `UNIQUE(branch_id, position_id) WHERE archived_at IS NULL`.
- **`StaffAssignment`** — датировано: `startsOn`/`endsOn` (null = без границы), `rateShare` (0.5 ставки), `staffingPositionId`, `isPrimary`. Закрытое назначение ОСТАЁТСЯ (на него ссылаются ставки и смены). Уникум «человек × должность × объект» СНЯТ; вместо него EXCLUDE по диапазону дат + `CHECK (ends_on >= starts_on)`.
- **`StaffRate`** — ВЕРСИЯ ставки (SCD2, append-only): цель — штатная единица (план) XOR назначение (факт); `rateType` (`monthly | per_shift | hourly`, `revenue_share` зарезервирован — только хранение), `amount` BigInt тиыны, `effectiveFrom`/`effectiveTo`.

## HTTP API

| Путь | Что делает |
|---|---|
| `GET objects/:objectId/staffing?period=YYYY-MM` | Таблица: единицы, вакансии строками, назначения, ставки и счётчики смен — по `caps` |
| `POST objects/:objectId/staffing/positions` · `PATCH/DELETE staffing/positions/:spId` · `POST …/rates` | Штатные единицы + плановая ставка |
| `POST objects/:objectId/staffing/assign` · `PATCH staffing/assignments/:aId` · `POST …/close` · `GET/POST …/rates` | Назначение (ставка ТОЙ ЖЕ транзакцией) · даты/доля · закрытие · версии ставок |

## Несущие правила

- **Ставка версионируется, а не перезаписывается.** Новая ставка с даты D закрывает предыдущую (`effectiveTo = D−1`) в ОДНОЙ транзакции. Версия ЗАДНИМ ЧИСЛОМ обязана закрыться следующей — иначе в истории две «бессрочные» ставки, и ответ на «сколько платили в марте» держится на удачной сортировке.
- **Официальный оклад — только чтение из КЭДО.** Меняется приказом `salary_change` ([hr_kedo.md](hr_kedo.md)); штатка показывает его и ведёт свою, управленческую ставку.
- **Ставка и назначение появляются ОДНИМ коммитом** (хук `inTx` внутри `assignPositionSystem`): «назначили, а платить забыли» — состояние, которого быть не должно.
- **Ранг субъекта уважается.** `assignPositionSystem` прав не проверяет по контракту `system*`, поэтому назначение, правка и закрытие зовут `StaffService.assertRankOver`: управляющий точкой не трогает назначения владельца организации.
- **Дата закрытия сверяется с началом В СЕРВИСЕ** (400), а не только `CHECK` в БД: нарушение CHECK Prisma отдаёт сырой ошибкой, и в общем фильтре она превращалась в 500.
- **Ролловер прав — на полночь ПОСЛЕ конца.** Окно назначения включительное: в последний рабочий день человек ещё работает, поэтому джоб `staff.assignment.rollover` ставится на `endsOn + 1` в поясе объекта.
- **Основным становится следующее, только если закрывали ОСНОВНОЕ.** Безусловное повышение ломало партиальный уникум «одно основное на человека» и отдавало 409 на ровном месте.

## План затрат (порт `ObjectsPayrollPort`)

`getPlannedPayroll(ws, {branchId?, from, to})` — строки по штатным единицам, ВКЛЮЧАЯ вакансии (незанятая ставка — тоже деньги), суммы тиынами строкой. Окно назначения обязано ПЕРЕСЕКАТЬСЯ с периодом (иначе человек, принятый на будущий год, попадал в план текущего месяца), вакансии считаются долями ставок (`headcount − Σ rateShare`), а ставки выбираются скоупом по цели и периоду — иначе тянулись ВСЕ версии всех людей сети.

## Ловушки

- **Партиальный уникум ≠ `@unique` Prisma**: `upsert({ where: { … } })` по нему не компилируется — писать `findFirst` + `create/update`.
- **Postgres режет имена индексов до 63 символов.** `DROP INDEX` по «полному» имени молча ничего не делает — дропать по ФАКТИЧЕСКОМУ имени из `pg_indexes`.
- **`btree_gist`** нужен для EXCLUDE `staff_assignments_no_overlap` (`CREATE EXTENSION IF NOT EXISTS btree_gist` в миграции).
- **На архивную единицу назначать нельзя** — в таблице её нет, и человек либо проваливается в чужую строку, либо исчезает из штатки, продолжая работать.
- **`ends_on` — колонка DATE**: сравнивать её с `new Date()` нельзя (единица архивировалась под человеком, чей последний день сегодня) — только с датой.
- **BigInt на проводе — строкой**; агрегаты считаются в `bigint`.

## Веб

Таблица: строки — люди единицы + строки-ВАКАНСИИ; денежные колонки рисуются по `caps.payrollView` ИЗ ОТВЕТА (сервер таких полей без права не отдаёт вовсе). Действия штатной единицы висят на ПЕРВОЙ строке группы: когда все ставки заняты, вакансий нет, и иначе единицу нельзя было ни изменить, ни убрать. Закрытое назначение показывается чипом «до ДД.ММ» и приглушением (поле `assignment.active`). Период и дата закрытия считаются в поясе ОБЪЕКТА (`lib/objects-time.ts`). Окно «Ставки» открывается и без права на деньги — под именем «Период»: ошибочно закрытое назначение чинится только там.

## Проверка

`node apps/api/scripts/verify-objects.cjs` — раздел «Штатное расписание»: единицы и дубль 409, вакансии строками, назначение и ставка одним коммитом, пересечение назначений 409, версии ставок, закрытие и повторное назначение, закрытие датой раньше начала 400, сужение денежных полей.
