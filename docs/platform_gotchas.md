# Сквозные ловушки платформы

> Ловушки, не привязанные к одному домену (доменные лежат в своих доках, раздел «Ловушки»). Каждая — выучена на реальном инциденте. Прежде чем «чинить» странное поведение — проверь, не одна ли это из них.

## Среда и сборка

- **Стейл-процесс на :3001**: старый `node dist/main.js` держит порт со старым кодом в памяти — новый параметр/ручка отвечает 400 при полностью правильном коде. Проверить, чей процесс слушает порт, ПЕРЕД отладкой.
- **Полный tsc на apps/api = OOM.** Только `nest build`.
- **tsc не работает из Git Bash на Windows** — сборки через PowerShell.
- **`nest start --watch` держит Prisma DLL** → EPERM на `prisma generate`.
- **Литеральный NUL-байт в исходнике** (эмитится некоторыми Write-инструментами вместо escape) делает файл НЕВИДИМЫМ для ripgrep — файл «пропал» из поиска, но существует; чинить PowerShell'ом.
- Порядок пересборки shared → api-client → api/web несущий (сборка против старого dist).
- **Prisma migrate дропает то, чего нет в схеме**: партиальные уникумы, generated tsvector, GIN-индексы — дописывать руками в миграцию И зеркалить комментом в schema.prisma.

## Ключи, ПДн, вебхуки (`core/keys`, `core/webhooks`)

- **Dual-verify окна**: legacy HS256 (`KEYS_LEGACY_HS256_UNTIL`) и prev-секрет вебхука (`prevExpiresAt`) — токен/подпись «ещё работает» после ротации по дизайну; «не отозвалось» ≠ баг, пока окно не закрыто.
- **Dual-write ПДн**: в `legacy` читаются открытые колонки — правка `_enc` руками невидима; в `encrypted` строка без `_bi` (посев сырым SQL) не найдётся по номеру — `POST /keys/dev/pii/backfill`. Порядок `$extends` несущий: `piiExtension` ДО `workspaceScope`.
- **`KEYS_PII_READ_MODE` — на один деплой**: сьюты, гоняемые в `encrypted`, возвращают `legacy` в `finally` (`verify-keys-pii.cjs`), иначе соседний сьют падает на ростере.
- **Снимок ключа API кэшируется 60 с**: любое изменение (отзыв, ротация, скоупы бота, allowlist, заморозка) обязано звать `invalidateByHash` — иначе «не сработало» до минуты.
- **Step-up окно 15 мин** переживает перезапуск клиента и сьюта: проверка `403 keys.step_up_required` начинается с `POST /keys/step-up/end`.
- **Новый контроллер под `/workspaces/:id/…` роняет бут** (`KeysRoutesAudit`): маршрут организации обязан быть либо строкой `KEY_SCOPE_SERVICES` (с `$` для точного пути), либо `@NoApiKeys()`, либо `@Public()`. Это не ошибка окружения — решение «пускать ли ключи» принимается в коде.
- **Партиции журналов ключей** (`api_access_log`, `pii_access_log`): месяц без партиции = ошибка вставки `no partition of relation`; бут и крон заводят три месяца вперёд, слив батча заводит недостающую и повторяется один раз. Ретеншн — `POST /keys/dev/usage/partitions` в dev.
- **Заморозка KEK = 403 везде**: `keys.key_unavailable` на чтении ПДн/секретов скоупа — состояние kill-switch, не порча данных; разморозка возвращает всё.
- **Prisma `Bytes` = `Uint8Array`**: `Buffer` из `node:crypto` заворачивать `Uint8Array.from`.
- **`prisma migrate diff --from-url` на живой БД** всегда тянет дрейф индексов аналитики (`*_dims_key`) — вырезать из ручной миграции.
- **Глобальный `APP_GUARD`/`APP_INTERCEPTOR` из AppModule** резолвит зависимости в контексте AppModule: провайдер @Global-модуля обязан быть в его `exports` (иначе «can't resolve dependencies» на буте).
- **Вебхуки на loopback** только с `WEBHOOKS_DEV_LOOPBACK=true` в development; endpoint в `pending_verification` получает лишь пинг; общий приёмник получает событие по разу на endpoint.
- **Кап бэкоффа движка джобов — час**: «N попыток ≈ трое суток» без своего `backoffCapMs` у типа — неправда, сколько попыток ни объяви (считать сумму пауз, а не верить комментарию).

## Браузерная проверка (агентом или руками)

- **Скрытая панель/вкладка**: `document.hidden` глушит rAF и ResizeObserver — React Flow не рисует рёбра, virtuoso не рисует ленту, Suspense-чанк `$RC` не раскрывается. Проверять во ФРОНТОВОЙ видимой вкладке.
- **Непокрашенная страница ≠ `document.hidden`**: у свёрнутого окна и скрытой панели браузера `document.hidden === false` и `visibilityState === 'visible'`, но кадров нет — молча не срабатывают ни `requestAnimationFrame`, ни `scrollIntoView({behavior:'smooth'})` (плавная прокрутка идёт покадрово). Признак — `window.innerHeight === 0`: замеры вёрстки в этот момент недостоверны, лечится эмуляцией вьюпорта (`resize_window`). В коде: то, что ОБЯЗАНО случиться, откладывать `setTimeout(…, 0)`, а не rAF.
- **CDP-скриншоты не видят PDF-плагин Chromium** (чёрный/пустой iframe — артефакт скриншота): PDF проверять байтами blob, не глазами скриншота.
- **CDP-эмуляция размера не шлёт resize/media-query события** и морозит transitions при скрытой панели.
- **У встроенного браузера предпросмотра УРЕЗАННЫЙ ICU**: `Intl` знает локаль `kk`, но данных к ней нет, и месяц прописью выходит «M09 5», день недели — «Sat», а `NumberFormat('kk')` группирует по-английски. Это артефакт сборки панели, а НЕ баг продукта: у Node (полный ICU) и настоящего Chrome та же дата — «5 қыркүйек». Проверять сомнительный формат в казахском одной строкой в `node -e`, прежде чем «чинить» форматтер.
- **React-состояние после `.click()` читать С ОЖИДАНИЕМ** — синхронное чтение даёт ложную находку.
- HMR-ошибки проверять в НОВОЙ вкладке. **Новый динамический `import()` в живом dev-сервере** даёт в консоли `[Turbopack HMR] Expected module to match pattern …` — это несовпадение реестра чанков, а не баг кода: модуль резолвится, слова рисуются, а новая вкладка уже чистая.
- **Консоль КОПИТ ошибки вкладки** (навигация их не чистит): «ноль ошибок консоли» проверяется в НОВОЙ вкладке, иначе чужие 409/403 прошлых проб читаются как свои.
- `curl -s <url> | grep -c '$RC('` → 0 — скрининг залипающих Suspense-границ (подробно — [web_conventions.md](web_conventions.md)).

## Веб-код

- Корневой `app/loading.tsx` вешает 404 на вечный спиннер — границы ожидания только на уровне сервисов.
- Нативные `confirm()`/`alert()` могут молча возвращать false / не показываться (галочка «блокировать диалоги») — сбой выглядит как успех. Только `useConfirm`/`toastError`.
- `z.coerce.boolean()` на query: строка `'false'` — истинна; только `queryBoolean`.
- CSS-импорты пакетов из чистого `.ts` Turbopack не кладёт в сборку — переносить в `.tsx`.
- Mantine пин `^8.3.11` — не поднимать до 9 до апгрейда Next на react 19.2+.
- `<input type="date">` не принимает точки — вводить ISO-форматом при автоматизации.
- Один RQ-ключ = одна форма кэша (useQuery vs useInfiniteQuery — крах «reading 'length'»).

## API-код

- Статические пути ДО `:id` в контроллерах (Nest иначе ищет сущность «mine»/«inbox»).
- `ORDER BY nullable ASC` в Postgres кладёт NULL в КОНЕЦ — явный `nulls: 'first'`, где важно.
- NULL-сентинел нельзя кодировать в keyset-курсор нулём (обрыв списка на первой «грязной» строке) — NULLS LAST + двухфазный keyset.
- Время в сыром SQL — только через `utcTs()`/`ts(d)`; `now()` и голый параметр-Date запрещены (доворот поясом сессии).
- `-ErrorAction SilentlyContinue`-класс ловушек: throw внутри try, съедаемый соседним catch, отключает предохранитель молча (прецедент — потолок ZIP).
- `pipe(res)` в Nest без `@Res()` = пустой 200.
- Сырые `$queryRaw` не скоупятся chokepoint'ом — фильтр workspaceId руками.
- Redis best-effort: сбой Redis не должен останавливать фоновую работу и не должен превращаться в unhandled rejection.

## Процессы и правила работы

- **Стража проверять на срабатывание**: подсадить нарушение → увидеть падение → убрать. Зелёный линтер зелен и когда селектор промахнулся.
- **Сверять план построчно** при отчёте о готовности этапа: опаснее всего «механизм есть на бэкенде, но веб его не зовёт» — сборка и тесты этого не ловят.
- **Правило долговечности правил**: правило, записанное не во всех путях (напр. защита от удаления в одном из двух путей удаления), НЕ действует. Новое правило — grep всех путей.
- «Проверили при открытии» ≠ проверено в момент действия (членство/права перерешивать при действии).
- `!== false` в парсере доверенного ответа = «молчание — согласие» (fail-open). Только явное подтверждение.
- Цвета не придумывать — нет оттенка в DESIGN.md → вопрос пользователю (исключение — цвет-ДАННЫЕ).
- Смысл несёт ФОРМА: статус = Chip, действие = Button; «покрашенное слово» запрещено.
- Не показывать UI несуществующих фич (data/API future-proof — да, видимый UI — нет).

## Идемпотентность повторов (`core/idempotency`)

- **Отпечаток включает query и params.** `?ms=0` и `?ms=12000` — РАЗНЫЕ запросы: один ключ на них честно даёт `422 key_reused`. Чаще всего об этом спотыкаются сьюты, повторяющие «тот же» вызов с другим параметром.
- **`@SkipIdempotency` на контроллере покрывает все его ручки.** Добавляя в такой контроллер необратимую операцию, снимайте исключение точечно, а не оставляйте «как было».
- **Страж на буте fail-closed.** Новая мутация с `@Res()` без `raw_response`, `required` на `@Public` без резолвера принципала, причина вне списка — бут падает со списком маршрутов. Это не помеха, а способ не выпустить дыру.
- **`atomic: true` — обещание, которое проверяется.** Не больше одной отмеченной транзакции и ни одной записи мимо неё; в development нарушение роняет запрос 500. Ноль транзакций законен (ручка ничего не сделала).
- **Ноль строк в `idem.keys` на горячей ручке — это норма**, а не поломка: «прочитано», раскладка доски и автосохранение объявлены `naturally_idempotent`/`own_mechanism` намеренно, иначе каждый кадр прокрутки писал бы строку в БД.
- **`INSERT … ON CONFLICT DO NOTHING` ЖДЁТ чужую транзакцию.** Если конфликтующую строку прямо сейчас меняет незавершённая транзакция (обычный `UPDATE` внутри `$transaction`), проверка уникальности не знает, останется ли строка, и ждёт коммита — «ничего не делающий» INSERT висит секундами и держит соединение пула. То же у голого `UPDATE … RETURNING` и `SELECT … FOR UPDATE` без `SKIP LOCKED`. Где ждать нельзя: сначала MVCC-снимок (`SELECT`), INSERT — только `WHERE NOT EXISTS (снимок)`, запись — через `FOR UPDATE SKIP LOCKED` (приём `IdempotencyStore.open`). Ловится не глазами, а сьютом: держать транзакцию открытой и мерить время второго запроса.
- **NUL-байт в исходнике.** Разделитель скоупа пишется как `'\u0000'` ЛИТЕРАЛОМ; записанный в файл настоящий NUL делает файл невидимым для ripgrep и ломает diff.
