# SuperApp6 — CLAUDE.md

**SuperApp6** — экосистема **B2C + B2B**: «ERP для жизни и бизнеса». Один аккаунт, один `user_id` навсегда — и внутри 100+ сервисов (целевой масштаб): задачи, календарь, чат, финансы, магазин, документы, кадры, звонки… Рынок — Казахстан; идея на стыке суперапп-подхода WeChat/Kaspi и ERP (Salesforce/Odoo). B2B живёт в том же приложении как организации-арендаторы (заголовок `X-Workspace-Id`).

**Карта документов проекта:**
- `CLAUDE.md` (этот файл) — правила работы и несущие принципы;
- **`docs/`** — КАНОН архитектуры: движки, сервисы, конвенции, ловушки (индекс — `docs/README.md`);
- `PRODUCT.md` — продукт, пользователи, позиционирование;
- `DESIGN.md` — дизайн-система (ОБЯЗАТЕЛЕН перед любым UI);
- `docs/gap_analysis_v2.md` — живой план; `docs/roadmap.md` — этапы и техдолг.

## 2. Философия разработки: Никакого MVP

- **Правило долговечности:** При работе над новыми частями и функциями проекта термины и подходы класса «MVP» (минимально рабочий продукт) строго запрещены. У нас нет задачи «проверить гипотезы» и выкатить неустойчивую заплатку.
- **Качество по умолчанию:** Мы проектируем и пишем код правильно, надолго и архитектурно устойчиво. Наши компоненты и модули должны быть изначально готовы к горизонтальному масштабированию, отвечать строгим стандартам безопасности, производительности, консистентности данных и изоляции (B2B/B2C).
- **Проектирование наперёд:** Во время планирования и реализации мы не обрезаем функционал, а думаем на несколько шагов вперёд (на уровень AI-инструментов, будущей интеграции с IoT, мобильным клиентом и т.д.). Пользователь (разработчик) сам укажет рамки реализуемой версии, если это потребуется.
- Перед крупной стройкой — **грилл дизайна**: trade-offs + бенчмарки гигантов, спорное — вопросами пользователю (с рекомендациями), второстепенное — автодефолт решениями гигантов.

## 3. Главный инструмент поиска: graphify

В проекте развёрнут локальный индексатор и анализатор кодовой базы на основе графов — **graphify**. Этот инструмент имеет приоритет над brute-force чтением и поиском.

- **Правило первого хода:** ИИ-агент ОБЯЗАН использовать локальные команды утилиты `graphify` перед выполнением широкого поиска по коду с помощью `rg` (ripgrep), glob-поиска или построчного чтения больших файлов.
- Команды: `graphify query "<вопрос>"` (скоупленный подграф) · `graphify path "<A>" "<B>"` (связь между сущностями) · `graphify explain "<концепт>"`. Результат обычно в разы меньше сырого grep.
- После изменения кода: `graphify update .` (AST-only, без API-затрат) — граф остаётся актуальным.
- Правило принудительно: в `.claude/settings.json` стоят hook-guard'ы на Bash/Grep/Read/Glob. Это правило распространяется и на субагентов — включай его в их промпты.
- `/graphify` — триггер скилла `.claude/skills/graphify/SKILL.md` (любой ввод → граф знаний).
- Точечное чтение/правка конкретных строк и файлов, которые graphify уже указал, — нормальный следующий шаг (для навигации по символам есть Serena, §12).

## 7. Принципы платформы (обязательны для КАЖДОГО нового сервиса)

1. **Сначала переиспользуй, потом пиши.** Новый сервис = тонкий модуль + регистрации в движках. Движка не хватает → он РАСШИРЯЕТСЯ, а не копируется. Карта готового — ниже.
2. **Человек в UI = карточка, ВЕЗДЕ.** Только `PersonChip`/`PersonAvatar` (5 размеров XS–XL), не голый текст — несущее продуктовое правило (видимость платных скинов).
3. **Rich Card — где уместно и было бы отлично добавить для удобства.** Сущность со статусами и действиями обязана уметь рендериться рич-картой (`core/rich-cards`).
4. **AI-ready.** Каждая операция вызываема программно: тонкий контроллер + Zod + способность (= будущие AI-инструменты). Чтение AI — напрямую из БД строго через `core/access`; действия — только через сервисные API (денежное — без исключений).
5. **Device-agnostic.** Веб, mobile (этап 2), Терминал — равноправные клиенты ОДНОГО API `/api/v1`. Пока нативного приложения нет, мобильный веб обязан работать.

## 8. Архитектура (несущее)

- **Модульный монолит** NestJS: каждый сервис — изолированный модуль. Связи ДВУХ видов: синхронные вызовы (атомарность: деньги в одной `$transaction`) и EventBus (Redis Streams, **at-most-once** — только то, что можно потерять). Обязательный фон — `core/jobs` (transactional outbox). **Новое синхронное ребро → добавить в `docs/module_graph.md`.** Циклы — ленивые токены из манифеста `shared/di-tokens.ts` (смоук на bootstrap).
- **Universal Identity**: роли в `user_roles(user_id, role, context, tenant_id)`; лестница `contractor < trainee < staff < manager < admin < owner`; найм всегда в trainee; contractor изолирован. Движки `core/*` не импортируют фичи — обратное направление только через реестры.
- **Контракт API↔клиенты** (три эшелона — компилятор, линтер, правила): одна форма провода = один тип в `@superapp/shared` на ОБЕИХ сторонах; вход = `z.infer` из Zod-схемы; страница едет в `data` ЦЕЛЬНОЙ (`CursorPage`/`OffsetPage`); клиенты — только хелперы `@superapp/api-client`; локальный interface серверного DTO запрещён. Детали — `docs/contract_boundary.md`.
- **Безопасность**: fail-closed env (всё, кроме явных development/test, = прод); tokenEpoch отзывает access-токены; IP только из `req.ip` (TRUST_PROXY); голый `fetch` в API запрещён линтером. Детали — `docs/security.md`.
- Решения «НЕ делать» (не возвращаться): микросервисы; переписывание core/access; SSR веба; слой «Контакты» (всё — «Окружение»). Полный список — `docs/roadmap.md`.

## 9. Несущие правила (выжимки; полные версии — в доках)

**API** (`docs/api_conventions.md`):
- Флаг в query — ТОЛЬКО `queryBoolean` (никогда `z.coerce.boolean()`: строка `'false'` истинна).
- Статические пути объявлять ДО `:id` (иначе Nest ищет сущность «mine»/«inbox»).
- Методы `system*` движков прав НЕ проверяют — проверяет вызывающий (первое, что смотрит ревью).
- Переходы состояний — status-guarded `updateMany`; идемпотентность — уникальные индексы; партиальные уникумы — руками в миграцию + коммент в схеме.
- Время в сыром SQL — только `utcTs()`/`ts(d)`; `db push` запрещён (только prisma migrate).
- Все ошибки — единый конверт через `AllExceptionsFilter`; машинные коды в `details.code` (клиент не ветвится по русскому тексту).

**Веб** (`docs/web_conventions.md`):
- Нативные `confirm()`/`alert()` ЗАПРЕЩЕНЫ → `useConfirm()` / `toastError()`.
- Примитивы — только кит `components/ui/`; человек — только `PersonChip`/`PersonAvatar`; пикеры — `EntitySelector`; пикер не предлагает того, что сервер отвергнет.
- RQ-ключи — в `lib/queries.ts`; один ключ = ОДНА форма кэша (useQuery и useInfiniteQuery несовместимы на общем ключе).
- Новый сервис = +1 строка `lib/app-nav.ts` + 1 файл `<сервис>/loading.tsx` (в корне app/ — НЕЛЬЗЯ).
- Смысл несёт ФОРМА (статус = Chip, действие = Button); цвета не придумывать — нет в DESIGN.md → спросить (исключение — цвет-данные); UI несуществующих фич не показывать.

**Данные и фон** (`docs/jobs_engine.md`, `docs/module_graph.md`):
- Деньги и security-обязательные эффекты — только синхронно в одной транзакции.
- Джоб ставится `enqueue(tx, …)` В транзакции мутации; обработчик идемпотентен, делит ошибки на транзиентные (throw) и постоянные (JobDiscardError); клейм не коммитить до эффектов.
- Хроника пишется `log(tx, …)` синхронно в транзакции мутации.

**Процесс работы**:
- Стража/правило проверять НА СРАБАТЫВАНИЕ (подсадить нарушение → увидеть падение → убрать).
- Отчёт о готовности этапа — сверив план ПОСТРОЧНО (опаснее всего «бэкенд есть, веб не зовёт»).
- Правило действует, только если стоит во ВСЕХ путях (оба пути удаления и т.п.).
- После UI-правок — браузерная проверка (0 ошибок консоли); ловушки проверки — `docs/platform_gotchas.md`.

## 10. Команды

> **Windows:** tsc НЕ работает из Git Bash — сборки через PowerShell (`powershell -Command "cd path; command"`). Полный tsc на apps/api падает по памяти — только `nest build`.

```bash
docker compose up -d                        # PostgreSQL 16 + Redis 7
pnpm install
cd packages/shared && pnpm build            # ПОРЯДОК НЕСУЩИЙ: shared → api-client → api/web
cd ../api-client && pnpm build
cd apps/api && pnpm db:generate && npx prisma migrate deploy   # схему менял → pnpm db:migrate
pnpm dev                                    # всё сразу (API :3001, Web :3000, Swagger /api/docs в dev)
pnpm lint:guard                             # оба линт-стража (~7с, из корня)
pnpm check:docs                             # страж документации (~2с): пути, индекс, env, рёбра модулей; --write обновляет module_graph_edges.md
node apps/api/scripts/verify-<name>.cjs     # e2e-сьют (при запущенном API)
```

Docker-профили сайдкаров (`--profile s3|scan|voice|calls|docs|pdf|sign`), свои сборки образов (docs-editor c обязательным `-FlushDiscovery`, sign-verifier) и ловушки среды — `docs/dev_environment.md`. Env-переменные — `docs/environment_variables.md`.
