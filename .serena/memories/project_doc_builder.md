# Блочный конструктор документов (2026-08-08)

«Создать документ с нуля внутри SuperApp6, не загружая Word» — построен ЦЕЛИКОМ за сессию: builder-шаблоны + свободные документы + PDF-рендер. Решения пользователя (грилл): гибрид PandaDoc (лист как в Notion + смарт-блоки + DnD обоих видов), PDF через Chromium 1:1, скоуп v1 = шаблоны + свободные документы организации, Word-файл на выходе не нужен.

## Архитектура
- **Формат блоков — СВОЙ в shared** (`types/doc-builder.ts` + рекурсивный Zod в `validation/doc-builder.ts`), НЕ сырой JSON BlockNote: редактор — сменная деталь, конвертер (`builder-convert.ts`) тонкий и живёт на клиенте. Исключение из «тип входа = z.infer» задокументировано (рекурсия + discriminatedUnion не инферятся).
- **Чип данных**: `path` в формате docx-тегов («Организация.БИН», «Форма.<ключ>») — реестр TemplateFieldRegistry и форматтеры core/templates ОБЩИЕ для docx- и builder-шаблонов.
- **Рендер — второй драйвер core/templates** (`builder-render.driver.ts`): блоки+значения → печатный HTML (А4, PT Serif, ГОСТ-поля 20/10/20/20, красная строка, склейка списков; strict → TemplateDataError списком, мягко → метка ‹путь›). `PdfRenderService` — Gotenberg (профиль `pdf`, порт 3030, env GOTENBERG_URL, инертен без него). Колонтитул «стр. N из M» — нативный footer Chromium в полях ИЗ ПАРАМЕТРОВ (с preferCssPageSize футеров не будет).
- **Файл builder-документа = сам PDF** (`fileId`): джоб documents.generate ветвится по `doc.builderDoc`; пересборка — replaceContent на месте (id стабилен); documents.pdf пересобирает из текущих блоков и ставит pdfFileId = fileId. Весь хвост (заморозка статусом, номер, маршрут, подшивка, гостевые ссылки) не переделывался.
- DocTemplate.kind ('docx'|'builder') + builderDoc Json; OrgDocument.builderDoc = СНИМОК (правка шаблона не меняет поданное). Миграция `doc_builder`.
- Публикация builder-шаблона: checkBuilderDoc против реестра + полей формы (400 полным списком); «пустой» = нет ни одного блока с содержимым (blocks.length НЕ критерий — свежий лист несёт пустой абзац; поймано сьютом).
- Превью = НАСТОЯЩИЙ PDF стримом (`POST templates/:id/preview`, `POST :documentId/preview`; override builderDoc в теле — превью несохранённого холста). Образцы полей формы + пример номера по формату вида.
- Лого в шапке: data:URI, качаем ТОЛЬКО свои `/public-files/` (произвольный URL из настроек орг — SSRF).
- Шрифты: infra/pdf-fonts (PT Serif OFL, казахский алфавит) — volume в Gotenberg И копия в apps/web/public/fonts (превью тем же шрифтом). Проверено: PTSerif embedded в PDF, ә ғ қ ң ө ұ ү һ і.

## Веб (components/doc-builder/)
BlockNote 0.53: ядро MPL-2.0 (ок, как Collabora), **XL-пакеты GPL/платные — НЕ СТАВИТЬ** (экспорт PDF/DOCX у нас свой). Кастомные блоки requisites/docMeta/signature/pageBreak + inline chip; слэш-меню и «{»-меню свои русские; панель справа: группы данных + «Форма подачи» (+ добавление поля на месте с автовставкой чипа) + карточки «Блоки» draggable; DnD из палитры: drop → elementFromPoint → closest('[data-id]') → insertBlocks after (работает нативным драгом CDP). Автосейв дебаунс 1.2с + дожим на unmount. Три входа: страница шаблона (kind=builder), `[documentId]/edit` (правка draft), CreateFreeDocumentModal («Создать документ» в реестре).

## ЛОВУШКИ (проверены в браузере)
1. **CSS-импорты пакетов из чистого .ts-модуля Turbopack НЕ кладёт в сборку** — стили BlockNote не грузились вовсе (меню голым текстом); переносить `import '@blocknote/mantine/style.css'` в .tsx компонента.
2. `insertOrUpdateBlock` в BlockNote 0.5x переименован в `insertOrUpdateBlockForSlashMenu`; `createReactBlockSpec` возвращает ФАБРИКУ — в схему идёт вызов `RequisitesBlock()`.
3. Заголовок группы слэш-меню ≠ title пункта («Текст»+«Текст» = duplicate React key).
4. **PDF-плагин Chromium не попадает в CDP-скриншоты** — iframe с blob-PDF выглядит чёрным; проверять байты blob (fetch → %PDF), не скриншот.
5. `frame-src` CSP должен нести `blob:` — превью-PDF открывается blob-URL (добавлено в next.config; report-only ловил).
6. `useEffectEvent is not a function` — НЕ HMR-артефакт (первая оценка была неверной: у пользователя падал весь раздел в error.tsx на «Создать документ»). Причина: Mantine 9 (приехала за BlockNote) зовёт `useEffectEvent` из React 19.2, а App Router Next 15.5 подменяет react на ВЕНДОРЕННЫЙ (~19.1) без этого хука — node_modules react 19.2.4 клиентским графом не используется. Лечение: пин `@mantine/core@^8.3.11` + `@mantine/hooks@^8.3.11` прямыми зависимостями apps/web (peer @blocknote/mantine допускает ^8.3.11 || ^9; Mantine 8.x useEffectEvent не зовёт вовсе — проверено grep'ом). **Mantine НЕ поднимать до 9, пока Next не вендорит react 19.2+.**

## Доводка по обкатке пользователем (2026-08-08, вторая волна)
1. **ФИО с отчеством**: `users.middleName` (миграция `user_middle_name`), поле «Отчество» в анкете веба (блок «Для договоров»; в карточках не показывается). Группа «Сотрудник»: `ФИО` = «Фамилия Имя Отчество» (key «ФИО» НЕ переименовывать — теги существующих бланков), `Отчество` отдельным полем. e2e-проверка ФИО — через дев-полигон `POST /templates/dev/resolve` (ответ под `data.values`).
2. **Период дат**: kind `daterange` («Период дат»), значение `{from,to}`; хелперы в shared/constants/org-documents: `isDocDateRangeValue`, `docDateRangeDays` (включительно), `expandDocFormValues` — разворот в плоские ключи «X С»/«X По»/«X Дней»/«X» (строка «с … по …»; один день = просто дата). Разворот стоит в `documentValues` джоба (docx И builder) и обоих превью — глубоких путей в тегах НЕТ намеренно. Публикация: суффиксные чипы — законные пути (`formKeys` flatMap). `sanitizeFields`: объект проходит ТОЛЬКО как строго валидный период на объявленном daterange-поле (защита от подмены групп не ослаблена). Веб: общий `FormFields` (SubmitDocumentModal) — `DatePicker` кита для date, `DateRangeField` (два пикера + тумблер «Один день», to=from, min у «По») для периода; карточка документа рисует поля ТЕМИ ЖЕ контролами — `OrgDocumentDto.formFields` (объявление формы из шаблона); панель конструктора даёт 4 чипа периода, даты вставляются с format='дата' по умолчанию (если селект «Формат вставки» пуст).
Проверено: verify-doc-builder 77/0 (юнит-рендер периода, публикация суффиксных чипов, снимок объектом, санитайзер режет мусор, ФИО с отчеством) + verify-documents/requisites ALL PASS + браузер полным путём (поле из панели, чипы в тексте, превью-PDF, подача с календарями, карточка).

3. **Панель конструктора — ВКЛАДКАМИ** «Данные · Форма · Блоки» (`panelTab`, кит `Tabs`, sticky к верху панели). Причина: три секции подряд + 30 чипов данных = «Форма подачи» и «Блоки» ниже сгиба, пользователь решил, что их нет вовсе («у меня старая версия»). Ловушки: у `.db-panel-tabs`/`.db-panel-section` обязателен `flex: 0 0 auto` — в flex-колонке с overflow переключатель сжался до 5px (визуально «вкладок нет»); иконки у вкладок убраны — при ширине панели 300px третья обрезалась.

4. **Поля у СВОБОДНОГО документа** (`OrgDocument.formFields`, миграция `free_doc_form_fields`): пользователь на `/edit` увидел «У этого документа нет полей подачи» и спросил, где кнопка. Модель: форма документа ПО ШАБЛОНУ принадлежит шаблону (PATCH formFields → 400 «заданы шаблоном»), у свободного — своя, на самом документе; `sanitizeFields(raw, templateId, ownFormFields)`; новое объявление ПЕРЕСЕИВАЕТ значения (снятое поле не оставляет висячего значения); `OrgDocumentDto.formFields` = шаблонная ∥ своя; конструктор получает `onAddFormField` только для документов без шаблона + `formHint` под три случая. **Найденный при проверке баг:** карточка и вкладка «Форма» судили о наличии полей ПО ЗНАЧЕНИЯМ — только что заведённое поле «не существовало», заполнить его было негде; теперь обе смотрят на объявление, а режим просмотра рисует подписи полей и прочерк у незаполненных.
