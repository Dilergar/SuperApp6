# Gap-анализ SuperApp6 v2 (2026-07-31)

Полный документ — **`GAP-ANALYSIS-v2.md` в корне репо** (пользователь читает сам и двигается по чек-боксам). Заменяет анализ 2026-07-18. Факты перепроверены разведкой по коду (18 пунктов); спорные развилки сняты гриллом.

core/jobs · core/verify (SMS-OTP + сброс пароля) · core/docs · helmet/fail-closed. SMS-канал есть, но только OTP (не уведомления).

## Главная стройка — документная вертикаль (порядок строгий; решения грилла)
1. **Диск** (Google Drive-аналог B2C+B2B; v1 ПОЛНЫЙ: папки Folder + core/access тип `folder` с наследованием parent, корзина, поиск-провайдер, фото-сетка) + **core/share-links** (общий движок гостевых ссылок: токен → гостевая СТРАНИЦА, срок+отзыв; v1 БЕЗ SMS-гейта)
2. **Шаблоны документов** — СВОЙ конструктор (блоки → PDF; НЕ DOCX-плейсхолдеры как основной путь — решение пользователя) + второй путь «загруженный DOCX с {{полями}}» (docxtemplater-класс); реестр источников данных user/workspace/staff/contact (паттерн calendar-layers)
3. **core/sign** — реестр методов подписи, v1 ВСЕ ТРИ: QR-ЭЦП eGov mobile + NCALayer + SMS-ПЭП (через core/verify); слот «биометрия». Заготовки в схеме: DocumentVersion.signed, reason='pre_sign'. ПЕРЕД стройкой — ресёрч: SIGEX vs НУЦ напрямую, юр. рамка ПЭП РК, хранение подписей (CMS/CAdES)
4. **ЭДО** — «Конверт»: документы + СВОЙ ЛЁГКИЙ линейный маршрут (согласует/подписывает, последовательно/параллельно; НЕ на Процессах — two-tier как канбан, нода «Отправить на подпись» позже) + требование метода per-подписант; внешний подписант по номеру = share-link + SMS-гейт (появляется здесь) + конверсия гостя; chatter-аудит, rich card, итоговый PDF со штампами в Диск обеих сторон
5. **КЭДО** — полный контур: кадровые шаблоны (приказ/заявление/договор из Staff-данных) + массовая рассылка по осям отдел/должность/филиал (проекции core/access готовы) + ознакомления под подпись + личный архив «Мои документы» у сотрудника (переживает увольнение — суперсила одного user_id vs Doodocs)

Вертикаль разблокирует: Счета → ЭСФ (нужна ЭЦП) → договоры CRM → подпись протоколов Диктофона.

## Малые проекты (нужны ВСЕ 4, от простого к сложному)
Заметки → Импорт Kaspi-выписки (первый потребитель импорт-движка) → Push (DeviceToken+FCM/Expo; до mobile) → Счета (после шага 2 вертикали).

## Биометрия (решение грилла)
Записана как будущий движок «подпись/ознакомление отпечатком/лицом с телефона или сканера/камеры ПК». Путь — WebAuthn/passkeys (устройство само сканирует; бонус 2FA+вход) vs своё распознавание лица (KYC-класс, биометрические ПД ЗоПД) — решается при стройке движка. KYC (селфи+liveness как Kaspi) — ОТДЕЛЬНЫЙ второй движок, к Jobs Marketplace/деньгам.

## Ключевые хронологические зависимости
Диск → шаблоны → ЭДО; подпись → ЭДО/ЭСФ/КЭДО; ЭДО → КЭДО → полный цикл «отпуска» HR; канбан → CRM; кастомные поля = с CRM; push+api-client+OTP-экран → до mobile; платёжный рельс → до биллинга/оплаты счетов; админка+согласия+движок ключей+прод-минимум → до публичного запуска; i18n — чем раньше тем дешевле.
