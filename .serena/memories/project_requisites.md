# Реквизиты (организация + человек + карты) — 2026-08-02

Фундамент документной вертикали (шаблоны → счета → ЭДО → КЭДО): данные вводятся ОДИН раз в своих анкетах, потребители читают оттуда. verify-requisites.cjs 32/0 + регрессии staff/b2b-wallet/workspace-restore/wallet/circle-review/files-consumers + браузер.

## Модель
- **WorkspaceRequisites** (1:1 при Workspace): orgForm (ип/тоо/ао/кх/пк/учреждение/филиал/other), taxRegime (general/simplified/retail/patent/snr_kh/astana_hub/other), legalName («Workspace.name — бренд, в договор идёт юрформа»), bin, legalAddress, kbe, vatPayer+свидетельство, directorUserId (**из сотрудников, валидация членством; FK нет намеренно** — увольнение не рвёт реквизиты, подписант сверяется на выдаче документа), signBasis.
- **WorkspaceBankAccount** — счета СПИСКОМ с основным (модель 1С/Odoo): первый — основной сам; переключение = tx «снять со всех → поставить одному»; удаление основного передаёт роль старейшему. Partial-unique НЕ делали: короткое окно двух основных ничего не ломает.
- **User**: iin, residentialAddress, idDocNumber/idDocIssuedBy/idDocIssuedAt. ДР в анкете — ТРИ поля (день / месяц НАЗВАНИЕМ / год; MONTH_NAMES_RU).
- **UserPaymentCard** («Кошелёк»): несколько карт с основной, panEncrypted+ibanEncrypted (AES-256-GCM через `shared/crypto/secret-field.ts` — обобщение process-crypto: контекст-строка на класс полей), panLast4 для масок, БЕЗ CVV (карта = реквизит «куда переводить»). Владельцу номер полностью (маска бесполезна — не проверить и не продиктовать).

## Двухуровневая «Видимость в Компаниях» (решение продукта, грилл)
1. **Коллегам** — тумблеры как раньше + реквизитные в мешке `extras` карты видимости (REQUISITE_VISIBILITY_EXTRAS: iin/residentialAddress/idDocument/paymentCard). Мешок extras и был заведён «под будущие поля» — отсутствующий ключ = false, т.е. дефолт «скрыто» без миграций карт.
2. **Управляющим (manager+) — нередактируемый уровень**: ИИН, ДР, адрес, удостоверение, ОСНОВНАЯ карта видны ВСЕГДА (комплект договоров/трудоустройства/выплат). В настройках анкеты показан замкнутым информ-блоком.
- В ЛИЧНОМ окружении (Группы) реквизиты не показываются вовсе.
- Ростер: `member.requisites` (manager+ всегда, коллегам по тумблерам); карты батчем `PaymentCardsService.primaryCardsFor` — расшифровка не расползается за сервис карт. Новое ребро: WorkspacesModule → WalletModule (PaymentCardsService).
- Видимость реквизитов ОРГАНИЗАЦИИ сотрудникам — first-class флаг `WorkspaceCardVisibility.requisites`, по умолчанию ДА (печатаются на каждом счёте); GET отвечает data:null при выключенном.

## Валидации (shared/utils/requisites.ts — чистые функции, те же в Zod и в веб-подсказках)
- ИИН/БИН: 12 цифр, два прохода весов mod 11 (s==10 → второй проход; снова 10 → номер не существует).
- IBAN KZ: KZ + 2 контрольные + 16 знаков, ISO 13616 mod 97 == 1 (mod кусками по 7 цифр без BigInt).
- БИК 8 знаков SWIFT-формата; КБе 2 цифры; карта — Луна 13–19 цифр; срок ММ/ГГ не в прошлом.
