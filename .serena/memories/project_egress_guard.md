# Страж исходящих запросов (2026-08-30, + ревью того же дня)

Закрыт последний пункт security-ревью 2026-07-25: «запретить прямой `fetch` линтером — иначе
следующая интеграция снова пройдёт мимо `safeFetch`». В бэклоге числился как «Egress-шлюз» среди
движков — **движком не является**: своей модели, таблиц и API нет. Это правило + механическая
проверка его соблюдения (третий эшелон, как ESLint-страж границы API↔клиенты в вебе).

## Несущее решение: дверей ДВЕ, не одна

Премиса «заставить всех звать `safeFetch`» ОШИБОЧНА. `safeFetch` по построению **запрещает
приватные адреса**, а все сидекары платформы именно приватны:

| сидекар | адрес |
|---|---|
| редактор документов (Collabora) | `DOCS_EDITOR_URL` = `localhost:9980` |
| Gotenberg (PDF) | `GOTENBERG_URL` = `localhost:3030` |
| верификатор ЭЦП (NCANode) | `NCANODE_URL` = `localhost:14579` |
| STT (whisper) | `VOICE_STT_URL` = `localhost:9000` |
| WOPI-обращение редактора к нам | `DOCS_WOPI_PUBLIC_URL` = `host.docker.internal:3001` |

Прогон их через щит сломал бы самохостовую сборку целиком.

**Дверь №1 `safeFetch`/`fetchJson`** — адрес пришёл ИЗ ДАННЫХ (конфиг ноды Процессов, настройка
организации, ввод человека). SSRF-щит: числовой разбор IP во всех формах, DNS-резолв КАЖДОГО хопа,
ручные редиректы, срезание `authorization`/`cookie`/`x-api-key` при кросс-хост редиректе.

**Дверь №2 `trustedFetch(url, init, {timeoutMs, origin})`** — адрес пришёл ИЗ .env, то есть его
выбрал ОПЕРАТОР при установке, а не пользователь запросом. Щита нет НАМЕРЕННО. Взамен: вызов
ЗАЯВЛЕН доверенным (`origin: 'env' | 'self'`), таймаут обязателен по сигнатуре (забытый таймаут к
упавшему сидекару держит слот джоба до конца аренды и выглядит как «очередь встала»), одна точка под
будущие ретраи/метрики. Поведение = голый `fetch` + `AbortSignal.timeout`.

**Правило выбора одной фразой: кто выбрал строку-адрес — оператор или пользователь?**

## ⚠️ assertPublicUrlShallow — НЕ дверь и не защита

Переименована из `assertPublicUrl` по итогу ревью. Она НЕ резолвит имя хоста: домен с A-записью на
`169.254.169.254` проходит её насквозь (`literalHostIsPrivate` для имени возвращает null). Это ровно
та неполнота, из-за которой случился SSRF 2026-07-25. Законное применение одно — дешёвый
предварительный отказ ПЕРЕД `safeFetch` (чтобы человеку, вписавшему `http://localhost` в конфиг
ноды, ответить сразу). **Связка «проверил ею + `trustedFetch`» = SSRF, а не защита**: у `trustedFetch`
щита нет по определению. Имя функции теперь говорит это в каждой точке вызова; предупреждение стоит
и в доккомментарии, и в шапке барреля.

## Переезд

`safeFetch` / `assertPublicUrlShallow` / `fetchJson` (≈200 строк) вынесены из
`modules/processes/process-service-nodes.ts` → **`shared/http/`** (`safe-fetch.ts`,
`trusted-fetch.ts`, `index.ts`). Причина: двери зовут движки `core/*`, а движок не имеет права
зависеть от фичи (принцип реестров). В Процессах остался реэкспорт — соседям по модулю путь импорта
не менялся. Переезд сверен с `git show HEAD:` — байт-в-байт.

Переведены 8 мест: 6 env-клиентов (`docs-editor.client`, `sign-qr.driver`, `sign-verifier.driver`,
`pdf-render.service`, `verify.sms`, `voice-stt.client`) + `documents.builderLogo`
(самообращение по `API_PUBLIC_URL` → `origin: 'self'`; там была РУЧНАЯ копия правила).

## Конфиг `apps/api/eslint.config.mjs`

Три правила, список запрещённых модулей объявлен ОДИН раз (`BANNED_MODULES`):

- `no-restricted-globals: fetch` — вызов и передача по ссылке (`const f = fetch`).
- `no-restricted-imports` — статический ESM-import `axios`/`undici`/`node-fetch`/`got`/`superagent`/
  `request`/`http`/`https`/`node:http`/`node:https`.
- **`no-restricted-syntax`, ПЯТЬ селекторов под value-позиции, которых первые два правила НЕ видят**
  (каждый найден пробой, ни один — рассуждением):
  1. `globalThis.fetch` / `global.fetch` — `no-restricted-globals` работает по ссылкам на глобальное
     ИМЯ и обращение к свойству объекта не видит;
  2. `globalThis['fetch']` — вычисляемое свойство;
  3. `const { fetch } = globalThis` — ObjectPattern, а не MemberExpression;
  4. **`require('node:https')`** — `no-restricted-imports` не покрывает CommonJS вовсе, а `require()`
     в apps/api ЖИВАЯ идиома (sharp, exif-reader, thumbhash, ffmpeg-static), то есть обход был бы
     естественным повторением местного стиля;
  5. **`await import('axios')`** — динамический импорт тем правилом тоже не покрыт.

**Исключений по ФАЙЛАМ нет** (в отличие от веб-конфига): законных `fetch` ровно два, по одному внутри
каждой двери, разрешены директивами на КОНКРЕТНОЙ строке → второй голый `fetch` в том же файле всё
равно упрётся в правило. В `src/shared/http/**` включён `reportUnusedDisableDirectives: 'error'` —
протухшая директива роняет линтер. Глобально она ВЫКЛЮЧЕНА, а плагин `@typescript-eslint` подключён
с выключенными правилами: в API живут декоративные `eslint-disable` из эпохи без ESLint, а ESLint 9
считает ошибкой директиву к неизвестному правилу.

Правило НЕ трогает вендорские SDK с фиксированной точкой назначения (googleapis, `@aws-sdk/client-s3`,
`livekit-server-sdk`, ioredis, prisma).

## Запуск

- **`pnpm lint:guard` из КОРНЯ** — задача `lint:guard` в turbo.json, гоняет ОБА стража (исходящих в
  API и границы в вебе), ~7с. Оставлять стража достижимым только длинной `--filter`-командой было
  нельзя: что не запускается привычной командой, то не запускается вообще.
- Шаг CI «Lint API (страж исходящих)» рядом со стражем веба.
- Сборку API проверять только `npx nest build`, НЕ полным tsc.
- **Остаточная мина (не чинилась — действовала договорённость «`lint` не трогать»):** `pnpm lint` в
  корне по-прежнему падает по памяти на `tsc --noEmit` у apps/api.

## Урок методики

Зелёный прогон линтера ничего не доказывает — он одинаково зелен и когда правило работает, и когда
селектор промахнулся. Здесь приём «подсадить нарушение → увидеть падение → убрать» сработал ДВАЖДЫ:
при стройке он поймал пропуск `globalThis.fetch`, а ревью тем же приёмом нашло ещё четыре дыры
(`require`, динамический `import`, деструктуризация, computed-доступ). **Ни одна из пяти не была
найдена чтением конфига.** Итоговая проба — 11 классов нарушений, ловятся все.

Проверено: `nest build` зелёный, `pnpm lint:guard` чист, `web tsc` чист, `pnpm install
--frozen-lockfile` (как в CI) проходит, сьюты docs / doc-builder / templates / documents / sign /
otp / voice / processes зелёные на ЖИВЫХ сидекарах (Collabora, Gotenberg, whisper в docker).
SSRF-поведение подтверждено не только текстуально: тесты A12 в `verify-processes` (блокировка
`169.254.169.254` и decimal-loopback `2130706433`) проходят через переехавший `safeFetch`.

Связано: `mem:project_security_review_2026_07` (откуда задача), `mem:project_contract_boundary_review`
(тот же приём — механический страж вместо договорённости).
