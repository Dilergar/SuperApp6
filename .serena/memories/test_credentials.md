## Почему разделены (2026-07-26)

Сьют по природе стирает состояние между прогонами, и на ОБЩИХ аккаунтах это уносило живые данные человека:
- `verify-files.cjs` начинался с `fileObject.deleteMany({ uploaderId })` → каждый прогон сносил ВСЕ файлы: аватарки, вложения задач и чатов, фото лотов (`FileLink` каскадится за `FileObject`, вложение исчезало из задачи молча). Это и была причина жалобы «загруженные файлы пропадают».
- `verify-cardskins.cjs` — `cardSkinInstance.deleteMany({ ownerId })` + сброс `defaultSkinInstanceId`/`premiumUntil`: стирал купленные скины (тест по смыслу требует «скин ещё не куплен» — на выделенном аккаунте это безвредно).

**Правило:** чистка по `userId`/`uploaderId`/`ownerId` в verify-скриптах запрещена и на выделенных аккаунтах. Базовая линия + проверки на дельту, свои id в наборе, уборка только их и штатным API (`DELETE /files/:id`, не сырой `deleteMany`: иначе квота раздута, а байты виснут на диске). См. CLAUDE.md, п.7 плейбука.

## Уборка накопленного мусора

- `scripts/gc-test-workspaces.cjs` — организации от скриптов/демо + их задачи, чаты, хроника, процессы, tuples, роли. **Ловушка: `tasks.workspace_id` = SET NULL** — голое удаление организации превращает её задачи в ЛИЧНЫЕ задачи человека. Кошелёк/магазины/книги финансов организации НЕ трогает (журнал двойной записи неизменяем, Σ=0).
- `scripts/gc-orphan-bytes.cjs` — байты в `storage/` без строки в БД (след прямых `deleteMany` мимо движка); пропускает файлы моложе 24ч, чтобы не убить идущую загрузку.

Оба по умолчанию сухие, удаляют по `--apply`.
