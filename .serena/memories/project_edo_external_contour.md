## Доводка по построчной сверке с планом (2026-08-17, все сьюты зелёные)

1. **send-external перепроверяет архивность КОНТРАГЕНТА** (`assertUsable` теперь и на отправке, не только create/PATCH): черновики архив справочника не блокируют, и между созданием и отправкой карточка могла уехать в архив. Класс «проверка есть на create, но нет на одном из путей».
2. **`/documents/upload` гейтит профиль файла**: только `profile='document'` (потолок 50 МБ = расчётный размер заморозки sign и джоба штампа); прежний осознанный «профиль любой» переигран по плану.
3. **SMS-бюджет организации тратится по ФАКТУ отправки** (правило бюджета verify): `slidingPeek` до отправки (без инкремента), `slidingRecord` после успеха; предел проверяется ДО кулдауна (иначе отказ «предел исчерпан» занимал кулдаун и повтор врал «уже отправлена»).
4. **Возврат после отказа контрагента — свой ключ хроники** `org_document.external_returned` (был переиспользован `withdrawn`).
5. **Профильные сьюты знают новые механизмы движков** (уроки «покрытие уехало в verify-edo»): verify-sign часть 3б (стопка источника sign, dev/cancel → cancelRequest, suppressOutcomeNotify A/B-паттерном «громкая ограничивает ожидание тихой», штамп на PDF-предмете дев-полигона + matchedBy на /check), verify-documents смоук external (вид/upload/submit-400/assign-number), verify-share-links (actionUrl-фолбэк `/profile/links` без describeRef.href). Дев-полигоны расширены: `signDevRequestSchema` += `pdf`/`suppressOutcomeNotify`, ручки `/sign/dev/cancel|state` (state отдаёт stampedSha256 — наружу он больше нигде не раздаётся), `/documents/dev/:id/state` (узлы Диска подшивки — прямая проверка узла, не только хроники).
6. **verify-edo достроен**: документ ИЗ docx-шаблона с тегами `{Контрагент.*}` сквозняком (сборка + unzip document.xml: БИН и подписант на месте, тегов не осталось), прямое чтение узла реестра Диска по registryNodeId, отправка архивному контрагенту → 400, файл чужого профиля → 400.

## Ключевые решения
- ЭДО = РАСШИРЕНИЕ modules/documents (UI: «Документооборот»), НЕ отдельный «Конверт». Категория вида `external` («С контрагентами»), статусы `sent`/`declined_external`. Маршрутов Процессов у external НЕТ в v1: submit → 400, публикация процесса с trigger.document на external-шаблон — error валидации, смена категории вида при живых документах запрещена.
- «Контрагенты» — отдельный сервис-справочник (modules/counterparties): Counterparty (bin = БИН юрлица / ИИН ИП+физлица, партиальный уникум (workspace_id,bin) СРЕДИ ЖИВЫХ — архив отпускает номер) + CounterpartyContact (архив вместо удаления: на него ссылаются документы без FK) + CounterpartyBankAccount (список с основным). Гейт РОЛЬЮ (trainee+/manager+), в core/access НЕ заведён. Группа полей «Контрагент» (~17 полей, включая «БИН-ИИН» для графы Р-1 и «Подписант…» из контакта) — fail-closed по workspaceId.
- Номер печатается в тексте ДО отправки: POST /:id/assign-number (тот же счётчик DocTypeCounter; отправка без номера — предупреждение, не блок). У uploaded-доков номер живёт только в карточке (пересобирать нечего).
- Третий путь создания: POST /documents/upload (PDF → pdfFileId=fileId сразу; DOCX → оживление core/docs + rendition). «Один файл — одна карточка».

## Расширения движков (переиспользуемые)

- core/sign: `cancelRequest(actorId, requestId)` (сервисный; порядок замков как у крона: акты→заявка), хук `SignRegistry.onRequestExpired` (джоб SIGN_EXPIRED_JOB ставится В ТРАНЗАКЦИИ крона истечения), `checkGuestCert(refId,{iin,bin})` → sign_counterparty_mismatch (акт НЕ хоронится), событие протокола 'cancelled'.
- core/sign ШТАМП: SignStampService + джоб sign.stamp (СВОЯ очередь sign_stamp cap 2, ставится в finalizeSigned при completed): pdf-lib + @pdf-lib/fontkit + PT Serif из infra/pdf-fonts (кириллица; fontkit через `(ns as any).default ?? ns`), полоса в нижнем поле каждой страницы + «Лист подписей» с QR на /check/<actId>?k=. Профиль sign_stamped НЕ evidence (перегенерируем). Клейм stampedFileId под гвардом, проигравший systemDeleteFile своего файла. /sign/check ищет и по stampedSha256 → matchedBy:'stamped_copy'. - core/sign: SignInboxProvider → ApprovalsRegistry.registerSource('sign') — свободные (approvalStepId IS NULL) pending-акты в стопке «Ждут решения», actions:[] (подпись = модалка), href signRequestHref.
- core/sign: SignGuestController GET /sign/guest/package?session=&kind=stamped|zip (@Public, throttle 5/мин, пропуск ПАРАМЕТРОМ; allowDownload не действует — копия подписанта = закон).

## Единый источник «Вида» + обратимый архив (2026-08-18, по замечаниям пользователя)
- **Дрейф, который заметил пользователь:** фильтр списка контрагентов остался на `COUNTERPARTY_KINDS` (3 широких вида), а форма ушла на `COUNTERPARTY_FORM_OPTIONS` (11 орг-форм) — две подписи «Вид» с разными списками. Починка: список фильтрует ТЕМ ЖЕ набором через общий `counterpartyFormQuery(value) → {orgForm} | {kind}` в shared (у видов без орг-формы — физлицо — фильтр по kind); `listCounterpartiesSchema` += `orgForm`. `COUNTERPARTY_KINDS` остаётся ВНУТРЕННЕЙ моделью (что лежит в bin, с чем сверяется ЭЦП), в UI как «Вид» больше не показывается.
- **Архив был односторонним** (DELETE ставил archivedAt, вернуть нечем, посмотреть негде — хотя `?archived=true` в API уже работал). Добавлен `restore()` + `POST /:counterpartyId/restore` (manager+): перепроверяет потолок справочника и БИН среди ЖИВЫХ (партиальный уникум → P2002 → 409 «номер занят»), гвард `archivedAt: {not:null}`, хроника `counterparty.restored`. Веб: чип-переключатель «В архиве» в ряду фильтров, свой EmptyState архива, кнопка «Вернуть из архива» (matte tone=success) на карточке вместо «Править»/«В архив».
- Форма: «Основание подписи» — номер отдельным полем + дата календарём (склейка «Приказа № 12-к от 15.08.2026», обратный разбор `parseSignBasis`; неразбираемая старая строка целиком уезжает в «Свой вариант», а не мнётся). Вид написан ПЕРЕД полем юрнаименования (как БИН/ИИН меняется от вида).
- Polish (скилл impeccable): карточка контрагента — ОДНА BentoGrid на все секции (три подряд слипались, у сеток нет внешних отступов); мёртвый класс `.ui-row` определён в ките (радиус 12px, рамка, ховер) — до этого ряды рисовались inline с несуществующей `--radius-item` и были квадратными; вкладки сервисов вертикали переведены с `Tabs` на `SegmentedControl` (пилюли — «как везде»); `.ui-segment` получил внутренний скролл (7 разделов распирали телефон), ряды списков — `flexWrap`.
