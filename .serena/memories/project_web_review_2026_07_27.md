# Ревью веб-части целиком + 6 фиксов (2026-07-27)

Ревью всех 186 файлов `apps/web` (40k строк): статика + прогон живьём под двумя
аккаунтами. web tsc чист, 22 маршрута отдают 200/404, консоль пуста в ЧИСТОЙ вкладке.
**НЕ закоммичено** (пользователь коммитит сам).

## Что подтвердилось здоровым (не трогать, это фундамент)
- Путей XSS нет: `dangerouslySetInnerHTML` и `eval` не используются вовсе.
- У КАЖДОГО `addEventListener` есть парное `removeEventListener` (проверено скриптом,
  сверяющим счётчики по файлам) — утечек слушателей нет.
- Пустых `catch {}` нет ни одного.
- `Modal`/`usePopover`: честные `role="dialog"`, `aria-modal`, Esc, ловушка фокуса,
  возврат фокуса на источник, портал, переворот при нехватке места.
- `Conversation.tsx` — скролл, гонки поиска и pending-jump сделаны всерьёз.
- Гейты прав деградируют мягко («Журнал доступен с роли Менеджер»), несуществующая
  сущность даёт «Задача не найдена», а не пустоту.
- Кит внедрён широко: 100 `<Input>`, 44 `<Select>`, 38 `<Field>`.

## 6 закрытых находок
1. **Организации не доезжали до переключателя до F5.** `WorkspacesPanel` держал свой
   axios-запрос мимо кэша, `['workspaces']` не инвалидировался НИГДЕ в кодовой базе,
   а обозреватель `AppShell` смонтирован постоянно (`refetchOnWindowFocus:false`) и
   сам не перезапрашивает. Ключи переехали в `lib/queries.ts` (`workspacesKey`,
   `workspacesArchivedKey`, `workspacesIncomingInvitationsKey`), панель — на React Query.
2. **Выход не чистил кэши** → `lib/session-reset.ts` (детали в памяти `web_auth_pattern`).
   Механизм доказан кодом; видимый симптом на tester1/tester2 НЕ воспроизводился —
   у обеих учёток одни и те же организации, данные неразличимы. Так и записано.
3. **`hydrate()` уничтожал refresh-токен на любом сбое** → только 401/403.
4. **Поля без подписей**: на `/profile/form` 13 из 13 без доступного имени (замер в
   браузере через вычисление accessible name). ~32 поля в 7 файлах переведены на кит.
   `SearchField` получил дефолтный `aria-label` в САМОМ ките — топбар-поиск висит на
   каждой странице, одна правка чинит все.
5. **30 нативных `alert`/`confirm`** → `useConfirm()` + `lib/toast.tsx`
   (подробности и мотивация — в памяти `ui_kit`, раздел «Запрещено»).
6. **404 был английской страницей Next**, маршрутных `error.tsx` не было вовсе →
   `app/not-found.tsx` + `app/error.tsx`, обе внутри каркаса.

## ⚠️ Главная ловушка (стоила отдельного расследования)
**Корневой `app/loading.tsx` вешает страницу 404 на ВЕЧНЫЙ спиннер.**
Симптом коварный: `curl` получает правильный HTML с текстом 404, сервер отдаёт всё,
`readyState: complete`, в консоли НОЛЬ ошибок — а в DOM висит фолбэк и
`<template id="B:0">` (незакрытая граница стриминга). Проверено экспериментом:
убираешь `loading.tsx` — 404 рисуется, возвращаешь — снова спиннер.

Удалять `loading.tsx` нельзя: без него клик по навигации МОЛЧИТ до полного ответа
(корневой layout динамический — читает cookie сайдбара). Решение: граница опущена на
уровень сервисов — 12 однострочных `<сервис>/loading.tsx` реэкспортят общий
`components/shell/RouteLoading.tsx`. 404 и `error.tsx` остались снаружи Suspense.
**Новый сервис = +1 такой файл.**

## Методические уроки (пригодятся в следующем ревью)
- **Проверять гипотезы, а не докладывать их.** Три «находки» оказались ложными:
  дубли запросов в сети = двойной вызов эффектов StrictMode (в Next 15 включён по
  умолчанию); «мёртвые» классы `reset-error`/`otp-alert` висят на ките `Alert` и
  ничего не ломают; безымянные ссылки сайдбара в рейле берут имя из `title`.
- Автопроверка классов CSS (скрипт: собрать `className` из tsx, сверить с
  определениями в css) даёт мало — Tailwind-утилиты генерируются на лету и шумят.
- Замер a11y надёжнее делать в браузере вычислением accessible name
  (aria-label → aria-labelledby → label[for] → предок-label → title), чем чтением кода.
- Буфер консоли живёт НА ВКЛАДКУ: ошибка падения дев-сервера всплыла спустя полчаса
  и выглядела как свежая. Проверять в новой вкладке.
- Дев-сервер веба падал сам по себе в процессе работы (порт 3000 освобождался,
  API жил) — при странных `000` от curl первым делом смотреть, жив ли процесс.
