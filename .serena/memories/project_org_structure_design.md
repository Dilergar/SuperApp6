# Орг. структура (B2B) — история дизайн-решений (грилл 2026-09-03)

Канон архитектуры — `docs/org_structure.md`, `docs/org_structure_web.md`, `docs/audiences_engine.md` (здесь только ПОЧЕМУ так).

## Принятые развилки
- **Должность, не человек** — SAP SuccessFactors (иерархия позиций переживает текучку); Odoo `employee.parent_id` отвергнут: вертикаль рвётся при увольнении.
- **Вертикаль**: голова отдела → вверх по дереву; **объект = отдел по умолчанию** для должностей без отдела (малый бизнес без отделов получает вертикаль без фиктивных сущностей); точечное `reportsToPositionId` сильнее всего. Голова лежит НА ОТДЕЛЕ (CFO ведёт «Финансовый», сидя вне отдела) — поэтому поле на отделе, а не флаг на должности; одна должность вправе вести несколько отделов.
- **Объект обязателен** (StaffBranch.isDefault — основной, заводится с организацией); руководитель объекта в v1 той же моделью; объект может стать своим ТОО — реквизиты придут с сервисом «Объекты».
- **Замещение**: standing (без дат) = запасной только когда некому; temporary (с датами) = вместо на период; датированное сильнее. Инвариант: RelationTuple хранит только независимые от времени факты — замещения НЕ проецируются (иначе датированное пережило бы отпуск).
- **Корень без руководителя → владелец** (снимок согласования не пуст, инвариант движка цел; подпись в assigneeLabel).
- **Области** добавляют права, Менеджер полновластен (`STAFF_FULL_SCOPE_ROLES`), сужение — с ролью «Кадры» (Bitrix24: руководитель правит свою ветку, видит всё).
- **Приказа на структуру нет** — след в журнале организации.
- **Код внутри modules/staff** (один агрегат, DI_TOKENS.StaffService уже был, ноль новых рёбер); отдельного движка графа нет; `core/access` расширен (head/manager + лестницы), новый `core/audiences` — 16-й движок.
- **Не переиспользуем модуль Процессов** для канваса: там документ-канвас — источник правды и компилируется, здесь правда — справочники; версий/публикации нет; порты по роли данных; сотни нод с фокусом; области вместо manager+. Библиотека @xyflow/react и визуальный язык — общие (`components/canvas/`).
- **Канвас — витрина**: координаты не хранятся (детерминированная раскладка без dagre/elkjs), узел = должность, отдел = рамка ≤2 уровней, сплошная/пунктир, переключатель видов вместо «всех стрелок сразу» (приём реестра слоёв календаря); фильтр «Объект» для сети; вакансия = пунктир + «Нанять».
- **Типовая схема без объекта считает голову ОСНОВНОГО объекта** (решение по ходу стройки): иначе каждая должность без отдела была корнем — сеть точек рисуется одной схемой «CEO → Управляющий → Продавец».
- **Библиотека бланков**: заявления согласует `subject_manager` (руководитель стороны документа); подписант приказов — как спросил мастер.
- **Директор реквизитов ≠ CEO**: мастер предлагает директора как вершину, шаблоны берут «Организация.Директор» из реквизитов.

## Вне скоупа (решения пользователя, чтобы не всплывало)
ЗП и график → Штатное расписание по объекту; конструктор доступов/видимости; реквизиты на объект → сервис «Объекты»; матрица, проектные команды, табель, роль «Кадры», онбординг-шаблоны структур; переброс уже созданных заявок на заместителя (снимки неприкосновенны).

## Ловушки стройки (выучены)
- Сьюты берут «сегодня» через Intl с Asia/Almaty (сервер считает в APP_TIMEZONE; UTC после 19:00 отстаёт на день).
- `grantSetFor` без workspaceId — область пересекать со справочниками своей организации.
- `applyStaffDiff` без сужения по отношению стирал бы чужие рёбра (department#manager) на каждой мутации.
- Bash heredoc с большим JS ломается на кавычках — скрипт в файл scratchpad + `node file`.
