# Контракт API ↔ клиенты — слабейшее место (ревью 2026-08-07) и ЧЕМ ОНО ЗАКРЫТО

## Что было

HTTP-граница API↔клиенты — единственный стык системы без автоматического стража (внутри API — TypeScript, в БД — Prisma, через провод — `any`). `@superapp/shared` был подключён как «библиотека утверждений», а не проверяемый договор.

Цифры ревью: веб — 423 вызова `api.*` / 0 с генериком, 218 `res.data.data`, ~45 локальных серверных типов; API — 0 аннотаций ответов; shared — **77 РЕАЛЬНО мёртвых** типов (не 133: 49 живут через композицию) + **114 «однокрылых»** (стоят только на одной стороне — опаснее мёртвых: одна сторона на них опирается, вторая живёт своей формой).

**Археология по всем 55 коммитам опровергла гипотезу «мёртвое было живым»:** ни один из 77 типов НИКОГДА не был импортирован из `apps/`. Они рождались в том же коммите, что и фича, «ритуалом описания контракта», а реализация сразу шла мимо: на API вход описывали Zod-схемы, на вебе ответ читался как `res.data.data`. У 64 из 66 проверенных `git log -S` даёт `touched=1` — тип добавлен одним коммитом и больше не правился. Редизайн Organic Bento и переписывание мессенджера ни при чём.

**Системная причина 8 из 10 локальных типов веба — одна:** контроллер разбирал страницу сервиса `{items, nextCursor}` на `data` + соседнее поле, клиент собирал её обратно своим типом. Так родились `ContactsPage`, `TasksPage`, `InboxPage`, `ApprovalMinePage`, `ShareLinksPageResult` и «web-only» `DriveListPageDto`.

## Чем закрыто (2026-08-07) — ТРИ ЭШЕЛОНА

1. **Компилятор.** `packages/api-client` — транспорт (axios, токен, single-flight ротация refresh, 401, хелперы `apiGet<T>`…); веб и mobile = адаптеры ~30 строк. Типы страниц `CursorPage<T>`/`OffsetPage<T>` + конверт `ApiOk`/`ApiError` в `common.ts`. **Вариант A на 14 ручках**: страница едет в `data` цельной. Входные типы — только `z.infer` из `validation/*` (41 рукописный дубль снесён). WS-типы мессенджера сведены в shared и стоят на gateway И на хуке.
2. **Линтер.** `apps/web/eslint.config.mjs` (eslint 9 flat, ТОЛЬКО правила границы: `api.*` вне адаптера, `.data.data` — включая маскировку деструктуризацией `const { data } = …; data.data` (отдельный селектор `[object.name='data']`), нативные `confirm`/`alert`; все `error`). 423 голых вызова и 218 `res.data.data` мигрированы до нуля. С 2026-08-08 это и есть локальный `pnpm lint` веба (`"lint": "eslint src"`), в CI — отдельный шаг. Точечный override один — `lib/public-api.ts` (гостевой клиент без перехватчиков распаковывает конверт сам, в двух типизированных `guestGet/guestPost` с `ApiOk<T>`); прежний override на `lib/api.ts` удалён как протухший (тонкий адаптер инстанс не трогает).
3. **Правила.** CLAUDE.md → «Контракт API ↔ клиенты» + плейбук пп. 3/6/7/8.

## Несущие правила (действуют для КАЖДОГО нового сервиса)

1. Одна форма провода = ОДИН тип в shared, на ОБЕИХ сторонах: `Promise<Dto>` на читающем методе сервиса И на фетчере клиента. Date/BigInt → строка В СЕРВИСЕ.
2. **Страница едет в `data` ЦЕЛЬНОЙ**: `CursorPage<T>`/`OffsetPage<T>`, поле списка всегда `items`. Расплющивать на `data` + `nextCursor`/`meta`/`total`/`actors` запрещено.
3. **Вход не пишется рукой**: `export type XxxInput = z.infer<typeof xxxSchema>` рядом со схемой. Внутренний вызывающий, который строит вход руками, проходит через ТУ ЖЕ схему (`createTaskSchema.parse({…})`) — иначе получит свой набор умолчаний.
4. Локальный `interface` серверного ответа на клиенте запрещён (класс запрета = нативный `confirm()`); узкий срез = `Pick<>`/`Omit<>`.
5. Клиенты ходят в API только хелперами из `@superapp/api-client` через свой адаптер. Запрещено линтером.
6. Тип без обеих сторон мёртв и врёт. WS — тот же закон, и форма enforced **на emit-сайтах** (релей ретранслирует payload как есть).

## Ловушки, найденные ПРОВЕРКОЙ (дороже правил)

- **`tsc --noEmit` на вебе прошёл ЧИСТО сразу после ломающей смены формы 14 ручек.** Клиент читал всё через `as` — компилятор ломающее изменение не увидел вовсе. Это главный аргумент за линтер: пока обходной путь дешевле правильного, типы не защищают ничего.
- **Массовый codemod с «умной» подстановкой типа из объявленного возврата насочинял ЛГУЩИХ аннотаций**: `return res.data.data.moved` схлопывалось в `return apiPost<number>(…)`, где `number` — тип функции, а не полезной нагрузки (`{moved: N}`). tsc такое принимает: тип утверждён вручную. Семь файлов-фетчеров пришлось откатить из индекса (`git checkout-index`) и переписать построчным преобразованием, которое печатает список того, что НЕ смогло. **Вывод: автозамена вправе трогать только формы, где тип выводится однозначно; всё остальное — в список «руками».**
- **Ручкам, отвечающим голым `{success:true}` без `data`, честнее объявить `Promise<void>`**, чем выдумывать тип (`removeMember`, `leaveChat`, `deleteMessage`, `markRead`, `markMentionsRead`, `cancelScheduled` — ни один вызывающий тело не читал).
- **`EventBusService.emit` принимал `Record<string, unknown>`** — под него не подходит НИ ОДИН именованный интерфейс (нет индексной сигнатуры), поэтому продюсеры собирали анонимные литералы: типизации на emit-сайтах не было в принципе. Заменено на `object`.
- **`z.infer` = `z.output`**: поля с `.default()` в нём ОБЯЗАТЕЛЬНЫ. Это сразу вскрыло два внутренних вызывающих (shop → tasks/calendar), собиравших вход руками мимо умолчаний схемы.
- **Prisma-колонки `String` под перечисление** требуют явного каста на границе DTO (`plan as SubscriptionInfo['plan']`, `type as NotificationType`, `chatType as ChatType`) — тот же класс, что `status as WorkspaceInvitationStatus`.
- **verify-сьют — единственное место, где форма провода проверяется по факту.** Он поймал 11 мест, где скрипты читали расплющенную страницу, включая три в «личности гостя», куда браузером не добраться. Ослаблять до `json.data?.items ?? json.data` нельзя: такая «терпимость» пропустит ровно тот дрейф, ради которого сьют и написан.
- **Ревью может пропустить ручку.** Список «11 расплющивающих контроллеров» оказался неполным: `/finance/coins` и `/wallet/history` нашлись только браузером (белый экран на `/finance/coins`) — искать надо grep'ом по `data: items` во ВСЕХ контроллерах, а не по отчёту.

## Живые баги, которые вскрылись, как только включили компилятор

- Пикер «Начислить сотруднику» (`workspaces/[id]/wallet`) подписывал людей **первыми 8 символами UUID с 31.05.2026**: локальный `type Member` обещал `name/firstName/lastName`, которых на ручке нет (имя в `userName`); все три ветки промахивались, все поля optional — сборка чиста.
- Скрепка 📎 в чате показывала **первые 20 задач** (не передавался `limit`, `meta` игнорировалась).
- `CalendarItemRow` гадал `eventId ?? id` и `start ?? startTime` — обе запасные ветки мертвы (полей `id`/`startTime` у события нет).
- Ветка «inline listings» в той же модалке не срабатывала НИ РАЗУ (у `Showcase` нет поля `listings`) — N+1 по витринам был единственным путём, а комментарий описывал поле, которого не было никогда.
- Суммы кошелька форматировались без `scale` в двух местах из трёх (у личных валют он 0 — мина ждала первой валюты со `scale=2`).
- `fetchIncomingInvitations` выбрасывал курсор, который сервер отдавал → второй страницы входящих не существовало.
- Плитка «В окружении» на Главной считала ГРУППЫ (`circlesCount`) вместо людей.
- LinkedIn и WhatsApp были **write-only**: форма спрашивала, сервер хранил, карточка не рисовала.
- `deviceInfo` сессий не писался НИГДЕ — колонка была с первого дня, список устройств навсегда показывал «Неизвестное устройство».

## Доводка 2026-08-08 (перепроверка плана 5 агентами — остатки закрыты)

- **2 выживших каста с ВРУЩИМИ комментариями**: `TriagePanel.tsx` держал `as keyof typeof TASK_STATUS_META` под комментарием «каста больше нет», `SkinsSection.tsx` — `as never` в файле, чей комментарий объявлял его убитым. Урок: комментарий «починено» проверяется грепом по самому файлу, а не верой.
- `drive.listNodes` возвращал безымянный `{items, nextCursor}` при живом `DriveListPageDto` в shared — ровно класс правила №1; аннотирован.
- **2 терпимости `?? json.data` в verify-скриптах** (verify-messenger-calls, verify-otp) — в verify-otp мёртвая ветка была ПРАВИЛЬНОЙ, т.е. скрипт молча прошёл бы расплющивание страницы. Вычищены.
- **`scale` появился в самих DTO лент** (`LedgerEntryDto`, `FinCoinFeedItemDto` + выборка в `getHistory`/`getCoinFeed`): клиент физически не мог форматировать без поля на проводе.
- Страничные DTO выражены через `CursorPage<T>` (алиас — Drive/Share/Office/Mine; `extends` — Chatter/OrgPage с `actors`); union `ApiResponse = ApiOk | ApiError` объявлен.
- Ключи токенов — только константы адаптера (`ACCESS_TOKEN_KEY`/`REFRESH_TOKEN_KEY`): было 3 копии литералов + одна в security-dialogs. `DriveRef`-алиас удалён — 7 файлов Диска на shared `DriveSpaceRef`.
- Входящие приглашения — `useInfiniteQuery` + «Показать ещё» (курсор возвращался, но UI брал одну страницу).
- Mobile: стор переписан на хелперы + shared-типы, `setOnAuthFailure` НАКОНЕЦ вызывается (был объявлен и мёртв); ключи из адаптера.
- **Транспорт впервые под сьютом**: `verify-api-client.cjs` — против живого API доказывает single-flight (ровно 1 ротация на пачку параллельных 401 — счётчик записей хранилища), onAuthFailure с зачисткой токенов, доставку `X-Workspace-Id` (fail-closed 403 на чужой организации) и форму `/wallet/history` (единственная ручка, которую не покрывал никто).
- `getWorkspaceId` на вебе НЕ подключён НАМЕРЕННО (документировано в адаптере): глобальный заголовок из URL включил бы chokepoint на личных запросах со страниц /workspaces/*; веб ставит заголовок пер-запросно, инъекция — для mobile.
- `@superapp/api-client` добавлен в `transpilePackages` веба (паритет с shared).

## Второе слабое место (правило есть, миграция — нет)

Обвязка verify-сьюта: 61 скрипт / 14 584 строки, HTTP-обёртка скопирована 58 раз в 7 вариантах, логин 56 раз в 10; 50 скриптов ходят в БД напрямую (89 `deleteMany`); unit-тестов нет, веб не покрыт ничем кроме tsc+eslint. `_lib.cjs` + правило плейбука п.7 — первый шаг; миграция скриптов — при следующей правке каждого. **Осознанно не мигрировали массово в этой работе**: тесты служили страховкой самих правок, и одновременная правка тестов смешала бы причины падений.
