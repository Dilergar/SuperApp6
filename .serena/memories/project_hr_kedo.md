# КЭДО (modules/hr) — построен 2026-08-24, документная вертикаль ЗАВЕРШЕНА

Шаг 5 вертикали (Диск → шаблоны → sign → ЭДО → **КЭДО**). Весь план из 9 этапов построен за одну волну; после сверки с планом (вторая волна того же дня, см. ниже) verify-hr **81/0** + verify-hr-campaigns **42/0** ALL PASS, регрессии documents/edo зелёные, браузер двумя ролями + 375px.

## Несущие решения
- **Действие первично — документ производен.** `HrAction` (машина draft→in_progress→scheduled→applied/failed/cancelled) порождает приказ (`OrgDocument.hrActionId`); применяет НОДА `hr.apply` на канвасе → джоб `hr.action.apply` В ДАТУ с ПОВТОРНОЙ проверкой законности (ст. 54 → `failed` с причиной, НЕ throw — джоб не ретраит человеческую ошибку).
- **Направление документы↔кадры — ленивый порт `HrPort`** (`DocumentsService.setHrService` на bootstrap, DI_TOKENS.HrService). ЛОВУШКА: порт токена обязан покрывать ВСЕ методы, которые ждут ноды — теперь это сторожит КОМПИЛЯТОР: `HrService implements HrPort, HrNodesPort` (второй порт экспортирован из process-hr-nodes.ts).
- **Личный архив переживает purge**: `PersonalDocRecord` (FK-free снимки) + `FileLink 'personal_doc'` держит FileObject; файл записи = ЗАМОРОЖЕННЫЙ `subjectFileId` заявки подписи (профиль доказательств, вечен). Сьют качает файл ПОСЛЕ dev-purge организации.
- **Запрет удаления подписанного кадрового** — `blocksDeletion` в `FileRefResolver`, проверяется в ОБОИХ путях удаления (softDelete 403 с кодом `hr_signed_doc_protected` + системная уборка тихо пропускает) — урок ревью sign «правило не во всех путях не действует».
- **Кампании**: ОДНА заморозка предмета на кампанию; sms-режим = одна заявка `refType='doc_campaign'` c `neverExpires`+`noInitialActs`, акты адресатам — `systemEnsureActs` пачкой. Задания — источник стопки `hr_campaign` (НЕ approvals-заявки — обход капов inbox). Идемпотентность клика РАНЬШЕ проверки статуса кампании.
- **Календарь РК**: сид в коде, единица срока — ПОЛЕ нормы (`HR_DEADLINE_RULES`), за горизонтом — честный отказ `hr_calendar_horizon`. `HR_DEADLINE_RULE_MAP` — ЕДИНСТВЕННАЯ точка правды сроков: ею считают ensureEsutd в hr.service И hr-actions И литералы 3 РД в getDeadlines (вторых рукописных копий больше нет).
- **Библиотека 11 бланков** (`HR_LIBRARY` в shared): мастер спрашивает ОДНО (подписант) и ставит вид+builder-шаблон+ОПУБЛИКОВАННЫЙ маршрут (`buildAndPublishRoute`, warnings принимаются поимённо).

## Сверка с планом gap-analysis-v2 (2026-08-24, вторая волна) — разрывы закрыты
1. **Исключения ст. 54 — ПЯТЬ в справочнике** `DISMISSAL_GROUNDS` (было одно `st52_p1_1`): + `st52_p1_18` (нарушение обязанностей руководителем с ущербом), `st52_p1_20` (неявка >2 мес из-за нетрудоспособности), `st52_p1_23` (досрочное прекращение полномочий руководителя), `st52_p1_1_1` (п. 1-1, квазигоссектор). `ST54_BAN_EXCEPTION_GROUNDS` несёт все пять; галочка `banExceptionConfirmed` осталась для «иных». Сьют: увольнение по пп. 20 применяется В ОТПУСКЕ без галочки.
2. **ЕСУТД-прекращение — строгая валидация ДО сдачи** (п. 13 — операция без отката): неполный снимок → 400 `hr_esutd_incomplete` списком; повторная попытка по сданному прекращению → `hr_esutd_locked` + ESUTD_TERMINATION_LOCK_NOTE. `buildEsutdPayload` — общий для «Скопировать» и валидации.
3. **Мёртвые ключи обрели производителей**: `hr.delivery.due` шлёт `warnDeliveries` в ежедневном кроне (≤1 РД/просрочено → управляющим); `hr.delivery_fixed` пишет `fixDelivery` (раньше маскировался под `org_document.filed` — вручение падало под чип «Документы» и теряло трек). Новый chatter-ключ `hr.sign_bin_warning` — предупреждение о сертификате без БИН больше не выглядит как «не применено» (итого 11 hr-typeKeys).
4. **Задача «издать приказ об отмене»** — НАСТОЯЩАЯ задача Задачника при отзыве/отмене с изданным приказом (`HrModule → TasksModule`, createTask `skipEnvironmentChecks`, executor = автор действия).
5. **Онбординг-пакет дошёл до UI**: модалка приёма собирает `packageTemplateIds` (чекбоксы; договор+согласие ПД предотмечены по libraryKey), ActionRow показывает чип «Подписано N из M» (по статусам документов).
6. **Очередь подписания «N из M»** (мастер пакета сотрудника И очередь работодателя, v1) — автопродвижение в DecisionStack: `SignStepModal.onSigned` открывает следующий подписной шаг сам.
7. Кампании: «Догнать сейчас» — ДЖОБОМ (не синхронный прогон в HTTP; дедуп живым uniqueKey) + кнопка в вебе; `markSmsFailed` — только fixMode='sms', закрытие последнего pending ЗАВЕРШАЕТ one_off (общий `maybeCompleteOneOff` — раньше зависала в active навсегда); `subjectSha256` в аналитике target DTO; кампания по отменённому документу → 400; standing-перерост потолка — громкий warn (не молчаливый slice); кнопка «SMS не доставлена» у pending в детали.
8. Гибрид/paperMode виден: чип режима доставки на карточке + `can.fixDelivery` теперь и при `deliveryMode≠electronic` (не только specialDelivery).
9. Дип-линки `?tab=` (deadlines/campaigns) переключают вкладку и при КЛИЕНТСКОМ переходе (useEffect на searchParams в members и documents).
10. Вычищено мёртвое: `hr_dismissal_banned`, `HrService.requireEmploymentViewer`, веб-фетчер `fetchMyHrActions`, неиспользуемый импорт Prisma; `CONTRACT_MAX_SILENT_EXTENSIONS` подключён к обоим сравнениям `>= 2`.

**Осталось осознанно (v1):** «печатный комплект одной кнопкой» = «Скачать PDF» + чип режима (отдельной сборки нет); ссылки на ПАПКУ личного дела на Диске в вебе нет (есть ZIP); отказы «снимок >500» и «кампания >5000» e2e непроверяемы (нет 501 юзера); hr-уведомления — прямой notify (прецедент finances/drive), не notifications.map.

## Ревью КЭДО и смежных движков (2026-08-24, третья волна) — 7 высоких + ~12 средних, все закрыты

Сьюты прошли ДО единой правки — находки лежали там, куда они не смотрели; каждая воспроизведена живым зондом против API, каждая перепроверена после починки.

**Право и доступ**
- **Ст. 56 п. 4 применялась не к тому**: отзыв проверял «kind=dismissal и это про меня» → работник отменял приказ работодателя о СОКРАЩЕНИИ, сколько угодно раз. Теперь только своё заявление (`source='employee'` ∥ ground `st56`), иначе 400 `hr_withdraw_not_own_application`; в вебе кнопка гаснет тем же условием.
- **Черновик действия светился субъекту** (вид, основание, дата, оклад) — правило «сторона видит с момента отправки» стояло на документах, но не на действиях. `listForUser({includeDrafts})`, `listMine` — то же; `documentsCount` отдаётся только тем, кому видна карточка.
- **Ранг субъекта не проверялся**: Менеджер заводил увольнение ВЛАДЕЛЬЦУ и правил его оклад. `assertCanManageHrSubject` (hr.constants) — на create/cancel/upsertEmployment; аудитория batch тихо отсеивает неподвластных (иначе «вся организация» стала бы доступна только Владельцу).

**Надёжность**
- **Клейм коммитился ДО эффектов** (`applyAction`): краш между `applied` и правкой карточки терял применение навсегда. Клейм + законность + эффекты КЭДО — В ОДНОЙ транзакции; чужие сервисы (removeMember, syncFact), уведомления и хроника — после коммита (`applyEffectsTx` возвращает `PostApplyEffects`).
- **Клейм принимает `draft`**: нода `hr.apply` при сегодняшней дате молча не применяла действие, если best-effort хук `onDocumentSubmitted` не доехал (у ветки будущей даты draft принимался — асимметрия).

**Целостность**
- **Уволенный подвешивал кампанию**: `InboxSource.releaseUser` — новый хук РЕЕСТРА источников стопки, движок решений зовёт его из того же каскада увольнения, что снимает с шагов. Кампании снимают только незакрытые задания (зафиксированное ознакомление вечно) и досчитывают закрытие one_off.
- **Карточка уволенного = 404** ровно тогда, когда на неё ведут «Сроки» и уведомление о применении → при кадровом следе открывается Менеджеру+ с `role: null` (чип «Не в организации», кнопки скрыты).
- Дубль действия (тот же вид + та же дата; увольнение — любое второе) → `hr_action_duplicate`. `batchId` проставляется в самом create (дописанный вторым запросом терялся при обрыве джоба → второй комплект документов). sms-кампания без заявки подписи гасится с ошибкой вместо тупика. Запись install пишется ДО сборки маршрута. Сид календаря переживает ошибку одного дня.

**Прочее**: окно исправления ЕСУТД — из `HR_DEADLINE_RULE_MAP` (был литерал 30); бейдж «Сроки» = окно экрана (30 дней, было 7); Zod отвергает период «конец раньше начала»; ZIP-выгрузка — рабочий потолок (прежний `throw` внутри `try` ловился соседним `catch`, файлы всё равно читались в память), гашение потока при обрыве, обрезка названа в описи; `blocksDeletion` спрашивается у всех привязок ЗАЩИЩАЮЩИХ типов (`FilesRefRegistry.typesWithDeletionGuard`, было `take: 100`); «Мои документы» и список кампаний — батчи вместо N+1; адресат `branch` доведён до ноды «Решение человека» (виджет `kind:'branch'` в вебе уже существовал).

**Принято осознанно**: пустой снимок адресатов следующей группы откатывает транзакцию решения (подписант получает отказ и подписывает заново — лучше вечно висящего шага); у `EsutdSubmission` нет партиального уникума (постановку сериализует клейм применения); `createAction` не транзакционен целиком (падение на создании документа оставляет отменяемый draft).

**Ловушка окружения**: в CLAUDE.md жил ЛИТЕРАЛЬНЫЙ NUL (из блока про драйвер шаблонов) — файл считался бинарным, и `grep`/ripgrep по главному документу проекта не работал ВООБЩЕ. Заменён на текст `U+0000`.

## Ревью ВЕБ-части КЭДО (2026-08-24, четвёртая волна) — 2 200 строк экранов построчно

**Юридически опасные умолчания и ввод:**

**Видимость и перф:**
