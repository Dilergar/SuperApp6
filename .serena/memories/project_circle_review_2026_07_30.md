Миграция `20260730162530_circle_review_fixes`.

## Несущие решения (не откатывать)

1. **null-видимость группы = дефолт ВЛАДЕЛЬЦА, а не платформенный.** Чинится в ДВУХ местах: чтение (`ContactsService.resolveVisibilityForViewer`) и запись (`CirclesService.updateCircle` — база первой настройки). Иначе добавление контакта в свежую группу (у неё `cardVisibility=null`) раскрывало город/био/возраст/соцсети: union умеет только расширять. `mergeVisibilities([])` теперь all-OFF (fail-closed), был permissive.
2. **`PersonalGraphRegistry`** (`modules/contacts/personal-graph.registry.ts`) — реестр «что отозвать при разрыве связи», паттерн FilesRefRegistry. Заменил единственный ленивый DI-токен на finances. Потребители: finances, calendar, shop (витрины+вишлист+staff). Правило: выдал грант «человеку из окружения» → зарегистрируй хук.
3. **`ContactsService.resolveCircleMemberIds`** — единственный законный разворот Группы (владение + гейт внутри). Копии из Задачника и Календаря удалены; они успели разъехаться (у календаря гейт был, у задач — нет).
4. **`assertReachable({personalOnly})`** — для ЛИЧНЫХ ресурсов (finbook, календарь, витрина, вишлист) рабочий пропуск отключается: иначе грант выдавался коллеге вне окружения, а ночной свип «гранты без ContactLink» его молча отзывал.
5. **`AccessService.revokeSubject(type,id)`** — снятие рёбер, где сущность = ПОЛУЧАТЕЛЬ. `circleDeleted` зовёт и `revokeResource`, и `revokeSubject`, обе в транзакции удаления группы.
6. **Диффная проекция уровней** (сначала grant нужного, потом revoke лишнего) — и у групп (`circleCalendarVisibilityChanged`), и у персонального `CalendarService.setShare`. Revoke-then-grant давал окно `none`.
7. **Регистрация ставит джоб `users.phone.invitations` В ТРАНЗАКЦИИ** (константа вынесена в `core/users/user-jobs.ts`, чтобы auth не импортировал users.service). AuthService больше не инжектит Contacts/Workspaces.
8. **Партиальный unique** `contact_invitations (from_user_id, to_phone) WHERE status='pending'` — руками в миграции + схлопывание накопленных дублей. Без него 10 параллельных POST обходили все лимиты.
9. **Принятие приглашения**: блок перепроверяется ВНУТРИ транзакции; встречное приглашение гасится там же (иначе вечный pending); `circleMemberAdded` проецируется после коммита (раньше членство жило без ребра до 4:00); `autoAddToCircleIds` отправителя наконец применяется.
10. **Веб**: страница разбита на `circles-lib.ts` / `circles-ui.tsx` / `circles-modals.tsx`; `contactsPagesKey = ['contacts','pages']` для useInfiniteQuery ОТДЕЛЬНО от плоского `contactsKey` (его читают пикеры — InfiniteData их сломала бы), вложен под `['contacts']`, поэтому старая инвалидация накрывает оба.

## Ловушки, найденные при проверке

- **Тест «видимость» бессмысленен на пустых полях**: карточка отдаёт `null` и для «скрыто», и для «не заполнено». В verify сначала заполняем city/bio, потом прячем.
- **Встречное приглашение через API создать НЕЛЬЗЯ** (send видит чужое pending в обе стороны → 409). Вечный pending — следствие гонки; в тесте вторая строка создаётся напрямую в БД.
- **`FAIL` в сводке сьютов ≠ провал**: часть скриптов печатает `RESULT N passed, 0 failed` — слово попадает в греп.
- **Prisma generate на Windows падает EPERM**, пока запущен `dist/main`: процесс держит `query_engine-windows.dll.node`. Останавливать нужно и `nest start --watch`, и дочерний процесс, иначе watcher поднимет новый и снова залочит.
- **`isPending`, а не `isLoading`** у выключенных запросов React Query — иначе экран «Пока никого» вместо загрузки (та же ловушка, что в Диктофоне).

## Платформенная ловушка React-стриминга (важнее самого ревью)

`/circles` после рерайта ВЕЧНО висел на спиннере `loading.tsx` при ПРЯМОМ заходе (клиентский переход работал): ноль ошибок в консоли, ни одного упавшего запроса, сервер отдаёт 200 и ПОЛНЫЙ html за 170мс.

Причина не в странице: React вкладывает содержимое Suspense-границы прямо в поток, только пока оно меньше `progressiveChunkSize` = **12800 байт**. Переросло — содержимое уезжает отдельным чанком, а раскрывает его инструкция `$RC(...)`, которая в React 19.2 планирует `$RV` через **requestAnimationFrame**. В невидимой/фоновой вкладке кадров нет → граница остаётся в fallback НАВСЕГДА. Старая страница не попадала, потому что рано возвращала `<p>Загрузка…</p>` (~50 байт), пока `isReady` false на сервере; рерайт начал рисовать всю обвязку кита (у каждого элемента с тоном ~250 байт инлайновых переменных).

Лечение: гейт `mounted` — до гидратации отдаём только шапку (авторизация клиентская, серверу рисовать нечего). **Оракул скрининга для всего приложения: `curl -s <url> | grep -c '$RC('` → 0 = хорошо.** Записано в CLAUDE.md, пункт про `loading.tsx` в плейбуке.

Диагностика (бисекция «модули → хуки → половины JSX») указала на панель приглашений — ЛОЖНЫЙ след: отключение любого крупного блока опускало payload под порог. Признак залипшей границы: пустой `main` + `<!--$~-->` + `<template id="B:0">`; проверять `document.querySelector('main').innerText.length`, скриншот при скрытой панели не снимается.

- Бронь ресурсов оставлена на своём ACL, а не мигрирована в `core/access` — закрыта только дыра валидации.
- `calcAge` в contacts и workspaces считаются по-разному (не входило в опубликованные списки).
- Серверного поиска по окружению нет: поиск на странице идёт по загруженным страницам.
- Продуктовые идеи (10 фишек / 10 улучшений / 5 масштаб / 5 сервисов) выданы пользователю списком — выбирает отдельной задачей.
